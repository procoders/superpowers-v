# v4 domain pre-flight (light), 2026-10-22

Format: requirement → source → acceptance check. "Probed" = run on git 2.50.1 here.

## A. Completion gate (Stop hook)

1. **Bound the block yourself.** Claude Code overrides a Stop hook after 8 consecutive blocks; hooks should read `stop_hook_active` and exit early. → code.claude.com/docs/en/hooks-guide (Stop). → Check: with `stop_hook_active:true` the hook exits 0 even with missing receipts; otherwise it blocks once and writes a marker keyed by run id + snapshot hash.
2. **A broken hook must fail open.** Timeout discards output; a missing script is a non-blocking error; `onFailure:"block"` has no effect on Stop. → hooks reference. → Check: kill, rename and hang `verify`; the session still stops and the run reads incomplete.
3. **Read the run record, not the transcript.** The transcript is written asynchronously and can lag; `last_assistant_message` exists. → hooks reference. → Check: gate never parses chat for "done".
4. **Agents game gates by editing evidence**: deleting or skipping tests, making the runner exit 0, hardcoding known inputs. Mitigation: hash test files at start and end; score with tests the agent could not modify. → EvilGenie (alphaxiv.org/abs/2511.21654), primeintellect.ai/rl-glossary/reward-hacking. No published Stop-hook gate found to copy; this is inference. → Check: `verify` records test-file set and hashes at plan time; deleted or modified tests, or a lower test count, flag the receipt. The test command comes from plan/config, never from chat.
5. **Receipts must not be agent-writable.** (Inference from 4.) → Check: only `verify` writes receipts; the lane guard denies other callers; a hand-written receipt fails validation.

## B. Hashing the working tree (probed)

Recipe: private index, `git add -A`, `git write-tree`:
`GIT_INDEX_FILE=<mktemp> git -c core.autocrlf=false -c core.fileMode=true -c core.excludesFile=/dev/null add -A -- . ':(exclude)docs/compound-v'` then `write-tree`.

6. **Not `git stash create`**: it omits untracked files (git-stash(1)). → Check: adding an untracked file changes the hash.
7. **Index private, outside the user's staging area** (`GIT_INDEX_FILE`, git(1)). Probed: new file, deletion and mode 100755 all recorded. → Check: real `git diff --cached` identical before and after `verify`.
8. **Gitignored files are invisible: a false-green hole.** Probed: `x.log` absent from the tree. `.env` and generated assets are not covered. → Check: document it; record an explicit include list or the ignored-file listing in the receipt.
9. **CRLF and filemode change the hash.** Probed: CRLF blob distinct; `autocrlf=true` normalises. → Check: same tree under two user configs gives one hash.
10. **Symlinks hash as link targets; deletions drop out; nested repos become gitlinks (content ignored).** Probed deletion. → Check: fixture with symlink, deletion and nested repo has documented behaviour.
11. **Reviewer checkout from the tree object**, then re-hash and compare (design §4.5). → Check: flip one byte in the checkout; `verify` rejects the review.
12. **Re-hash at stop time**, not only at receipt time. → Check: edit a file after receipts exist; the hook blocks with "stale".

## C. LLM-as-reviewer loops

13. **Judges favour their own and same-family output.** → arxiv.org/abs/2410.21819. → Check: prefer a different family (Codex); the Claude fallback gets request + diff + acceptance table only, no author transcript.
14. **Reviewers over-correct, flagging conforming code.** → arxiv.org/pdf/2603.00539. → Check: a finding needs a reproducing command or file:line; unverified findings are recorded, not auto-fixed. Two-round cap stands.
15. **Same-context review blesses the original mistake** (practitioner opinion, dev.to; weak). → Check: review runs isolated, no author context.
16. **Stale snapshot**: no source found; inference. → Check: each round carries the snapshot hash; a finding against another hash is rejected; a fix round that leaves the hash unchanged counts as no-op.
