# Phase 1A — Code archaeology: v2.17 co-change advisory + evidence packing

Run 2026-07-25 against the r1 spec. **It falsified three r1 claims**; the spec was rewritten to r2.
Phases 1B (domain) and 1C (library) were **deliberately not run** — the feature has no user-facing or
regulated surface and adds **zero** dependencies (pure stdlib over the `git` CLI), so both would have
had no material to audit. Recorded here so the omission is a stated choice, not an oversight.

## Findings that changed the design

1. **`--no-renames` fabricates co-change pairs.** `compound-v-churn.py:255` passes `--no-renames`
   deliberately, so `--numstat` paths stay literal. Inheriting that for co-change is a correctness bug:
   a single rename then emits the old and new path in one commit and manufactures a pair at **100%
   confidence** that is pure artifact. r2 uses `-M` and requires a rename fixture in the selftest.

2. **`agents/spec-reviewer.md` has no WARN vocabulary.** Every finding there is an `ISSUE:`, and `:14`
   / `:203` make any `ISSUE:` a hard DONE-blocker enforced by `commands/v-collect.md:41`. r1 would have
   **blocked every merge on a correlation** without a line of code changing. r2 drops that consumption
   point entirely; only `agents/partition-reviewer.md` is wired, where `WARN: BATCHING_MISSING`
   (`:93`, *"a warning, not a fail"*, rendered `:121-123`, outside the FAIL block at `:105`) is the
   exact precedent.

3. **The `churn-cache.json` precedent does not exist.** `git ls-files docs/superpowers/memory/` returns
   only `recon-outcomes.jsonl`, `routing-lessons.md`, `task-outcomes.jsonl`, `worker-performance.jsonl`.
   The file is written only at `/v:onboard` WRITE and has never been built here. r2 drops the cache
   entirely (sub-second full computation — YAGNI).

4. **The generalization claim was too broad.** There are **two** hand-written lockstep guards:
   `validate.yml:43-52` (plugin↔marketplace) and `validate.yml:54-81` (CHANGELOG↔plugin). The second
   pair measures `min(P) = 0.59` — **below the bar** — because `CHANGELOG.md` is touched 56 times against
   `plugin.json`'s 36. The computed signal is silent on a rule CI really enforces. Both guards stay.

5. **`CONVENTIONS.md` is generated** (`:1-6`, provenance in
   `docs/superpowers/architecture/.onboard-manifest.json`) and is rewritten by `/v:onboard --refresh`.
   A charter rule placed there would be silently erased. r2 moves it to ADR 0002.

6. **`pack_evidence` ordering is a real dilemma.** After `redact()` (`epic-arbiter.py:1477`) the
   omission markers egress un-redacted repo paths to both Codex (`:1489`) and agy (`:1519`); before it,
   `redact`'s byte cap and `_bound_text` (`:817`) can still tail-amputate the failures. r2 resolves it
   by running **before** redaction *and* making markers **path-free**, so nothing in a marker needs
   scrubbing.

7. **`redact()` fails closed on any exception** (`:646`, `:665-666`) and `_build_codex_prompt`
   substitutes an evidence-free placeholder for `None` (`:803-804`). A `pack_evidence` that raises would
   silently degrade **every** arbiter ballot. r2 requires it to never raise and to return its input
   unchanged on any internal error.

8. **`--max-files 40` drops 0 of 372 real commits here** — the bulk-noise filter has zero real-data
   coverage and can only be proven by a selftest fixture.

## Latent sibling behaviours inherited knowingly

- `_git_numstat_log` returns `("", False)` on any non-zero git exit (`churn.py:259-260`), making a git
  failure indistinguishable from an empty history. **Not inherited** — r2 requires a visible surface.
- `load_churn_config` swallows every taxonomy exception into `([], [])` (`:187-188`); malformed and
  absent YAML are the same observable outcome. Inherited, and stated.
- On this repo the taxonomy resolves to **zero** exclusions (`.claude/` holds only the `.example.yaml`,
  which `load_churn_config:166-174` refuses by design).
