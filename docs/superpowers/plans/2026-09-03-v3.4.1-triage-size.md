# v3.4.1 Triage-size Implementation Plan

> **For agentic workers:** this plan is executed by Compound V (`/v:dispatch`) on Engine C — one job per task below, disjoint lanes, the gate and the authority after every wave. Each task's Interfaces block is the contract its neighbours rely on.

**Goal:** a small code change reaches SCOPED (or SCOPED+ on a sensitive path), localization never scans for plain words, a SCOPED job runs only the tests in its scope, and the hook finishes T3 by itself.

**Architecture:** five disjoint jobs in one wave (A scorer+taxonomy+schema, B localizer, C test scoping, D hook+headless classify, E validator+dispatch docs) and a release job after them. The engine's public API (`score`, `triage_request`, `needs_t3` re-entry) is unchanged in shape; new fields are additive.

**Tech Stack:** Python 3.9 stdlib scripts with `--selftest`, bash hooks (shellcheck-clean, fail-open), `tests/*.sh` sandboxes, `tests/v2.9-e2e` unittest.

## Global Constraints

- Python 3.9 stdlib only; hooks fail open; no shell interpolation of hook input; every external process under `scripts/compound-v-run-with-timeout.py`.
- Never Haiku; the light classify resolves through `compound-v-resolve-model.py` (`claude`/`light` → sonnet).
- The engine never calls a model. Fail-closed: error/timeout/non-enum ⇒ `unknown` ⇒ FULL.
- Three tier tokens only; SCOPED+ is `decision: SCOPED_PIPELINE` + `flavor: scoped_plus`.
- No fabricated metrics. Tests that pinned changed behaviour are rewritten in the same task.
- Spec: `docs/superpowers/specs/2026-09-03-v3.4.1-triage-size-design.md` (read it first; section letters below refer to it).
