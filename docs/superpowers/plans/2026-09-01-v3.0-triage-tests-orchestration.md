# Compound V 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the existing triage engine impossible to skip, make tests proportionate to a change without losing the safety the full suite provided, and move dispatch onto the native Workflow runtime so the scope gate becomes mechanical on the claude path.

**Architecture:** Three independent surfaces over one shared contract. The manifest schema is the shared resource — it carries both the `triage` block (Feature A's mechanical consumer) and the `test_contract` (Feature B's transport), so it is built **first and serially** as Task 0. Everything else partitions cleanly by file.

**Tech Stack:** Python 3.9 (stdlib only, CI floor), bash hooks, markdown contracts, generated JavaScript for the Workflow runtime.

## Global Constraints

- **Python 3.9** is the CI floor. `datetime.fromisoformat` does not accept a `Z` suffix there; strip it.
- **Never Haiku.** Opus by default; Sonnet only under the 8-box junior-task carve-out.
- **Anti-ruflo:** counts only, never estimated or fabricated metrics. An honest `—` beats a guessed number.
- **No speed or cost claim ships with 3.0.** The "~20,000 tests" observation is unreproduced; Feature B's defaults are principle-derived and must be described that way.
- **Never emit the permission-bypass flag.** Never auto-arm a scheduler.
- Every new script carries `--selftest` and is picked up by the CI sweep over `scripts/*.py`.
- **Every new guard must be demonstrated to fail on a planted violation** before it is trusted. A green guard that has never been seen to go red is not known to work.
- Claude Code version floor: **≥ 2.1.219**. Nothing may depend on `/workflow-authoring` (needs 2.1.248).
- Spec is authoritative: `docs/superpowers/specs/2026-09-01-v3.0-triage-tests-orchestration-design.md`. Pre-flight audits under `docs/superpowers/preflight/2026-09-01-v3.0-*.md` are binding design constraints.

## Task 0 — The shared contract (SERIAL, blocks everything)

**Files:** Modify `scripts/compound-v-validate-manifest.py`, `skills/compound-v/execution-manifest.md`, `examples/manifest.example.yaml`, `.github/workflows/validate.yml`

**Produces (every later task depends on these exact names):**

> **The closure, which must not live only in the manifest's repair note.** `--require-triage` ships **default-off in every mode**, and `/v:dispatch` passes it **explicitly on every dispatch, in every mode** (Task 9 owns that call site). Defaulting it on for `--mode pre-dispatch` alone is not the guarantee it looks like: that mode is selected only for `fast_path` manifests, so an ordinary FULL manifest would take a mode-less PASS forever — the same exemption 3.0 legitimately takes once during bootstrap. The CI historical sweep stays mode-less and keeps its allowlist.
- Top-level manifest key `triage: {tier, pre_eval_id, taxonomy_digest, decided_at}`; `tier ∈ {DIRECT, SCOPED, FULL}`.
- Top-level key `test_contract: {floor_command, full_command, impacted_map:[{when, run}]}`.
- Per-job key `test_scope ∈ {full, impacted, floor_only}`, default `full`.
- Validator flag `--require-triage`, default **on** for `--mode pre-dispatch`, **off** otherwise.

**Steps:**
1. Write failing tests in the validator's `--selftest`: a manifest with no `triage` FAILS under `--require-triage`; a `tier` outside the enum FAILS; a `taxonomy_digest` that does not match the taxonomy bytes on disk FAILS; the same manifest PASSES without `--require-triage`.
2. Run `python3 scripts/compound-v-validate-manifest.py --selftest`; confirm the new checks fail.
3. Implement. Keep `TOPLEVEL_REQUIRED` / `JOB_REQUIRED` conventions; add `triage` under the flag, not unconditionally, so the CI historical sweep keeps passing.
4. Add `test_contract` and `test_scope` validation: an `impacted_map` entry missing `when` or `run` FAILS; `floor_only` with an empty `floor_command` FAILS (never resolves to nothing).
5. Update `execution-manifest.md` with both blocks and update `examples/manifest.example.yaml` to carry them.
6. CI: add a step that executes every file under `tests/` (today only `scripts/*.py` is swept, so all three test files are dead). Make the full-suite backstop a job that **always runs** — a conditionally-skipped job reports `Success` on GitHub and would green a required check without running.
7. Prove the new CI step fails: plant a deliberately failing line in a `tests/` file, run the step, confirm red, remove it.
8. Run the whole selftest suite and the manifest gate over all committed manifests. Commit.

**Acceptance:** spec AC-2 (partially — the `--require-triage` mechanism), AC-10, AC-17.

## Tasks 1–12 — Parallel

Each task below is independent, writes only its own files, and ends with its own tests green and a commit.

### Task 1 — The third tier (`scripts/compound-v-preeval.py`)

Add `DECISION_SCOPED`. Implement the 3×3 matrix from spec §A1 **inside the engine**, not as a post-hoc read of the verdict dict. **Any fired override forces FULL** — override #4 at `:424` returns genuine `low`/`low` bands beside `override_fired=4`, and a post-hoc reader would grant DIRECT, and with it auto-route, to a record whose own audit says a hard override fired. Unknown bands stay fail-closed to FULL.

Selftest must cover all 9 cells, the unknown case, and the override case. **Consumers:** `fastpath-materialize`, `fastpath-run`, `postdiff-reclassify`, `triage-outcomes` and `commands/v-orchestrate.md` currently branch binary on the decision; Task 1 owns only this file — it must document the new value in its module docstring so Tasks 2, 3 and 4 can consume it. **AC-1.**

### Task 2 — Outcomes stream and the circuit breaker (`scripts/compound-v-triage-outcomes.py`)

`:733` currently collapses everything that is not fast-path into the `fullpipeline` cohort; SCOPED must become its own cohort or the fast-path precision figure `/v:status` renders is silently corrupted. Add `predicted` and `actual` event emission to `docs/superpowers/memory/triage-outcomes.jsonl`.

Implement the **miscalibration circuit breaker** (spec §A4.9): a rolling demotion rate over the last `auto_route_window` (default 20) DIRECT decisions; above `auto_route_max_demotion_rate` (default 0.25) auto-route disarms and reverts to offering until a human re-arms. A selftest must prove it **never delays the first decision** and that it disarms once the threshold is crossed. **AC-5 (breaker half), AC-7.**

### Task 3 — Fast-path materializer and the floor (`scripts/compound-v-fastpath-materialize.py`, `scripts/compound-v-fastpath-run.py`)

`build_manifest` must emit a `triage` block or it breaks at runtime and in its own selftest once Task 0 lands. Update its selftest in the same commit.

`run_test_floor` (`fastpath-run.py:308-343`) **already is** Feature B's floor — merge-blocking, records command and exit code, fail-closed on empty. Do not build a second one. Give it a producer for `--test-cmd` (today `"$CFG_TESTS"` is an unbound placeholder), move its `return` **below** the `changed_paths` computation so it can be diff-proportionate, and make the always-run set the union of **impacted ∪ previously-failing ∪ newly-added** (`git diff --name-only --diff-filter=A` for the last). **AC-3, AC-9.**

### Task 4 — `/v:triage` and orchestrate wiring (`commands/v-triage.md` NEW, `commands/v-orchestrate.md`)

`/v:triage <request>`: resolve localization, classify, score, write **and commit** the record to `docs/superpowers/pre-eval/<id>.json`, print the tier and the predicates that decided it. This is the caller the engine has never had.

Implement the nine auto-route predicates of spec §A4, including predicate 7 (**floor passed before commit**) and predicate 8 (**full post-diff re-validation** of single-path, sensitive-set, no-test-file and the line budget — not the line count alone). The `sensitive` set is read from the taxonomy, never hardcoded. `/v:orchestrate` invokes `/v:triage` when no record exists. **AC-4, AC-5.**

### Task 5 — The amended Iron Invariant (`skills/compound-v/phase-preeval.md`, `SKILL.md`, `rationalization-table.md`, `routing-policy.md`)

Replace "The score only OFFERS, never auto-routes" with the amended wording in spec §A4 across **all four** files. Verify with `grep -rn "never auto-routes"` that no file still asserts the unamended form. Add a rationalization row for "the change is tiny, I'll skip the triage record". **AC-6.**

### Task 6 — Test transport and reporting (`schemas/job_result.schema.json`, `skills/backend-launcher/SKILL.md`, `skills/backend-launcher/adapter-*.md`, `scripts/compound-v-run-*-worker.sh`)

`job_result.schema.json:7` is `additionalProperties: false` with no field for a test command; add `tests: {command, exit_code, scope, selected_count}`. Every worker takes `--prompt-file` and the `job_spec` contract has no test field, so `test_scope` would reach an external worker only as prose — add a real `test_contract` slice to `job_spec` and pass it through each worker script **as an argument**. Update `examples/job_result.example.json` if one exists. **AC-11.**

### Task 7 — Tier-aware review gate (`agents/spec-reviewer.md`)

`:138` currently demands "the composite must build/compile and the test suite must pass" unconditionally. Make it tier-aware: floor unconditional; `full_command` required at FULL and for any job with an unmapped path; declared impacted set sufficient at SCOPED and DIRECT. **A job reporting no test command at all is a FAIL** — read `tests.command` and `tests.exit_code` from the job result. **AC-12.**

### Task 8 — The triage rule inside the Stop hook (`hooks/epic-goal-stop.sh`, `tests/test-epic-goal-stop.sh`)

Add a **second rule to the existing script**, never a second registration — two blocking `Stop` registrations are undefined ordering, which is why v2.18 put both of its rules in one file. Fires when tracked non-exempt files changed with no triage record for the session; `session_id` is on the `Stop` stdin payload. Exempt on an existing record, on DIRECT auto-route class membership, or on a session opt-out. OFF by default under `enforcement.triage_gate`.

Three mechanics the pre-flights corrected: `stop_hook_active` is a **consecutive-block counter**, not a session flag, and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` (default 8) lets the harness override the hook — block at most once per session on the script's **own** marker. **Exit 2 blocks**; the `|| true` registration stays load-bearing because **bash exits 2 on a parse error** (probed: stray `fi`, unterminated quote, unclosed function all → 2), and no in-script trap runs when the script fails to parse. All `Stop` hooks share a **1.5s budget** — use a bounded check and **record when it could not complete rather than passing silently**, or this becomes another dead guard. **AC-14.**

### Task 9 — The Workflow dispatch engine (`scripts/compound-v-emit-workflow.py` NEW, `commands/v-dispatch.md`, `agents/parallel-dispatcher.md`, `skills/compound-v/workflows-accelerator.md`)

Call it **Engine C** — the name used in nine shipped locations; "Engine B" is the rejected `claude -p` shell-out.

`compound-v-emit-workflow.py` turns a manifest into a script: `depends_on` → topological staging, `max_parallel` → chunking, backend/tier/effort → `agent()` options. Stages are `implement → gate → record` via the variadic `pipeline`, whose stage callbacks receive `(prevResult, originalItem, index)`.

Three mandatory properties, each closing a found defect: the **Gate stage never throws** (a throwing stage drops its item to `null` and skips every remaining stage, so Record would never run and the audit trail would be lost precisely on the jobs that failed); **`null` is FAIL, never pass** (`agent()` returns `null` on kill or terminal API error); the **Record stage is idempotent** (a mid-fan-out failure re-runs completed agents).

The emitted script must contain no `Date.now()`, `Math.random()`, bare `new Date()` or `import()` — all throw or fail in that runtime. Dispatch prose must force the `scriptPath` invocation form, or the committed artifact is not what ran. Probe `CLAUDE_CODE_WORKFLOWS` (restricts a session to named workflows and refuses `scriptPath`) and fall back to Engine A.

Engine selection: Engine C only in a top-level session where the live probe succeeds; Engine A in subagent, `/v:epic`, shim and headless contexts. **Do not justify this by claiming workflows are unavailable headless — they are available in `-p` and the SDK; only the `ultracode` keyword is route-restricted.** Justify it by the three operational facts in spec §D3. Update `workflows-accelerator.md`, whose current text says Engine C never touches enforcement or recovery. **AC-15, AC-16.**

### Task 10 — Two ADRs (`docs/superpowers/adr/0003-scoped-tests-with-a-floor.md`, `docs/superpowers/adr/0004-workflow-as-the-dispatch-engine.md`)

0003 supersedes the v2.17 `impacted-tests` rejection: state the original rationale (v2.14.1, 25 of 29 selftests silently never running), the three-set floor, the always-run CI backstop, and the measured RTS miss rate of **0.2% class-level to 10.6% method-level unsafe per revision** — noting that a hand-written glob map carries less information than a call graph, so 0.2% is an optimistic floor, not an expectation. Record what would falsify the decision.

0004 records that Feature D reverses `workflows-accelerator.md:60-71` — the "load-bearing guarantee" that the scope gate and `state.json` stay in Engine A — with its rationale and falsification condition. Follow the shape of `adr/0002-limits-ship-with-the-claim.md`. **AC-13.**

### Task 11 — v2.18's unfinished wiring (`commands/v-epic.md`, `commands/v-status.md`, `commands/v-init.md`, `skills/compound-v/epic-mode.md`)

Job p5 from the absorbed v2.18 manifest: `/v:epic` arm/disarm plus the shim offer, `/v:status` armed-goal column, `/v:init` enforcement key, `epic-mode.md`. Read `docs/superpowers/specs/2026-07-26-v2.18-autonomy-mechanisms-design.md` for the contract. The arming helpers already exist in `scripts/compound-v-epic-state.py` (`--arm-goal`, `--disarm-goal`, `--goal-status`). **AC-18.**
