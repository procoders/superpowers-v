- [ ] `scripts/compound-v-validate-manifest.py`: `TEST_CONTRACT_ALLOWED_KEYS += ("timeout_s",)`; `_validate_test_contract` accepts an optional `timeout_s` that is an int and not a bool (`isinstance(v, int) and not isinstance(v, bool)`, the file's own guard) in `1..540`, refusing anything else with a violation naming the key. Mirror the existing `floor_command`/`full_command` isinstance pattern. Selftest cases: accept 480; refuse 0, -1, 541, `true`, `"480"`.
- [ ] `scripts/compound-v-fastpath-run.py`: `TEST_TIMEOUT_S = 480`; `resolve_test_commands` copies `contract.get("timeout_s")` into the slice when present; `_cmd_test_floor` passes `test_timeout_s=slice_.get("timeout_s", TEST_TIMEOUT_S)` into `run_test_floor` (the real function — the earlier plan text named a nonexistent `run_tests`); a checker that exits 124 yields `tests.exit_code: 124` and a `tests.failures[]` entry `timeout after N s: <checker>` (the string `run_test_floor` already builds in `reasons`); NO `failure_class` change. - [ ] Finding 105 (spec Part 3): in `resolve_test_commands`, a changed path under `docs/superpowers/execution/**` or matched by `.gitignore` (`git check-ignore --stdin`, one call) never counts as unmapped for the `full_command` promotion; a contract note says `ignored N bookkeeping path(s) for the unmapped rule`.
