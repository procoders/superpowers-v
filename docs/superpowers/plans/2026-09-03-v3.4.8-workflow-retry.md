### Task A — `scripts/compound-v-emit-workflow.py`
- [ ] In the JS template (grep `async function gateStage` and the implement/record/finalize stage functions), add `async function withRetry(label, fn, opts)`: call `fn()`; on a thrown error whose `String(err)` matches `/529|Overloaded|overloaded_error|rate.?limit|429|ECONNRESET|ETIMEDOUT|network/i`, append `{label, attempt, class, wait_ms, ts}` to `<run>/logs/retries.jsonl` (via the existing Bash-free path: the JS returns the log line in its structured output and the emitter's Record appends it — or, simpler, the JS keeps the attempts in memory and the stage result carries `retries: [...]`, which Record writes to the log), wait `min(60000, 2000 * 2**(attempt-1)) ± 25%` and retry while `attempt < CFG.retry.max_attempts` (default 3); any other error, or the last transient one, rethrows unchanged.
- [ ] Wrap every `agent(...)` call in the stage functions with `withRetry('<stage> <job.id>', () => agent(prompt, opts))`.
- [ ] Reviewer lift: in the review stage, when `withRetry` exhausts on a transient class and `job.tier === 'deep'` and `CFG.retry.escalate_reviewer`, spawn once more with `opts.model = 'fable'` and `label + ' (frontier)'`, and pass `--escalated-from deep` to gate-receipt so the receipt carries `escalated_from`.
- [ ] `CFG.retry` is emitted from the manifest's `retry` block (defaults `{max_attempts: 3, escalate_reviewer: true}`).
- [ ] Record: when the stage result carries `retries` and a terminal transient error, write `failure_class` from the class (`overloaded` | `rate_limited` | `network` | `timeout`), not `other`; when `escalated_from` is present, copy it into the result.
- [ ] Selftests (string checks on the emitted script + a Python-side simulation of the backoff table): `withRetry` present; every `agent(` inside a stage is wrapped; `escalate_reviewer` branch present; the backoff table 2 s/4 s/8 s… capped 60 s; Record maps the class; `--selftest` green.
