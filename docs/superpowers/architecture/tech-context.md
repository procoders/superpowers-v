# Tech context — stack and conventions

## What this codebase is

This is a Claude Code **plugin**, not an application. Its manifest declares `name`, `description`,
`version`, `author`, `license`, `homepage`, `repository`, and `keywords`. (`.claude-plugin/plugin.json:1-25`)
The shipped surface is markdown skills, agents, and commands plus Python/bash helper scripts — there
is no application runtime, build system, or package manager lockfile in the repo root.

## Languages and runtime

- **Python (stdlib only).** The deterministic toolkits are Python scripts that avoid third-party
  dependencies. The scope gate is explicitly "Python 3.9-safe, stdlib only. Targets stock-macOS
  python3 3.9.6." (`scripts/compound-v-scope-check.py:141`) The `/v:onboard` toolkit says the same in
  its one-line docstring. (`scripts/compound-v-onboard.py:1-2`) V-memory describes itself as
  "pure-stdlib core, offline, `--selftest`'d." (`skills/compound-v/memory.md:15-17`)
- **Bash hooks and worker scripts.** Hooks under `hooks/*.sh` must be executable, and CI shellchecks
  both `hooks/*.sh` and `scripts/compound-v-*.sh` (the headless workers `scripts/compound-v-run-*-worker.sh`
  are bash too). (`.github/workflows/validate.yml:216-230`)
- **Markdown skills / commands / agents.** Skills live under `skills/*/SKILL.md`, agents under
  `agents/*.md`, commands under `commands/`; CI verifies each has `name`/`description` frontmatter.
  (`.github/workflows/validate.yml:83-107`)
- **Generated JavaScript, not hand-written.** Engine C emits a native Workflow script per run; the
  emitted JS has no filesystem and no shell access and is deliberately thin — it schedules, it never
  decides, so every mechanical decision stays in Python. (`scripts/compound-v-emit-workflow.py:11-16`)

## Plugin manifest and CI

`.claude-plugin/plugin.json` is the plugin manifest; CI validates it is valid JSON, that required
fields (`name description version author license`) are non-empty (`.github/workflows/validate.yml:19-42`),
and that its `version` is in lockstep with `marketplace.json` (`.github/workflows/validate.yml:43-52`)
and with the top CHANGELOG entry (`.github/workflows/validate.yml:54-81`).

The other standing gates in the same workflow: the frontmatter linter
(`.github/workflows/validate.yml:117-118`), the manifest invariant gate run against the example **and
every tracked run manifest** (`.github/workflows/validate.yml:120-134`), a committed `state.json` for
every committed run dir (`.github/workflows/validate.yml:136-159`), the anti-ruflo fabricated-metric
grep over `scripts/` and `docs/` (`.github/workflows/validate.yml:185-214`), and — deliberately last,
so cross-refs to files authored by later batches resolve — the repo-wide dead-link scan.
(`.github/workflows/validate.yml:232-274`)

## The `--selftest` convention

Deterministic scripts ship with built-in self-tests invoked by `--selftest` that build throwaway git
repos in `$TMPDIR` and run offline. The scope gate's `_selftest()` starts with pure glob unit tests
(including the literal-bracket dynamic-route cases) before any git is involved
(`scripts/compound-v-scope-check.py:626-683`), then covers the git integration cases — among them the
reproduced escaping-symlink exploit and the in-root link that must *not* trip it.
(`scripts/compound-v-scope-check.py:985-1010`) The onboard toolkit's `--selftest` is a top-level flag
rather than a subcommand. (`scripts/compound-v-onboard.py:1184-1186`)

CI runs the epic-state and epic-arbiter self-tests first under a **clean Python 3.9** to prove they
stay pure-stdlib (`.github/workflows/validate.yml:285-289`), then sweeps **every** `scripts/*.py` that
mentions `--selftest`, discovering new ones automatically (`.github/workflows/validate.yml:298-312`).
Everything under `tests/` is executed by a separate job that **always runs** — no `paths:` filter, no
`if:` guard, because GitHub reports a conditionally-skipped required check as `Success` — sweeping
`.sh` and `.py` recursively and failing when it discovers nothing.
(`.github/workflows/validate.yml:317-374`)

## Hooks — the native events the plugin registers

Nine bash hooks are wired through `hooks/hooks.json` across seven events: `Stop` (`hooks/hooks.json:8-19`),
`PreToolUse` on `Skill` and on `Write|Edit|MultiEdit|NotebookEdit|Bash` (`hooks/hooks.json:20-44`),
`UserPromptSubmit` (`hooks/hooks.json:45-57`), `PostCompact` (`hooks/hooks.json:58-70`), `SessionStart` with the
`startup|clear|compact` matcher (`hooks/hooks.json:71-89`), `PostToolUse` on `Write` (`hooks/hooks.json:90-108`),
and `PreCompact` (`hooks/hooks.json:109-121`). Every entry carries `"shell": "bash"` so these scripts are
not handed to PowerShell on a Windows box with no Git Bash. (`hooks/hooks.json:2`)

There is deliberately **no** `PostToolUseFailure` registration: the v3.3.0 tool-failure ledger wrote a
file nothing read, so both the hook and its event were removed in 3.4. (`hooks/hooks.json:6`)

## Key scripts

- `scripts/compound-v-scope-check.py` — the git-derived scope gate called after every job; emits a
  JSON verdict (`pass`/`blocked`) with exit codes 0 = pass, 1 = blocked, 2 = usage/git error.
  (`scripts/compound-v-scope-check.py:132-139`)
- `scripts/compound-v-emit-workflow.py` — **Engine C**: turns `manifest.yaml` into a native Workflow
  script (one `pipeline()` per dependency wave, three stages per job) and provides the deterministic
  entry points that script's agents call — `emit`, `gate-receipt`, `record`, `finalize-wave`,
  `resume-prepare`, `register-lane`. (`scripts/compound-v-emit-workflow.py:5-9`,
  `scripts/compound-v-emit-workflow.py:18-40`)
- `scripts/compound-v-integration-gate.py` — the integration **authority**: it runs outside the
  workflow, in a real shell, over the real trees, and refuses integration until every job resolves to
  a verdict it derived or verified itself (`pass` / `blocked` / `forged` / `contradicted` /
  `unverifiable`, the last failing closed). (`scripts/compound-v-integration-gate.py:15-18`,
  `scripts/compound-v-integration-gate.py:22-40`)
- `hooks/lane-guard.sh` — the `PreToolUse` deny that refuses an out-of-lane write before the bytes
  land; explicitly *not* a replacement for the scope gate, and fail-open on every uncertainty.
  (`hooks/lane-guard.sh:5-15`, `hooks/lane-guard.sh:32-58`)
- `scripts/compound-v-onboard.py` — the `/v:onboard` deterministic toolkit (stdlib only) whose
  subcommands are `pack`, `verify-citations`, `staleness`, `design-lint`, `detect-ui`, `scan-output`,
  `recommend-mcp`, `recommend-autoskills`, and `draft-taxonomy`. (`scripts/compound-v-onboard.py:1145-1170`)
  It reuses the engine's canonical secret-pattern families (`SECRET_RE`, `PEM_RE`) from
  `compound-v-memory.py` rather than forking a second list. (`scripts/compound-v-onboard.py:5-9`)
- `scripts/lint-frontmatter.py` — parses every markdown file's YAML frontmatter and validates it
  against the plugin spec and project conventions. (`scripts/lint-frontmatter.py:3-6`)
- `scripts/compound-v-validate-manifest.py` — the deterministic invariant gate backing the
  `partition-reviewer` agent: it either passes or fails with specifics, with no LLM judgment, no
  network and no fabricated metrics. (`scripts/compound-v-validate-manifest.py:3-14`)
- `scripts/compound-v-memory.py` — the V-memory recall engine (FTS5 core + opt-in embeddings).
  (`skills/compound-v/memory.md:3-10`)
- `scripts/compound-v-resolve-model.py` — the model broker that resolves `(backend, tier, effort)` →
  a concrete model, so routing survives model churn without editing call sites.
  (`scripts/compound-v-resolve-model.py:3-8`)
- `scripts/compound-v-preeval.py` — the Pre-Evaluation scorer (two axes: difficulty ⊥ impact) and the
  sole producer of the three-tier `decision` value every downstream consumer branches on.
  (`scripts/compound-v-preeval.py:3-14`)
- `scripts/compound-v-epic-state.py` · `-epic-arbiter.py` — the epic spine (a deterministic
  topological state file, one level up from `state.json`) and the cross-model failure arbiter, which
  is treated as a security boundary because it egresses feature evidence to an external model.
  (`scripts/compound-v-epic-state.py:3-9`, `scripts/compound-v-epic-arbiter.py:3-20`)
  The v2.11 auto-resurrection watcher and the v2.14 headless shim no longer exist — resurrection is
  the native `/loop` / `/schedule` and the goal is the native `/goal`. (`skills/compound-v/epic-mode.md:172-184`)
- `scripts/compound-v-usage-extract.py` · `-usage-aggregate.py` — measured-only usage: extract a
  canonical per-job `usage` object from a backend's own events log, or — for Engine C, whose Claude
  jobs have no events log — from the Workflow subagents' JSONL transcripts, then aggregate honest
  per-run totals. Missing or unparseable input yields `measured:false` with null counts, never a
  number. (`scripts/compound-v-usage-extract.py:17-20`, `scripts/compound-v-usage-extract.py:44-56`,
  `scripts/compound-v-usage-aggregate.py:3-14`)

## Doc placement convention

Compound V writes to a flat, predictable structure under `docs/superpowers/`: `recon/`, `archaeology/`,
`expert/`, `library-audit/`, `execution/<run-id>/`, `memory/`, `specs/`, and `plans/`.
(`skills/compound-v/SKILL.md:199-227`)
The run directory carries the run's own record — `manifest.yaml`, `state.json`, the committed
`dispatch.workflow.js`, `lane-map.json`, `jobs/`, `logs/`, `receipts/` and `results/`.
(`skills/compound-v/state-machine.md:140-157`) The onboarding pipeline extends this with
`docs/superpowers/architecture/*` plus root `CONVENTIONS.md`/`AGENTS.md`/`CLAUDE.md` and a conditional
`DESIGN.md`. (`skills/compound-v/onboarding.md:9-13`)
