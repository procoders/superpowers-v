# Native mechanisms vs. ours — audit and 3.0 checklist

**What this is.** Every guarantee Compound V makes, matched against the Claude Code mechanism that could provide it. It is simultaneously a **version comparison** (2.x → 3.0) and the **checklist 3.0 is built against**.

**Why it exists.** Compound V was built as an orchestrator. Claude Code has since grown a native orchestration runtime and a full set of enforcement points. This table is the honest accounting of which of our parts are a real architectural choice and which are a leftover from not having looked.

**Evidence.** Native-mechanism claims are from the installed binary (`2.1.238`) — its embedded `RunWorkflow` API reference, hook-event table and permission-layer strings — plus live probes. They are **not** from fetched documentation: a second fetch of the hooks page returned a confidently wrong Stop-hook contract, so for this runtime the binary is the source of truth.

**Standing rule, set by the maintainer 2026-09-01:** *if a native mechanism exists and covers the need, 3.0 uses it.* Ours survives only where nothing native exists, or where the native one demonstrably does not cover the case.

## Итог по третьей колонке

Три разных ответа, и они не равноценны.

**Нативного нет (8).** Триаж как решение, полосы, доказательство изменения, политика повторов, тесты, пол, кросс-вендорное второе мнение. Своё оправдано — **это и есть продукт**.

**Нативное есть, но не покрывает (4).** Resume не переживает смерть сессии; журнал эфемерен; `agentType` порождает, но не рецензирует. Своё оправдано, причина записана.

**Нативное есть, покрывает, и мы им не пользовались (12 — на одну больше, чем я насчитал сначала; `agentType` вскрылся при проверке таблицы по коду).** Из них пять — «решили в 1.0 и не построили» (весь Engine C), три — «не знали, что существует», одна — «не смотрели», одна — «удалили по ложной посылке», одна — рисуем сами. **Почти половина нашей механики оказалась не архитектурным выбором, а незнанием или недоделкой.** Все одиннадцать закрываются в 3.0.

## Пусто с обеих сторон — то, чего нет ни у нас, ни в рантайме

Закрывается в 3.0:

- **Тесты соразмерны правке** — в схеме манифеста не было ни одного поля про тесты.
- **Пол тестов** — код существовал как мёртвый: у `--test-cmd` не было производителя.
- **Решение о размере** — движок без вызывающего и без единого артефакта.
- **Доказательство изменения на claude-пути** — формально «наше есть», фактически проза, а через этот путь прошло 100% реальных джоб.

**НЕ закрывается в 3.0 — открытые дыры, названные, чтобы не забылись:**

- **Откат плохого слияния.** Джоба прошла гейт, влилась, позже выяснилось, что сломала соседа. Механизма нет ни нативно, ни у нас — только руками, и только если человек знает, что произошло.
- **Гонка двух сессий на одном репозитории.** Гейт партиции поймал частный случай: две сессии читают «предохранитель взведён», первая снимает, вторая работает по устаревшему разрешению. Общего взаимного исключения — файла блокировки, аренды — нет. С автономными прогонами это перестаёт быть теоретическим.

## Как этим пользоваться

Строка считается закрытой в 3.0, когда у неё есть **владелец в манифесте** и критерий приёмки, который можно проверить механически. Строка со статусом 🔬 требует живой пробы **до** того, как на неё что-то закладывается — сегодня таких строк нет.

**Единственная строка, которую проба перевела из 🔬 в ✅, стоит того, чтобы прочитать её целиком.** `PreToolUse` действительно достаёт до агентов воркфлоу и несёт `agent_id`, так что запрет по полосам возможен. Та же проба вскрыла и предел: матчер по `Write`/`Edit` обходится записью через шелл — `sed`, heredoc, — а эта среда прямо подталкивает агентов писать именно так. Поэтому Feature E матчит и `Bash`, инспектирует команды и работает в паре с `bashCommandClamp`, **но git-выводимый вердикт остаётся авторитетом**: разбор команд — это парсинг с неограниченным числом обходов, и полагаться на него как на единственную защиту нельзя.
