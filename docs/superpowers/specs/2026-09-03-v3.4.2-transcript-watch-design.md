# v3.4.2 — Transcript play-ahead: read the workers' transcripts before their results — design

Stage 3 of the post-3.4.0 verification program: a FULL normal task, run through the pipeline with zero
manual interventions. The feature is the mechanism the maintainer endorsed on 2026-09-03 after the
orchestrator used it by hand through five runs of 3.4.1: reading a live worker's transcript surfaces an
out-of-lane write, a denied command, a wrong cwd or a stall MINUTES before the gate records it — and in
r5 it let the orchestrator pre-stage the fix for a finding before the verdict landed.

## What exists (native artefacts, read-only)

- A workflow agent's transcript: `~/.claude/projects/<project>/<session>/subagents/workflows/<wf_id>/agent-<id>.jsonl`
  — one JSON object per line; `message.content[]` items of type `tool_use` (`name`, `input`) and
  `tool_result` (`content`); `agent-<id>.meta.json` (`agentType`, `model`); `journal.jsonl`
  (`started` / `failed` / `result` lines).
- The run directory: `lane-map.json` (job → cwd, isolation, written by `register-lane`), `manifest.yaml`
  (`write_allowed`, `isolation` per job), `state.json` (job statuses).
- The harness's `/workflows` and `/tasks` views — what a person watches. This feature is what the
  ORCHESTRATOR watches, and it never writes anything but its own state file.

## Decisions

1. **One read-only script:** `scripts/compound-v-transcript-watch.py --run-dir <run> [--wf <wf_id>]
   [--transcripts <dir>] [--once | --every <s>] [--state <file>] [--json]`. Python 3.9 stdlib. Exit 0 always
   (advisory), non-zero only on a usage fault. `--once` is the default.
2. **Discovery, not a new state field.** The workflow's transcript directory is found by scanning
   `<session>/subagents/workflows/*/agent-*.jsonl` for the run directory's absolute path (every worker prompt
   carries it in its `register-lane` command); the newest matching `wf_*` wins; `--wf` overrides. The session
   directory comes from `CLAUDE_CONFIG_DIR`/`~/.claude/projects/<encoded cwd>` and the newest session file
   that references the run, or `--transcripts` names it outright. No write to `state.json`.
3. **Signals — mechanical, no model, one line each:**
   - `out-of-lane` — a `Write`/`Edit` tool_use, or a `Bash` command whose redirection/`git rm`/`mv`/`cp`
     target is outside the job's `write_allowed` (matched with the scope gate's own matcher, imported by
     path from `compound-v-scope-check.py`, never a second matcher) AND not under the job's worktree-relative
     equivalent of an allowed path;
   - `wrong-cwd` — a `register-lane` whose `--isolation` disagrees with the manifest's `isolation` for that
     job, or whose `--cwd` is the repository root while the manifest says `worktree` (finding 60's shape);
   - `error` — a Bash `tool_result` containing `Traceback (most recent`, `Permission denied`,
     `command not found`, `No such file or directory`, `SELFTEST FAILED`, `\bBLOCKED\b`, or `exit code [1-9]`;
   - `stall` — no tool_use for more than `--stall-minutes` (default 8) on an agent that has not returned;
   - `denied` — a tool_result that is a PreToolUse denial (the lane guard's `DENY` text).
   Agent → job resolution: the `--job-id` of the agent's `register-lane` call; an agent with none is reported
   as `(unregistered)` and its writes are all `out-of-lane` candidates.
4. **Output:** `<HH:MM:SS> <job> <agent[:8]> <signal> <evidence[:140]>` per NEW signal since the last state
   (the state file keeps per-agent line offsets and emitted signal keys, so `--every` never repeats); a
   per-tick summary line `jobs: <id>=<status>… agents: N live, M returned`. `--json` emits one object per
   signal. Nothing is ever acted on automatically.
5. **Where it is used:** `/v:status --live <run-id>` calls `--once`; `/v:dispatch` step 6 tells the
   orchestrator to run `--every 120` in the background (the harness's Monitor tool) and to treat
   `out-of-lane` / `wrong-cwd` as a reason to `TaskStop` the workflow and re-orchestrate early — the exact
   move r1 of 3.4.0 needed and r2 of 3.4.1 would have caught in its first minute.
6. **Not in scope:** acting on signals; parsing external backends' own JSONL (the worker scripts already
   capture Codex's); a daemon; any write into the run directory.

## Pre-flight amendments (2026-09-03, after 1A archaeology and 1C library audit)

1. **YAML without PyYAML.** "Python 3.9 stdlib" cannot parse `manifest.yaml`; the script imports
   `load_yaml` from `scripts/compound-v-validate-manifest.py` by path — exactly as `hooks/lane-guard.sh`'s
   `repo_loader()` does — never a third parser.
2. **The real denial text.** The lane guard's denial reads `Compound V lane guard: job '<job>' is not
   allowed to write …` (no hyphen, no literal DENY); `Compound V lane-guard FAILED OPEN:` is an allow-with-
   notice, not a denial; the harness's own `bashCommandClamp` denial is unrelated to lanes and appears on
   routine retries. The `denied` signal matches the first string only.
3. **Agent → job comes from the agent's own `register-lane --job-id`, never from `lane-map.json`'s
   cwd→worktree map.** That fallback is what produced finding 68 (a finished run's direct job claiming the
   checkout); an agent with no register-lane call is `(unregistered)`.
4. **Transcript shape is Workflow-only.** `<session>/subagents/workflows/<wf_id>/agent-*.jsonl` holds
   Workflow-spawned agents (the only kind Compound V dispatches); a plain Task agent lands one level higher.
   Discovery scans `workflows/*/` only and a zero match is a clean, non-crashing "no transcripts found" line.
5. **`meta.json` keys are absent when default** (`model` missing, not null): every read is `meta.get(...)`;
   the fixtures include a meta file without `model`.
6. **Session directory resolution, stated:** `$CLAUDE_CONFIG_DIR` if set else `~/.claude`, then
   `projects/<cwd with every "/" replaced by "-">/<session-id>/subagents/workflows/`; `--transcripts` overrides
   it outright, and the newest session directory that contains a workflow mentioning the run directory wins.
7. **Finding 68 itself** is fixed alongside this feature, outside its lanes: the guard skips MERGED/BLOCKED
   runs, the finalizer deletes `lane-map.json` at a terminal phase, and the file is gitignored.

## Testing and evidence

`tests/test-transcript-watch.sh` builds a sandbox run dir (manifest with two jobs, one worktree, one direct;
a lane map) and synthetic `agent-*.jsonl` files: an in-lane Write (no signal), an out-of-lane Write, a Bash
`>` redirect outside the lane, a Traceback result, a `register-lane --isolation direct` on a worktree job, a
PreToolUse denial, and a stalled agent (old timestamps) — expected signals exactly; `--once` twice emits
nothing the second time; `--json` validates; an unregistered agent is named. The script's `--selftest` covers
the parsers on the same fixtures. The feature is verified through its own path: after the merge, the watch
is run `--once` against THIS run's own transcripts and its output is quoted in the review.

## Out of scope

`workflow_id` in `state.json`; a native `/workflows` replacement; Monitor-based auto-stop.
