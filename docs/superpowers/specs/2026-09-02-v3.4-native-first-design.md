## Global constraints

- Python 3.9, stdlib only. PyYAML is soft in `preeval`/`taxonomy` (the shared loader) and a **hard** dependency in `compound-v-emit-workflow.py` (`_load_yaml` exits without it) — run that file with `/usr/bin/python3`. Every hook fails **open** and stays inside its budget (`UserPromptSubmit`: `timeout: 10` in `hooks.json`; the Stop hook's shared 1.5 s).
- No fabricated metrics. Never Haiku. Hook input is untrusted: the prompt text is passed through an environment variable or stdin, never interpolated into a shell command.
- **A mechanism names its caller.** Every new subcommand or hook path in this spec states, in its own docstring, who invokes it. Nothing ships "for later".
- Existing tests either keep passing or are rewritten in the same task that changes the behaviour they pinned. `tests/test-epic-goal-stop.sh`, `tests/test-native-points.sh`, `tests/test-triage-landing.sh` and every `--selftest` stay green in CI (`.github/workflows/validate.yml`).
- Version `3.4.0`; `CHANGELOG.md` entry; `.claude-plugin/plugin.json` and `marketplace.json` in lockstep.

## WS1 — Epic: `/goal` + `/loop` + `/schedule` replace Feature A and the three schedulers

### What the binary offers (2.1.238, probed 2026-09-02)

- **`ProposeGoal` tool** — *"Propose a session goal condition, with one-keypress user approval; once set, Claude keeps working until a separate evaluator confirms it is met."* Condition: *"written so a separate evaluator can verify it from the conversation (e.g. `all tests in test/auth pass (bun test exits 0)`)"*, bounded length; `ask_user` defaults to true; plan mode blocks proposing; `/goal clear` clears; one goal at a time. An `@internal` setting can disable the tool (`disabled`), in which case a typed `/goal <condition>` is unaffected.
- **`/loop [interval] <prompt-or-slash-command>`** — a user-invocable skill (`argsMayContainSlashCommands: true`); interval mode is a cron entry (`CronList`/`CronDelete`), dynamic mode self-paces through `ScheduleWakeup` and ends with `stop: true`.
- **`/schedule`** — cloud routines on a cron schedule, or a one-time run; runs without the local machine.

### Replace — `commands/v-epic.md` and `skills/compound-v/epic-mode.md`

- **§0c Resurrection (was: arm two scheduler tiers).** When `autonomy.stance == marathon`, after the stance binding, *offer* — never arm silently — one of: `/loop 30m /v:epic <epic-id>` (this session; the model may invoke the `loop` skill only after the user says yes in this conversation), or a `/schedule` routine running `/v:epic <epic-id>` (cloud; survives the machine being off). `/v:epic` is re-entrant, so every firing is a plain resume. **Termination:** when the epic is terminal (`done`, `done_with_blockers`, `blocked_needing_human`, a tripped breaker), `/v:epic` prints *"epic terminal — stop the loop"* and, if it is the loop's own firing, stops it (`ScheduleWakeup stop` in dynamic mode; `CronDelete` on the `/loop` entry `CronList` shows in interval mode). The resume cap is the marathon's existing global breakers — there is no second counter.
- **§0d Goal (was: `--arm-goal`).** Marathon only; offered, never silent. If `ProposeGoal` is in the live tool listing: propose with `ask_user: true` and this condition, verbatim shape: *"epic `<epic-id>`: `python3 scripts/compound-v-epic-state.py --stats --state <path>` reports every feature `done` or the epic terminal"*. If the tool is absent: print exactly that as `/goal <condition>` for the user to type. The evaluator is the harness's; the condition points it at the deterministic `--stats` output so it never has to judge prose.
- **Honesty boundary (README, epic-mode.md, v-init 3c):** `/loop` shares the session's fate exactly as the old tier-1 did (paused while the session is busy or gone); `/schedule` is the genuine machine-off path and needs the cloud routine's own auth. The `:17/:47` cadence, the resume cap and the "one catch-up per wake" paragraphs are deleted — they described our schedulers. **The 7-day expiry stays, because it is true of the replacement:** `/loop`'s interval mode is a `CronCreate` job, and recurring `CronCreate` jobs *fire one final time after 7 days and are then deleted* (1C, live schema). A marathon expected to outlive a week needs a re-arm or `/schedule`. Marathons longer than 7 days are **out of scope for 3.4.0** and said so, not silently relied on.

## WS2 — Triage: the `UserPromptSubmit` hook runs the scorer

### One implementation, two callers

`scripts/compound-v-preeval.py` gains a subcommand **`triage`** — the body of today's Phase T2 block in `commands/v-triage.md`, moved out of prose:

```
compound-v-preeval.py triage --request-file F|--request-env VAR --repo DIR --session-id SID \
    [--t3-category C] [--json]
```

It binds `session_id`, `base_commit` and `declared_paths` through `build_record`'s kwarg (as T2 does), runs `run_preeval`, evaluates predicates 1–6, and prints either the human report (today's text) or, with `--json`, `{pre_eval_id, tier, decision, needs_t3, t3_prompt?, record_ref, predicates:[…], declared_paths}`. It never runs git. Callers, named in its docstring: `commands/v-triage.md` T2 (which becomes a one-line call) and `hooks/triage-prompt-nudge.sh`.

### The hook

`hooks/triage-prompt-nudge.sh` keeps its name, registration and every gate it has today (event, not a slash command, not a short question, session id present, repo has `.claude/compound-v.json` or `docs/superpowers`, no covering record for this session, no active run) and then, instead of a reminder:

1. Writes the prompt to a private temp file (`umask 077`), runs `python3 <plugin>/scripts/compound-v-preeval.py triage --request-file <tmp> --repo <proj> --session-id <sid> --json` **bounded** (the Stop hook's `_bounded_capture` pattern, 8 000 ms of the 10 s registration budget), and unlinks the file.
2. On a record: injects `additionalContext` — tier, `pre_eval_id`, bands, override if any, predicates 1–6, and the sentence *"record written, not committed: `/v:orchestrate` commits it at bind; for a DIRECT change include `docs/superpowers/pre-eval/<id>.*` in your commit."*
3. On `needs_t3`: injects the T3 prompt with *"run `/v:triage` to finish — one light Task."* (the hook never calls a model).
4. On any failure or timeout: injects today's reminder text unchanged. The hook never blocks, never commits, never exits non-zero.

**The once-per-session marker stays** (amended after the Review Gate's ISSUE 4, 2026-09-02): the record covers the "already sized" case, but the engine can decline to write — `pre_eval_disabled`, `needs_t3`, a failure or a timeout — and without a marker the hook would re-run the scorer on every prompt of such a session. The marker answers "already tried", the record answers "already sized"; both gate the hook, and the hook's header says so. `pre_eval.enabled: false` still makes the stage a no-op (the engine returns `pre_eval_disabled`; the hook then stays silent).

### What does not change

The Stop-hook triage gate reads records off disk, so an uncommitted hook-written record covers exactly as a committed one does. `/v:dispatch --require-triage`, the validator's `triage` block, `bind`, the outcome stream and the breaker are untouched. `/v:triage` T3 ("commit the record") stays for the command path.

### Tests — `tests/test-native-points.sh`, triage section

In a sandbox repo with the example taxonomy: a change-request prompt naming one file → a record exists under `docs/superpowers/pre-eval/` bound to the stdin `session_id`, and the context names its tier; a `?` question → silent; a slash command → silent; a second change request in the same session → silent (record exists); a repo with `pre_eval.enabled: false` → silent, no record; a scorer that fails (planted: unreadable engine path) → today's reminder text, exit 0. The existing "does not burn the marker on a question" assertions are replaced by "does not write a record on a question".

## After the fourth review pass (2026-09-02) — both scope-gate carve-outs are withdrawn

Two exemptions were added to `scripts/compound-v-scope-check.py`'s changed set *between* review passes, for real ergonomic problems, and the fourth pass showed each of them buying the ergonomics with a piece of the plugin's central control. The orchestrator's decision, recorded here: **the scope gate keeps no carve-outs.** Both are withdrawn; the honest cases they served are handled upstream.

1. **Interpreter bytecode, by extension.** Withdrawn because *a `.pyc` does not have to merge in order to run.* The fourth pass executed it: an **unchecked hash-based** `.pyc` (flags `0b01` — CPython never validates one against its source) planted at `scripts/__pycache__/compound-v-scope-check.<tag>.pyc` is hidden from `git status` by `.gitignore` and, under the exemption, from the gate; it is then loaded in-process by [`hooks/lane-guard.sh`](../../../hooks/lane-guard.sh)'s `spec_from_file_location` + `exec_module` on **every** `Write`/`Edit`/`Bash` call, and by [`compound-v-integration-gate.py`](../../../scripts/compound-v-integration-gate.py)'s deliberate import of the same module — and it can return an `is_allowed` that approves every out-of-lane write. `-B` and `PYTHONDONTWRITEBYTECODE=1` do not help: they stop Python *writing* a cache, not *reading* one. The upstream fix is two-sided — nobody writes bytecode (`-B` on every python command the emitter composes, `sys.dont_write_bytecode` in the three scripts, the instruction in the Implement prompt), and neither loader reads an in-tree cache (`PYTHONPYCACHEPREFIX` in the guard, `sys.pycache_prefix` around `exec_module` in the authority and in the emitter's two by-path imports).

2. **The pipeline's own outcome streams, by name.** Withdrawn because the exemption's safety claim — *"never land through merge-back"* — is true of merge-back and of the wave commit, and both are the wrong door. The pipeline commits `docs/superpowers/memory/triage-outcomes.jsonl` **by name** at [`commands/v-orchestrate.md:84`](../../../commands/v-orchestrate.md), [`commands/v-triage.md:220,721`](../../../commands/v-triage.md) and [`agents/parallel-dispatcher.md:349`](../../../agents/parallel-dispatcher.md), so a direct-mode worker's unreported rewrite rode the next such commit into a stream that resolves last-writer-wins and feeds the Tier-2 precision gate. The upstream fix is ordering, not forgiveness: the `merge_pending` `actual` moves out of `record` — which now writes nothing outside the run directory — into `finalize-wave`, **after** the integration authority has re-derived the wave and before the pathspec-restricted commit. The digest exclusions on both sides of the seam cover the run directory and nothing else.

**Stated residual, not papered over.** The append is placed after the authority has *run*, not after it has *permitted*, so a refused wave still records its outcome. That leaves one tracked file modified-but-uncommitted in the tree of a halted run: a later re-gate of that same run (`/v:collect`, `/v:resume`) will see it, and with no carve-out it is visible rather than silent. That is the intended trade — a loud, explicable extra path beats an invisible one — and the orchestrator's next documented `git add` of that path closes it.

## After the fifth review pass (2026-09-02) — the enforcement chain had a hole at each end

The fourth pass closed the scope gate's carve-outs. The fifth drove the resulting chain with a **real run's manifest** rather than a hand-written fixture, and found that neither end of it worked: the guard could not read the manifest, and the command that binds a job to the guard could not be run.

1. **The lane guard read no manifest written by `yaml.safe_dump`.** [`hooks/lane-guard.sh`](../../../hooks/lane-guard.sh) reads `write_allowed` through [`compound-v-validate-manifest.py`](../../../scripts/compound-v-validate-manifest.py)'s `load_yaml`, which without PyYAML falls back to an embedded subset parser. That parser modelled neither of the two shapes `safe_dump` emits for every manifest this pipeline writes — a scalar folded across lines at the dump width, and a block sequence at its parent key's own indentation — and stopped the parse at the first of either, dropping `jobs:` and everything after it. On a machine where `command -v python3` resolved to a build without PyYAML, the guard therefore resolved the job, found it in no manifest, and **failed open on the out-of-lane write**. The fix is both halves, because either alone leaves a hole: the subset parser reads what `safe_dump` writes and **raises** rather than returning a truncated document when a top-level `jobs:` yields no jobs; and the guard **prefers an interpreter that can `import yaml`** (`CV_PYTHON` verbatim, else `/usr/bin/python3` before `PATH`, else the first found), resolving that preference lazily — after a job has resolved — so the unresolved path an ordinary human session takes keeps its published cost.

2. **The command that arms the guard was denied by the clamp.** The Implement prompt emitted `--cwd "$PWD"`, and the per-spawn bash clamp refuses shell substitution. In run r9 the job's *first* command was denied for it — the single denial that leaves a job unregistered, and an unregistered job is one the guard resolves nothing for. The prompt now instructs `pwd` (an admitted form) and a literal `<ABSOLUTE_CWD>`. The "keep every command on ONE line" rule that a previous pass introduced is **retired**: it named the wrong cause (a continuation, not a substitution) and contradicted the emitter's own `_shell_join` launch commands.

3. **An acceptance grep that could not fail.** The withdrawn carve-out constants were written as split literals so a bare `grep -rn` for their names stayed clean. Two tests were made unreadable to protect a check that matched any *mention* rather than a *definition*. The names are spelled plainly; the acceptance check is `grep -rnE '^PIPELINE_BOOKKEEPING\s*=' scripts hooks`.

**The standing lesson, stated once.** Both defects at 1 and 2 survived four review passes because every test that touched them used a hand-written fixture — a manifest indented the way a person indents one, a command written the way a person writes one. Neither is what the pipeline actually produces. A test whose input the system under test would never generate proves the code works on inputs it will never see.

## After the sixth review pass (2026-09-02) — the fix chose its interpreter by guessing, and the numbers around it had gone stale

The fifth pass closed a hole at each end of the enforcement chain. The sixth read the fix itself and found that one half of it was a guess wearing the clothes of a decision, and that three files were still publishing a cost measured before two changes that doubled it.

1. **`-x` is not "can run".** [`hooks/lane-guard.sh`](../../../hooks/lane-guard.sh) chose its interpreter by **ordering** candidates and taking the first executable one, leaving `import yaml` to be discovered later inside the payload. A wrapper script, a stale shim, a virtualenv whose framework moved out from under it are all executable and all exit non-zero on anything; picked as *the* interpreter, the payload never runs, the wrapper discards the empty output, and the hook produces **no decision at all** — a silent no-op indistinguishable from an allow, which is the failure mode the fifth pass had just finished closing one layer down. The pick is now a **viability ladder**: the first candidate for which `<py> -c 'import yaml'` exits 0; failing that, the first for which `<py> -c pass` exits 0, logged by path with its missing PyYAML named; failing that, a log line saying the guard is INERT for that call. Fail-open stays the contract; silence does not. `/usr/bin/python3` is still probed before `PATH`'s, now purely as a **cost** heuristic — the probe decides, not the ordering — and `CV_PYTHON` remains the only candidate when set, put through the same ladder, because obeying an override is not the same as pretending a dead interpreter works.

2. **Assertions that grep the source for a comment.** Two checks in [`tests/test-lane-guard.sh`](../../../tests/test-lane-guard.sh) asserted the fix by grepping the hook for the string `CV_PY_CANDIDATES` and for the words `RESOLVED LAZILY`. Both would have stayed green through any rewrite of the mechanism, including one that deleted the behaviour. They are replaced by behavioural cases — a broken `python3` first on `PATH` and first in the candidate list, a list with nothing runnable on it, and a **planted mutation** (`_cv_can_yaml() { return 0; }`) that must make the same out-of-lane write pass in complete silence. A check that cannot fail is not evidence, and this is the second pass in a row to find one.

3. **A measured claim replaces a counted-once one.** "Across all 35 manifests… the parser now agrees with PyYAML" was re-run: over all **47** manifests under `docs/superpowers/execution/`, both parsers read every file, and the only field they disagree on anywhere is `jobs[].body` — the block scalars the subset parser flattens. Jobs lists identical **47/47** with `body` set aside (`write_allowed` among them), 12/47 including it.

4. **The published ambient cost had stopped being true, and the reason was ours.** `README.md`, `AGENTS.md` and the hook's own header all said 47–81 ms. Re-measured on the same machine — 50 invocations per path, old and new hook interleaved in one round, bare-interpreter floor taken in that round and rounds above ~31 ms of floor discarded as measurements of the load — the **unchanged** hook costs **120 ms** on the path that published 47. The fourth pass's `PYTHONPYCACHEPREFIX` redirection is why: a redirected bytecode-cache lookup that `PYTHONDONTWRITEBYTECODE` forbids populating recompiles every stdlib module from source on every invocation (31 ms plain → 90 ms with both). The viability ladder adds ~45 ms more. Published now: **167 ms** unresolved, **~245 ms** resolved, with the decomposition and the discard rule in the hook's COST header. The standing lesson: a defence that lands between measurements invalidates the measurement, and nobody re-took it for a day across three files.

## After the seventh review pass (2026-09-03) — the implementer had no role, and two pieces of evidence could not fail

The sixth pass fixed how the guard picks an interpreter. The seventh read what the pipeline actually *tells* a worker, and re-read the two artefacts that are supposed to prove the sixth pass's fix.

1. **An implementer arrived with no role.** Every Claude implementation job was spawned anonymously: its whole contract was whatever `_implement_prompt` restated inline, it inherited the session's turn budget, and nothing carried the model's own guidance on scope, narration cadence or deliverable length. `agents/implementer.md` is that role now, and the emitter spawns every non-reviewer Claude job as it (`type: review` keeps `spec-reviewer`; the other reviewer-ish types stay anonymous rather than being told to write inside a lane).

   Arriving as a role is also **the only native way a workflow job gets a turn cap**. Checked against the binary (2.1.238): the workflow `agent()` options are `label`, `phase`, `schema`, `model`, `effort`, `isolation`, `agentType`, plus `disallowedTools` and `bashCommandClamp` — **no `maxTurns`** — while an agent *definition* file supports `maxTurns:` as a positive integer. So `implementer` carries `maxTurns: 80` and `spec-reviewer` `maxTurns: 80`, `lint-frontmatter.py` rejects a malformed cap (the runtime ignores one silently, which is worse than absent), and the inline-definition fallback **logs that the cap is lost** on that path, because an inline spawn is not a definition and nothing can re-impose it.

   Three subtractions follow from Anthropic's Opus 5 guide, and they are subtractions on purpose: the official scope / cadence / deliverables snippets go into the role verbatim (effort buys *thinking*, not output length, so length is asked for explicitly); `render_worker_prompt` adds **no** "verify / re-check / report per item" imperative of its own, because explicit verification instructions make this model over-verify and the Gate re-derives every enforcement fact from git anyway; and the prompt states the job's turn cap (`max_turns`, else `light` 30 / `standard` 50 / `deep`·`frontier` 80), saying plainly that for an external worker it is a budget it is *told*, not a ceiling any runtime imposes.

   `compound-v-validate-manifest.py` needed no change and got none — it is out of this job's lane, and it rejects no unknown per-job key by design. Verified rather than assumed: `examples/manifest.example.yaml` with `max_turns: 40` added validates `valid`.

   **Effort became a policy by job kind** (`routing-policy.md`, `execution-manifest.md`, `v-orchestrate.md` step 4): new code and design `deep`·`high`; a **fix job minted from a review finding** `medium`, since the finding already names the file, the defect and the bar; a reviewer `high` on the first pass and `medium` on a re-pass over the same diff; transports `low`. And `/v:init` gained one **offer**, never a write — `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` in the user's own settings `env`. The name and the "0"/"1" semantics are binary-verified (`"1"` selects the SIMPLE/short prompt, `"0"` turns it off and selects the long preset with the anti-verbosity rules, so the offer recommends `"0"`); whether the long preset actually helps stays a community claim this project has measured nothing about.

2. **The `PATH` case could not fail.** `tests/test-lane-guard.sh` asserted that an executable-but-broken `python3` first on `PATH` still denies — which is true under the plain ordering the ladder replaced, because `/usr/bin/python3` is probed first and the broken one is never reached. The case that discriminates is the one the hook's header claims: `PATH`'s python3 imports yaml and the OS one does not, so the probe and not the order decides. It cannot be built by editing `PATH` alone, so the suite now drives a hook copy whose OS candidate is dead, asserts the log **names the interpreter used** and the one passed over, and then plants the pre-change order (`_cv_can_yaml() { return 0; }`) and asserts the same out-of-lane write passes in complete silence. The hook logs its chosen interpreter on **every** path now, not only the fallback ones — otherwise the pick is unobservable exactly where it matters. **Third pass in a row to find a check that could not fail.**

3. **The published cost was measured on the wrong path, and for one population only.** The `-c pass` probe moved out of the `import yaml` loop into its own. Stated precisely, because the flattering claim is wrong: that changes **nothing** for the ordinary machine (it already broke out on its first candidate) and nothing where no candidate has PyYAML (still three probes); it removes one probe from the machine whose **second** candidate has PyYAML, 3 → 2. Re-measured 2026-09-03, 50 invocations per cell, two qualifying rounds (floor 25.6/25.9 → 26.2/26.3 ms), against a sandbox carrying copies of the repo's 48 run directories: **149 ms** unresolved with one probe, ≈175 ms with two (derived from the measured parts, and flagged as derived), **200 ms** with three, **240 ms** resolved. The 167/245 ms of the sixth pass is superseded as noisy, not withdrawn as wrong. The method error worth keeping: the first attempt drove the "unresolved" loop from the checkout itself, which this very run's lane map claims, and produced 247 ms — the **resolved** path wearing the wrong label. Measure the unresolved path somewhere unresolved, and read `CV_LANE_GUARD_LOG` back to confirm which one you hit.

## After the eighth review pass and Codex round 4 (2026-09-03)

The eighth pass re-read the seventh pass's own artefacts, and a Codex cross-model round then read the merge and lane-guard code the fourth through seventh passes had produced. Both are closed by run `2026-09-02-v3.4-native-first-r12`.

**Eighth pass**, six items: **#1** the `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT` offer had the toggle backwards in its own prose — `"0"` turns the SIMPLE prompt *off* and selects the long preset carrying the anti-verbosity rules, not the other way round; the offer text and the two references to it above now state that, with the source labelled binary-verified name/semantics, community-claim benefit. **#2** `agent_role_for` now matches reviewer types exactly (`review`, `spec_review`, `quality_review`, `integration_review`) instead of a loose match, and returns a reason when it declines a role; `review_fix` jobs get the implementer role. **#3** `tests/test-lane-guard.sh` asserts the interpreter log line on the healthy path — nothing passed over — so a planted restoration of the pre-sixth-pass conditional turns that assertion red. **#4** a malformed manifest `max_turns` degrades to the tier default with a note in both the rendered prompt and the emit output, rather than degrading silently. **#5** `implementer`'s `maxTurns` was **60** while `execution-manifest.md`'s stated deep-tier default is **80** — the two disagreed with each other in the same release. `agents/implementer.md` now carries `maxTurns: 80`, matching the default it inherits under `deep`. **#6** the interpreter is logged once per session rather than once per hook invocation, and the COST paragraphs in `README.md`/`AGENTS.md`/the hook header state that.

**Codex round 4** (`docs/superpowers/reviews/2026-09-03-codex-round-4-gate-changes.json`), nine findings, closed by the `patch-artifact` and `guard-hardening` jobs of run r12:

- **C1** critical — the manifest was mutable after Gate-time approval; a lower-trust worktree worker (Antigravity/Cursor, per `AGENTS.md`'s own confinement caveat) could widen its own lane and have both gates accept the result, because `cmd_gate_receipt` re-read `manifest.yaml` live. **Closed:** `emit` bakes `sha256(manifest.yaml)` into the emitted script's `CFG.manifest_digest`; Gate, Record, the authority and Finalize all re-verify the on-disk manifest against that digest and refuse on mismatch.
- **C2** critical — the enforcement CLIs stayed shadowable: a planted module or stale `.pyc` on `sys.path` could load before the bytecode-cache defences took effect. **Closed:** every enforcement entry point (`compound-v-emit-workflow.py`, `compound-v-integration-gate.py`, `compound-v-scope-check.py`, `compound-v-validate-manifest.py`) strips its own directory and the cwd from `sys.path`, and sets `sys.dont_write_bytecode`, before any non-stdlib import.
- **C3** critical — the authority verified the live tree at one moment, but Finalize staged that tree again afterward; a mutation landing between the two, or a worktree whose patch never actually merged, was invisible to the check that was supposed to catch it. **Closed:** the Gate captures a sealed per-job artifact (`jobs/<id>.patch`, `git diff --cached --binary` against the baseline, restricted to the job's approved paths) and its sha256 in the receipt; the authority validates that artifact, not the live tree; Finalize applies exactly the artifact and proves from git, after the commit, that HEAD's version of every artifact path equals its post-image, before pruning.
- **C4** critical — worker-writable `state.json` could forge the idempotence marker (`realised_commit` et al.) and make Finalize permanently skip a real merge. **Closed:** state is a cache, never authority; the idempotent resume branch now requires git proof — the sealed patch digest bound into the merge commit — not a trusted field.
- **H1** high — ordinary test-generated files created after the honest scope check could turn a green floor into an authority contradiction, defeating the documented promise that test byproducts sit outside the Gate's authority. **Closed:** by validating the sealed artifact captured at Gate time rather than re-scanning the live tree, a later test run's byproducts cannot contradict what was actually approved.
- **H2** high — when the private pycache prefix could not be created, both `hooks/lane-guard.sh` and the authority's `_load_module_from_path` silently fell through to an unredirected `exec_module`. **Closed:** a failed cache-prefix creation now means the hook emits its fail-open notice and skips the load, and the authority fails closed with a reason — neither ever imports unprotected.
- **H3** high — the lane guard's interpreter-viability probes had no watchdog, and `hooks.json`'s `PreToolUse` registration had no timeout, so a candidate wrapper that hangs (e.g. `sleep 30`) stalled every tool call rather than failing open on schedule. **Closed:** every probe runs under the hook's own sub-second bounded-capture pattern; the registration carries an explicit timeout sized to and documented against the measured cost in `hooks.json`'s `$comment`.
- **H4** high — resume-after-prune verification accepted a commit as proof a job merged merely because some ancestor commit touched a matching pathname (`any(...)` over touched paths) — not proof that job's own patch landed. **Closed:** resume verification binds to the sealed per-job patch digest recorded at merge time, not to pathname overlap with any ancestor commit.
- **L1** low — the run-directory exemption docstring claimed an "EXACT, CLOSED LIST" of three files while the implementation exempted more (`receipts/<id>.gate.json` among them). **Closed:** the docstring and comments now name the actual exemption classes, backed by a table-driven test generated from the same canonical list so the two cannot diverge silently again.

Every existing guarantee from the fourth through seventh passes is kept unchanged: fail-open contract on the hook, Python 3.9 floor, bash 3.2 floor. Tests: `tests/test-integration-gate.sh` and `tests/test-engine-c-contract.sh` cover the sealed-patch and manifest-digest mechanisms end to end (reverted-but-not-pruned worktree, post-Gate ignored byproducts, a forged `state.json`, a widened manifest, a planted shadow module, a forced cache-prefix failure); `tests/test-lane-guard.sh` covers the hook-side shadow-module, cache-prefix and hung-probe cases.
