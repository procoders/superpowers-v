# v2.17.0 — Co-change advisory + bounded evidence packing

Two approaches internalized from a critical review of `repowise-dev/repowise` (AGPL-3.0 — **ideas only,
no code copied**). Six other candidates were evaluated and **rejected on our own data**; the rejections
are recorded below so we do not re-litigate them.

**Revision r2** — rewritten after the Phase-1A code archaeology falsified three claims in r1. Each
correction is marked `[r2]` where it changed the design.

## Feature A — Co-change advisory (the inverse of the scope gate)

**The gap.** Our scope gate answers *"did a worker write OUTSIDE its lane?"* — a containment question.
It cannot answer the opposite and equally real failure: *"does a partition cover file A but FORGET
partner file B, which our own history says always moves with it?"*

**The evidence (measured on this repo, 372 commits since 2026-01-01; reproduced independently by the
archaeology pass).** Three pairs clear `n>=5` and `min(P(B|A), P(A|B)) >= 0.70`, and **all three have
been violated — 10 times total**:

| Pair | n | P(B\|A) | P(A\|B) | historical violations |
|---|---|---|---|---|
| `.claude-plugin/plugin.json` ↔ `.claude-plugin/marketplace.json` | 34 | 100% | 94% | 2 |
| `commands/v-epic.md` ↔ `skills/compound-v/epic-mode.md` | 17 | 81% | 94% | 5 |
| `AGENTS.md` ↔ `GEMINI.md` | 8 | 73% | 100% | 3 |

One violation is **live at HEAD**: `GEMINI.md` is 2 commits behind `AGENTS.md` and the two differ by
134 diff lines.

**[r2] The generalization claim is narrowed.** r1 said this feature generalizes "the" bespoke lockstep
CI guard. There are in fact **two** guards — `validate.yml:43-52` (plugin↔marketplace) and
`validate.yml:54-81` (CHANGELOG↔plugin) — and the second pair measures `min(P) = 0.59`, **below the
bar**, because `CHANGELOG.md` is touched 56 times against `plugin.json`'s 36. So the computed signal is
**silent on a rule this repo really enforces**. Both CI guards stay; **neither is removed**. The honest
claim: this feature finds pairs nobody has hand-written a guard for, and it does **not** replace the two
we have.

### Design

New `scripts/compound-v-cochange.py` — pure stdlib, git-derived, **zero model involvement**:

- `pairs --repo . [--since <date>] [--min-n 5] [--min-conf 0.70] [--max-files 40]` — emit JSON pairs.
- `check --repo . --files <list>` — given a file set, return partners that are missing.
- **[r2] No cache, no cache file.** r1 said to mirror `docs/superpowers/memory/churn-cache.json`; the
  archaeology proved that file **does not exist in this repo and is untracked** — the precedent is
  absent. Full computation over 372 commits is sub-second, so v1 computes on demand. No
  `formula_id`, no `head_sha`, no committed artifact, no shared resource. (YAGNI: add a cache only if a
  repo appears where the scan is actually slow.)

**Git contract — every branch decided explicitly (the archaeology showed these are not inheritable
from `compound-v-churn.py`, which mines `--numstat` for a different purpose):**

- **[r2] Rename detection is ON (`-M`).** `churn.py:255` passes `--no-renames` deliberately so numstat
  paths stay literal. Inheriting that here would be a **correctness bug**: without rename detection a
  single rename emits the old and new path in one commit and **fabricates a co-change pair with perfect
  confidence**. We pass `-M` and cover a rename in the selftest fixture.
- **Pure-format commits are dropped**, reusing `_is_format_subject` / `_compile_format_patterns` from
  `compound-v-churn.py` by import (never forked).
- **Excludes** come from `load_churn_config` — imported, so they stay genuinely single-sourced.
  **[r2] Stated plainly: on this repo that resolves to ZERO exclusions** (`.claude/` holds only
  `compound-v-impact-taxonomy.example.yaml`, and `load_churn_config:166-174` refuses the `.example`
  fallback by design). The excludes are a contract honored for downstream repos, not an effect here.
- **Every git call routes through `compound-v-run-with-timeout.py`** with `stdin=DEVNULL` and a byte
  cap, per the external-launch invariant (`churn.py:195-228`). Never `subprocess.run(timeout=)` on git.
- `--no-merges`; the `capped` truncation flag is honored (a truncated trailing line is dropped).
- **A non-zero git exit is reported visibly**, not silently flattened into "no pairs" (the sibling's
  latent behaviour at `churn.py:259-260` is not inherited).
- **Partners that no longer exist at HEAD are filtered**, or `check` would name a deleted file forever.
- `glob_match` is **imported** from `compound-v-taxonomy.py`, never forked — a third glob copy is
  exactly what CONVENTIONS.md forbids.

**[r2] ONE consumption point, the safe one.** r1 wired the signal into both the partition reviewer and
Review-Gate Pass 3. The archaeology found that `agents/spec-reviewer.md` has **no WARN vocabulary at
all** — every finding is an `ISSUE:`, and `:14` / `:203` make any `ISSUE:` a hard DONE-blocker enforced
by `commands/v-collect.md:41`. Wiring an advisory correlation in there would have **blocked every merge
on a correlation**, violating this spec's own anti-goal without a line of code. So v1 wires **only**
`agents/partition-reviewer.md`, which already has the exact precedent — `WARN: BATCHING_MISSING`
(`:93`, *"a warning, not a fail"*), rendered at `:121-123`, **outside** the FAIL block that starts at
`:105`. New sibling step after Step 6 emitting `WARN: COCHANGE_PARTNER_MISSING`, plus one line in the
PASS template at `:126-133`. The Review Gate is **not touched**. `spec-reviewer.md` stays as is.

**Anti-ruflo, non-negotiable:** counts and measured conditional frequencies only, never a fabricated
"risk score"; every warning carries `n`, both directions, and the sample window; a pair below the bar is
**silent** rather than guessed at. It never blocks and never edits — the scope gate remains the only
hard gate, because a co-change signal is a correlation, not a contract.

## Feature B — Bounded evidence packing for cross-model prompts

**The gap.** We have been burned twice by oversized prompts to external judges: an open-ended Codex
review timed out at exit 124 as the repo grew (v2.6.2), and Sol went flaky at exit 144 on heavy repro
prompts (v2.12) — both fixed ad-hoc by hand-tightening that one prompt. The three truncators that exist
today (`_bound_text` at `epic-arbiter.py:770-774`, `_cap_bytes_with_marker` at `:608-620`, and the caps
at `:107-127`) are **all tail-drop**, so they amputate exactly the traceback at the end of a log. This
is a genuinely new capability, not a duplicate.

### Design

`pack_evidence(text, budget_chars, section_label)` added to `scripts/compound-v-collect-results.py`
(the existing home for worker output), imported by the arbiter through the **existing**
`_load_sibling_module` seam (`epic-arbiter.py:526-541`) — no new loader.

- **Failures first, always.** Error/failure/traceback lines are never dropped; passing noise is trimmed.
- **[r2] Runs BEFORE `redact()`, and its markers carry NO paths.** The archaeology surfaced a real
  dilemma: after `redact()` the markers egress un-redacted repo paths to both Codex (`:1489`) and agy
  (`:1519`); before it, `redact`'s byte cap and `_bound_text` can still tail-amputate. **Resolution:**
  run before redaction *and* drop the path from the marker entirely — `[cv-omitted: 142 lines]` with a
  section label, never a file path or line range. Nothing in the marker needs scrubbing, so the ordering
  dilemma dissolves. A judge that needs the detail is told the evidence was trimmed and can ask.
- **[r2] It MUST NOT raise.** `redact()` fails closed on any exception (`:646`, `:665-666`), so an
  exception here would silently degrade **every** arbiter ballot to the evidence-free placeholder at
  `:803-804`. `pack_evidence` wraps its whole body and **falls back to returning its input unchanged**.
- **[r2] Composes with the existing truncators instead of fighting them.** It is called with the *same*
  budget the downstream cap uses, so its output is already under the limit and `_bound_text` becomes a
  no-op. The marker vocabulary is reconciled with the existing `TRUNC_MARKER` (`:129`) rather than
  becoming a third dialect.
- **Bounded and honest.** The real pre-trim size is reported; small inputs are byte-identical
  passthrough.
- The CLI contract of `collect-results.py` (`main()` at `:670-718`) is **unchanged**; new cases go in
  the existing `_selftest()` (`:533-626`) using its `check(name, cond)` idiom.

## Feature C — "The limits ship with the claim"

Any published number about Compound V ships with a **"What this does not show"** note in the same
document. **[r2] Home changed:** r1 put this in `CONVENTIONS.md`, which the archaeology showed carries a
generated-file header (`:1-6`) and is rewritten by `/v:onboard --refresh` — the rule would have been
silently erased. It becomes **`docs/superpowers/adr/0002-limits-ship-with-the-claim.md`** instead: a
genuine decision with alternatives and consequences, non-generated, and V-memory-recallable. (It also
gives the ADR corpus a second entry — see the rejected-candidates note on ADR relations.)

## Rejected candidates (killed on our own data — do not re-litigate)

- **ADR relations (`supersedes` / `refines` / `conflicts_with`) + staleness scoring.** REJECTED: we have
  **exactly 1 ADR**. A relation graph over one node is textbook over-engineering. Revisit at ~10.
- **Self-validating the Pre-Evaluation scorer against its own outcomes.** REJECTED FOR NOW: only **2 of
  9** recorded runs are pre-eval-backed. An accuracy claim off n=2 would itself be the
  fabricated-confidence defect our charter forbids. Revisit at n>=20.
- **`impacted-tests` (run only the tests a diff exercises).** REJECTED: directly contradicts the v2.14.1
  lesson — we found 25 of 29 selftests silently never running in CI. Running *fewer* tests is the bug we
  just fixed.
- **Mining agent transcripts for repeated corrections into decisions.** REJECTED: v2.16's hardest
  invariant is that a rationale is captured UNPROMPTED and **never inferred**; Codex caught 7
  fabricated-evidence defects there. Inferring a preference from a transcript is that exact defect class.
- **Multi-source decision mining (ADR files, PR bodies, commit archaeology, comments).** REJECTED: a
  code-intelligence project, not an orchestration one. Out of our layer.
- **Code-health scoring / dependency graph / generated wiki.** REJECTED: not our layer, and enormous.
  Compound V orchestrates and verifies builds; it does not index codebases.

## Global constraints

Python **3.9-safe, stdlib only** (CI installs only `pyyaml` + `jsonschema`; PyYAML stays soft, reached
only through the taxonomy loader). No `X | None` annotations, no `match`/`case`. `--selftest` present as
a **literal string** so the v2.14.1 CI auto-discovery loop finds it (`validate.yml:271-274`), **ASCII-safe
under `LANG=C`**, offline, no real git identity (pin `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` to
`os.devnull` per `churn.py:460-472`), no dependence on a real taxonomy. tz-aware
`datetime.now(timezone.utc)`, never `utcnow()`. Deterministic JSON: `indent=2, sort_keys=True,
ensure_ascii=True` + trailing newline. **No fabricated metrics** (CI greps for cost/savings phrasing at
`validate.yml:159-179`).

## Acceptance criteria

- `compound-v-cochange.py pairs` reproduces the three documented pairs on this repo at the documented
  thresholds; `check` flags a file set missing a partner; a partner deleted at HEAD is filtered out.
- **A rename fixture in `--selftest` proves `-M` prevents the fabricated self-pair** — the single
  highest-value test in this build, since the wrong flag yields a pair at 100% confidence that is pure
  artifact.
- **`--max-files` is covered by a selftest fixture**, because it drops **0 of 372** real commits here and
  real data cannot exercise it.
- A non-zero git exit is surfaced, not flattened to "no pairs".
- Every co-change output carries `n` + both conditional frequencies + the window; no fabricated score;
  the signal is advisory and **never** returns a BLOCKED verdict.
- The partition-reviewer warning renders **outside** the FAIL block; `agents/spec-reviewer.md` is
  **untouched**; both existing CI lockstep guards (`validate.yml:43-52`, `:54-81`) still pass unmodified.
- `pack_evidence()` never drops a failure line; never raises (returns its input on any internal error);
  emits path-free `[cv-omitted: N lines]` markers; small inputs are byte-identical passthrough;
  `collect-results.py`'s CLI exit codes and stdout are unchanged.
- ADR `0002` exists and states the limits rule; `CONVENTIONS.md` is **not** edited.
- 2.17.0 lockstep across `plugin.json` + `marketplace.json` + `CHANGELOG.md` (the very pairs Feature A
  studies); all selftests green under `LANG=C` on Python 3.9; scope gate clean on every job.

## Anti-goals

NO new hard gate (co-change is advisory — correlation is not a contract). NO edit to
`agents/spec-reviewer.md`. NO model involvement in computing pairs. NO fabricated risk score or
confidence %. NO cache file, no committed artifact. NO paths inside omission markers. NO change to
`collect-results.py`'s CLI contract. NO edit to `CONVENTIONS.md`. NO removal of either existing CI
lockstep guard. NO code copied from an AGPL-3.0 project. NO code index, health score, dependency graph,
or decision mining.
