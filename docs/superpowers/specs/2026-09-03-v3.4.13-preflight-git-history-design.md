# v3.4.13 — the pre-flight archaeologist may read git history (finding 145) — design

**Date:** 2026-09-03 · **Scope:** one clamp list and its selftest; stage 8 of the verification program (a perfect pass with a stopwatch).

**Probe.** `scripts/compound-v-emit-preflight.py` clamps every pre-flight agent's Bash to two forms —
`compound-v-memory.py search:*` and `compound-v-memory.py recall-check:*`. Phase 1A (code archaeology) is asked for "recent
commits" evidence and, on 2026-09-03, reported twice that `git log`/`git blame` were unreachable, so its history evidence came
from dated prose instead of git.

**Decision.** The emitted clamp gains three read-only git forms — `Bash(git log:*)`, `Bash(git blame:*)`, `Bash(git show:*)` —
for every pre-flight agent (1A, 1B, 1C share one clamp; all three are read-only auditors). No write-capable form is added:
`git status`, `git diff` stay out (they were never requested), and nothing that can change the tree or the index.

**Files.** Modify `scripts/compound-v-emit-preflight.py` only: the `clamp` list next to the two memory forms, and its
`--selftest` — one check that the emitted script's `bashCommandClamp` contains the three git forms, one check that it contains
no form beginning with `Bash(git ` other than those three (so a future edit cannot slip `git commit` or `git checkout` in).

**Acceptance criteria.** `python3 scripts/compound-v-emit-preflight.py --selftest` passes with the two new checks; an emitted
pre-flight script (`--spec <any spec> --out <tmp>`) contains exactly three `Bash(git ` forms — `log`, `blame`, `show`; every
other existing selftest check still passes.

## Pre-flight amendments (2026-09-03, after 1A archaeology and 1C library audit; 1B skipped — internal tooling)

1. **The two existing selftest checks change in the same commit** (1A): "Bash is clamped to the recall query" and "every clamped
   python command carries -B" both assume every clamp rule is a `compound-v-memory.py` form; they are narrowed to the python rules.
2. **The singularity claims go** (1A): the module docstring ("with ONE exception … the recall query") and the comment above the clamp
   ("The one shell form an auditor needs") are rewritten in the same change — same file, same lane.
3. **Exactly three forms, nothing else git-shaped** (1A, 1C): `git log`, `git blame`, `git show`; the second new check is exhaustive.
4. **Residual risk, recorded and accepted** (1C): `git log` and `git show` accept `--output=<file>`, which writes bytes to any path the
   process can reach, and the pre-flight stage has no scope gate. The auditors already hold the `Write`/`Edit` tools by design (they
   write their audit document), so `--output` adds no capability an auditor does not already have; the clamp is a spend limiter for
   Bash, not the auditors' write boundary. No argv hook is added. `git blame` is clean of any file-writing option.
5. **`bashCommandClamp` semantics are inferred** (1C): the public workflows page still does not document the option; the syntax is
   the shipping `Bash(prefix:*)` form this repository already relies on in `compound-v-emit-workflow.py`.
