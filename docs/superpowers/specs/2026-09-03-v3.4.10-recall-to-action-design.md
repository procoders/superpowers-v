# v3.4.10 — the recall→action bridge acts at emit time (stage 5b: recall→action) — design

**Date:** 2026-09-03 · **Stage:** 5b of the post-3.4.0 verification program

## What the probe found

- `compound-v-memory.py recall-check` (the deterministic, conservative-only bridge `memory.md` promises) says **`tighten` for 7 of the 27
  runs dispatched today** — every v3.4.6 run and v3.4.8, i.e. exactly the runs whose emitter job died to the implementer's turn cap on
  `scripts/compound-v-emit-workflow.py` (2 prior failure records on that file by the second attempt, 4 by the fourth). The signal was right
  and early. **Nothing consumed it**: `memory.auto_tighten` / `memory.auto_recall` are read by no script; the reviewers run
  `recall-check` by prose at the END of a run; the emitter never asks.
- The bridge's documented actions — force worktree, extra review pass, fold into Task 0 — do not map to Engine C: worktree is already the
  default, "extra review pass" and "fold into Task 0" have no mechanism in the emitter. The action that would have saved five runs was a
  hard reading budget and a smaller job.
- A first probe reported `none` everywhere: zsh does not word-split an unquoted variable, so every lane went in as one string. Recorded
  so the next person does not repeat it.

## Decision

At emit time, for every implement job, the emitter runs `recall-check --files <write_allowed> --json` (subprocess, the same stdlib CLI;
never an import). The verdict is recorded in the emitted job entry and on the job in `state.json` (`recall_check: {verdict, match_count, evidence[:3], recall_check_ms}`), where the reviewer's Step 0 reads a fact instead of re-deriving one — `state.json` carries it for a `tighten` verdict; `none`/`unavailable` stay in the emitted entry and the emit summary. (Review-1 item 4: the gate receipt does not carry it; the clause was struck rather than the receipt widened.)

When the verdict is `tighten`:

1. **Always, when `memory.auto_recall` is on (default true; `emit --no-recall` forces it off for one emit):** the implementer prompt gains a `## Prior failures on your lane` section —
   the count, the last three evidence lines (run · status · file), and the instruction that follows from them: budget your reading
   (`grep -n` then `sed -n` ranges, ≤ 20 reading calls), never read a large file top to bottom, commit what is complete if the turn budget
   nears. Measured facts, no adjectives.
2. **Applied only when `memory.auto_tighten` is true (default false, set at `/v:init` Step 3b):** the job's tier is raised one rung
   (`light → standard`, `standard → deep`; `deep`/`frontier` unchanged; an explicit `model:` pin is never touched — the same rule as
   `escalate_claude_model`), and the review job's acceptance gains "re-run `recall-check` over the merged diff and state whether the
   prior-failure pattern recurred". Never a lower tier, never a different backend, never a loosened test slice — conservative-only, as
   `memory.md` promises.

`--no-recall` on `emit` skips the lookup (a missing or erroring `compound-v-memory.py` is noted and stepped past, never a reason to refuse
to emit). The verdict is also printed in `emit`'s JSON summary.

## Files

`scripts/compound-v-emit-workflow.py` (+selftests: a fixture results root with two failures on a lane ⇒ tighten ⇒ the prompt section and
the state field; auto_tighten on ⇒ tier raised, pin untouched; off ⇒ prompt only; `--no-recall` ⇒ nothing), `skills/compound-v/memory.md`
(the bridge's real actions on Engine C replace the three that never existed there), `commands/v-init.md` (Step 3b's `auto_tighten`
sentence names the real action), `CHANGELOG.md`.

## Acceptance criteria

1. `emit` on a manifest whose lane has ≥ k prior failure records writes `recall_check` on the job in `state.json` and the implementer
   prompt carries the `## Prior failures on your lane` section with the evidence; with fewer records neither appears.
2. With `memory.auto_tighten: true` the job's tier is raised one rung and the review acceptance gains the re-check clause; with the
   default false, the prompt section alone; an explicit `model:` pin is never changed either way.
3. `--no-recall`, a missing engine, or an engine error ⇒ emit proceeds with a note; never a refusal.
4. `memory.md` and `commands/v-init.md` describe exactly these actions; the three phantom actions are gone; CHANGELOG entry; selftests
   green (`compound-v-emit-workflow.py --selftest`, `tests/test-engine-c-contract.sh`).

## Decisions forced by pre-flight 1A/1C (2026-09-03)

- **Where the verdict is recorded.** `cmd_emit`/`build_plan` has no state.json write path. The verdict rides in the emitted job entry (`CFG`) and reaches `state.json` through `register-lane` — the runtime hook that already writes into a job's state entry before its work starts — via a new `--recall-check-json` argument the emitted register-lane command passes. No new state writer in emit.
- **The tier raise happens inside `job_entry`, BEFORE `resolve_job_model()`** (the call at the entry builder), not after the entry is built. An explicit `model:` pin already wins in `resolve_job_model` (explicit-model-first), so no extra guard is needed for that property — stated, and asserted by a selftest anyway.
- **The ascending ladder is new code:** `TIER_RAISE = {"light": "standard", "standard": "deep"}` — never an index into `compound-v-resolve-model.py`'s `TIERS`, which is ordered high-to-low.
- **The subprocess has a real timeout.** `_run()` has none; the recall-check call uses `subprocess.run(..., timeout=30)` with `TimeoutExpired` → `unavailable`, so a hung engine can never block emit.
- **Cost, measured, not assumed.** One `recall-check` walk over today's 150+ run directories takes what `time` says at emit (recorded in the emit summary as `recall_check_ms` per job); the run's review compares it with the emit's total. If it grows past a second per job, the follow-up is one walk per emit with per-job matching in Python — not this release.
- **Which review job gets the re-check clause:** every `type: review` job in the manifest (the emitter enforces no other mapping; today there is exactly one).
- Python 3.9 floor: no `match`/`case`, no `isinstance(x, A | B)`; `X | Y` only in annotations (the file's `from __future__ import annotations` stays). Stdlib only; the engine is a subprocess, never an import.
