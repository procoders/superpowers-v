# v3.4.6 — two triage/test-scoping defects from stage 5a (findings 99 + 102) — design

**Probe.** A request naming `scripts/compound-v-memory.py` (66,677 B, not sensitive, broad glob `scripts/**`, fan_out 1) sized FULL with
no T3 handoff; the same shape on three smaller scripts returned `needs_t3` (demotion). Cause: `_classify_paths` reads at most
`MAX_FILE_READ_BYTES` (65,536) and flags `content_scan_incomplete` for a longer file; the scorer treats the flag as impact-raising, which
vetoes `t1_from_broad_glob`. But `**/*.py` and `**/*.sh` are in the taxonomy's `content_scan_exclude` — the scan the flag doubts would
not have run at all.

**Decision.** In `scripts/compound-v-localize.py::_classify_paths`, a path for which `taxonomy.content_scan_excluded(path)` is true is
neither read for content nor flagged incomplete (its PATH rows and `sensitive_path` still apply, as §A5 already says for the content
patterns). The over-cap flag stays for every non-excluded file. Selftest: an oversized `.py` under a taxonomy that excludes `**/*.py`
→ `exact`, no `content_scan_incomplete`; the same file with no exclusion → the flag; an oversized `.md` (not excluded) → the flag.
End-to-end: `compound-v-preeval.py triage` on "small edit to <that big excluded script>" returns `needs_t3` (demotion), not FULL.

**Files.** `scripts/compound-v-localize.py` (+ selftest), `CHANGELOG.md`. Run it through the SCOPED path (the hook should size it
SCOPED after T3): the first SCOPED-tier dogfood of a `scripts/` file.

## Part 2 — the full-suite checker cap (finding 102)

**Probe.** 5a r2's docs-2 was refused: an unmapped lane path promoted its slice to `full_command`, and the whole suite (≈350 s on this
machine under load; 94 s an hour earlier) hit `TEST_TIMEOUT_S = 300` (compound-v-fastpath-run.py:122) → rc 124 → `blocked`, `failure_class`
None, the wave halted, the review never ran.

**Decision.** `test_contract.timeout_s` (optional, default 600, validated as a positive integer ≤ 3600) is the tier-1 checker's budget for
`full_command` and every impacted/floor command; `compound-v-fastpath-run.py` reads it from the contract the emitter hands the worker; a
checker that exits 124 is recorded with `failure_class: timeout` in the job_result (the retry policy's existing class) and the receipt note
says `timeout after N s`. Every external worker's `tc_validate` accepts the new key. Selftests: contract with timeout_s → the runner's
budget; a sleeping checker → rc 124 + failure_class timeout; the validator refuses `timeout_s: 0` and non-integers.

**Files.** `scripts/compound-v-fastpath-run.py`, `scripts/compound-v-validate-manifest.py`, `scripts/compound-v-emit-workflow.py` (pass-through),
the five `scripts/compound-v-run-*-worker.sh` (`tc_validate`), `skills/compound-v/execution-manifest.md`, `schemas/job_result.schema.json` if
failure_class lacks `timeout`, `CHANGELOG.md`.

## Part 3 — bookkeeping paths are not blast radius (finding 105)

**Probe.** The r3 review job (direct mode, checkout root) reported 46 stale `docs/superpowers/execution/*/.run.lock` files and four old
`logs/*.events.jsonl` as changed paths; the gate exempts them from the lane check but the test-contract resolver counted each as an
unmapped changed path and promoted the slice to `full_command` — the same stopwatch that refused r2's docs job.

**Decision.** `resolve_test_commands` ignores, for the unmapped⇒`full_command` promotion only, every changed path under
`docs/superpowers/execution/**` and every gitignored path (a contract note records how many were ignored and why). The wave finalizer
deletes `<run>/.run.lock` when it retires `lane-map.json` at MERGED/BLOCKED, so finished runs stop leaving locks behind. The lane
check is unchanged.
