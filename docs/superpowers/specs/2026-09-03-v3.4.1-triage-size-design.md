# v3.4.1 — The size of a code change reaches the tier — design

Stage-2 of the post-3.4.0 verification program. The decisions below were taken by the maintainer on
2026-09-03 through four structured questions after an eight-request probe of the 3.4 scorer
(`scratchpad` probe, summarised in the CHANGELOG). The probe's finding, in one line: **any change under
`scripts/**` is FULL by taxonomy glob regardless of size, a README typo is FULL from content-pattern
noise, and free-text localization scans hundreds of files for common words.** A size decision that
cannot say "small" for code is not a size decision.

## The four decisions, verbatim (maintainer, 2026-09-03)

1. **T3 may demote to SCOPED.** When T1's bands come from a BROAD path glob and the path is not
   sensitive and no content override fired, run ONE light-tier classify even though T1 classified;
   `plumbing` or `user-facing-minor` with fan_out ≤ 2 → SCOPED. `user-facing-major`/`unknown` →
   unchanged (FULL). DIRECT for code stays unreachable.
2. **Localization searches paths and identifiers only.** Plain words are never searched. A named file
   that does not exist is `new_file`, not `ambiguous`.
3. **SCOPED+ for small edits on sensitive paths.** sensitive ∧ exact ∧ fan_out ≤ 2 ∧ T3 ∈
   {plumbing, user-facing-minor} → SCOPED with a mandatory deep review + a cross-model second opinion
   + the human accept. Otherwise sensitive → FULL as today. Never DIRECT.
4. **SCOPED runs only the tests in the change's scope, never the whole app.** An unmapped path runs the
   tests that REFERENCE the changed module (capped at ~5 suites beyond impacted + floor), else the
   floor only. FULL keeps today's rule; CI stays the full backstop.

Plus one finding from stage-2 preparation (finding 50): **T3 can be finished headlessly from the hook.**
A nested `claude -p --model sonnet --tools ""` answers a T3 prompt in ~5 s; the read-only Codex route
answers in ~8 s. The hook no longer has to degrade to a reminder on `needs_t3`.

## Global constraints

- Python 3.9 stdlib only; every hook fails open; hook input is never shell-interpolated; GNU
  `timeout` is absent on macOS — every external process runs under `compound-v-run-with-timeout.py`.
- Never Haiku. The light classify is Sonnet (Claude) or the resolved codex `light` model.
- The engine stays T3-agnostic and never calls a model; every model touch is in
  `compound-v-classify-request.py` or the hook.
- Fail-closed direction unchanged: any error, timeout or non-enum reply is `unknown` ⇒ FULL.
- No new tier token. `DECISION_TO_TIER` keeps three values; SCOPED+ is SCOPED plus a `flavor`.
- No fabricated metrics. `tests.selected_count` is a count of commands, never a saving.
- Existing selftests are rewritten in the same task that changes the behaviour they pinned.

## WS-A — the scorer (`compound-v-preeval.py`, `compound-v-taxonomy.py`, the record schema, this repo's taxonomy)

### A1. Breadth is a property of the glob, not of the repository

`match_path` already returns the matched rows. It additionally returns, per row, `broad: bool` —
true when the glob contains `**` or ends in `/*`. No file counting: breadth must not cost a repo scan
at every prompt, and a pattern that says "everything under here" is broad by construction.

### A2. The T3 demotion (decision 1)

In `score()`, after Layer A and after T1/T2 banding, a new signal `t1_from_broad_glob` is true when
EVERY T1 row that produced the bands is broad, no resolved path is sensitive, and
`_content_raises_impact(flags)` is false. When it is true and `fan_out ≤ 2`:

- with `t3_category is None` → return `needs_t3` exactly as today, plus `"t3_reason": "demotion"`
  (today's unbanded case carries `"t3_reason": "unbanded"`). The caller reads the reason for its log
  only; the re-entry is identical.
- with `t3_category ∈ {plumbing, user-facing-minor}` → the bands become `(medium, medium)`: difficulty
  from the T3 table raised to at least `medium` ("DIRECT for code stays unreachable"), impact capped
  at `medium`. The matrix then yields SCOPED. The record keeps the taxonomy's bands beside the
  decision as `t3_demotion: {"from": {"difficulty": "high", "impact": "high"}, "category": "plumbing"}`
  and `tiers_signalled` gains `T3`. No override fires; the demotion is override-free evidence.
- with `user-facing-major` or `unknown` → bands unchanged → FULL, and the record still carries
  `t3_demotion: {"from": …, "category": …, "applied": false}`.

Override #4 (semantic-vs-path disagreement) is NOT evaluated on the demotion path: the whole point is
that T1 said `high` from a broad glob and T3 says `plumbing`. It keeps firing on the existing path
where T1 came from a specific row.

### A3. SCOPED+ (decision 3)

Override #2 becomes conditional. When a resolved path is sensitive: if localization is `exact`,
`fan_out ≤ 2`, and the request is T3-classified `plumbing` or `user-facing-minor`, the verdict is
`SCOPED_PIPELINE` with `flavor: "scoped_plus"` and bands `(medium, medium)`; the record carries
`override_fired: null` and `t3_demotion` as in A2 with `"sensitive": true`. With `t3_category is None`
on that path → `needs_t3` with `t3_reason: "sensitive"`. Any other case → override #2 → FULL exactly as
today. `.pem/.key/.env` and `.github/**` paths are NEVER demoted (a hard list in the engine,
`NEVER_DEMOTE_GLOBS`): secrets and CI are not "small edits".

`build_record` writes `flavor` only when set. `triage_request` returns `flavor` beside `tier`.

### A4. Localization confidence `new_file` (decision 2, engine side)

`score()` accepts `confidence == "new_file"` as localized: T1 runs on the directory's pattern
(`match_path` is glob-based and needs no file), `tiers_signalled` gains `localization`, and Layer B's
DIRECT predicate still requires `exact` — a new file is never DIRECT. Override #1 keeps firing on
`failed`/`ambiguous` only.

### A5. Content patterns do not apply to prose (the README finding)

The taxonomy gains an optional top-level `content_scan_exclude: [glob, …]`. `classify()` skips
content matching for a path that matches one of them (path rows still apply). Default empty, so every
other repository's behaviour is unchanged. This repository's taxonomy sets `["**/*.md"]`.
`compound-v-validate-taxonomy.py` validates the key as a list of globs.

### A6. This repository's taxonomy: the enforcement chain is sensitive

`sensitive_path_list` gains the enforcement files: `scripts/compound-v-scope-check.py`,
`scripts/compound-v-integration-gate.py`, `scripts/compound-v-validate-manifest.py`,
`scripts/compound-v-emit-workflow.py`, `scripts/compound-v-emit-preflight.py`,
`scripts/compound-v-preeval.py`, `scripts/compound-v-lane-guard*`, `hooks/**` (already). A small edit
there is SCOPED+; a small edit to any other script is SCOPED via A2; `scorecard.py` is the example.

### A7. The record schema

`localization.confidence` enum gains `new_file`; optional `flavor: {"enum": ["scoped_plus"]}` with a
conditional: `flavor` present ⇒ `decision == SCOPED_PIPELINE`; optional `t3_demotion` object
`{from:{difficulty,impact}, category, applied, sensitive?}`; optional `t3_reason`. `tiers_signalled`
unchanged.

## WS-B — the localizer (`compound-v-localize.py`) (decision 2)

`extract_query_tokens` keeps only identifier-shaped candidates: path-like (contains `/` or ends in a
known source/doc extension), backticked or quoted spans, `snake_case` (contains `_`), `CamelCase`
(an inner capital), dotted names (`a.b`), CSS-ish selectors as today. Plain words are dropped, and the
stopword list is no longer the only filter. No token → `failed` at once (no repo scan). A path-like
token naming a file that does not exist, whose parent directory exists inside the repo →
`{"resolved_paths": [that path], "fan_out": 1, "flags": ["new_file"], "confidence": "new_file"}`.
The eight probe requests become selftest fixtures with expected `(confidence, paths)`.

### WS-B amendments (stage-2 record, 2026-09-03)

The stage-2 request itself exposed two localizer defects. (1) A literal path followed by sentence
punctuation (`hooks/triage-prompt-nudge.sh.`) is not resolved: the strip set lacks `.` — strip a
TRAILING period (never an inner one) and `?`/`!`. (2) A literal path whose file exceeds
`MAX_FILE_READ_BYTES` turns the whole localization `ambiguous`, so every request naming a large
script is FULL by override #1 regardless of size. A literal path is `exact` by name; an incomplete
content scan adds the flag `content_scan_incomplete`, which the scorer treats as impact-raising
(`_IMPACT_RAISING_FLAGS`) — fail-closed on impact, not on localization.

## WS-C — the tests a SCOPED job owes (`compound-v-fastpath-run.py`) (decision 4)

`resolve_test_commands(contract, scope, …, tier=None, referencing=None)`: for `scope == "impacted"`,
an unmapped path resolves to `full_command` ONLY when `tier` is FULL or absent. For SCOPED and DIRECT
it resolves to `referencing` — the list the caller computed with the new
`referencing_tests(repo, changed_paths, cap=5)`: files under the repository's test directories
(`tests/`, `test/`, `spec/`, `__tests__/`, `*_test.*`, `test_*.*`, `*.spec.*`) whose text mentions the
changed path's basename or its module name (basename without extension), language-agnostic, bounded
read, sorted, capped at 5 beyond the impacted set; each becomes the contract's `impacted_map`-style
runner for that suite when one exists (`bash <file>` for `.sh`, `python3 <file>` for `.py`) else the
file is reported and not run. None found → the floor only, with a note `unmapped: referencing tests
found none — floor only at tier SCOPED`. `slice.scope` is labelled `impacted+referencing` when the
heuristic contributed, and `slice.selected_count` is the command count. `resolve_from_manifest`
passes the manifest's `triage.tier` and computes `referencing` from the worktree. `full` stays for
FULL. The e2e tests gain one case per branch. `execution-manifest.md` and `spec-reviewer.md` §3.3 say
what a SCOPED job owes.

## WS-D — the hook finishes T3 (`triage-prompt-nudge.sh`, `compound-v-classify-request.py`, `/v:triage`)

`compound-v-classify-request.py --classify-headless --request … --path … [--cwd] [--timeout 30]`:
runs `claude -p --model <resolved claude light model> --tools "" --output-format text <prompt>` under
the supervisor with stdin closed (NEVER `--bare`: it loses the login), parses the enum; on any failure
tries the codex route when `codex` is on PATH; else `unknown`. Output JSON `{category, backend,
timed_out, exit_code, model}` as the codex mode already prints. Never Haiku: the model is resolved
through `compound-v-resolve-model.py --backend claude --tier light`.

The hook, on `needs_t3`: runs `--classify-headless` bounded (30 s + 3 s grace, inside its own budget),
then re-invokes the triage subcommand with `--t3-category <enum>` and continues as if T1 had banded.
On `unknown` it re-invokes with `--t3-category unknown` (FULL, recorded) rather than degrading to the
reminder; the reminder remains only for engine failure. The tier text gains a SCOPED+ line: "SCOPED+
— a small edit on a sensitive path: offer it; on acceptance /v:orchestrate with `triage.flavor:
scoped_plus` (deep review + cross-model second opinion are mandatory)". `tests/test-native-points.sh`
drives the hook with a fake `claude` on PATH that answers the enum, and asserts: demotion → SCOPED
record; `unknown` → FULL record; a hanging fake → the reminder within budget.

`/v:triage` documents the headless route as the default and the Task route as the fallback.

## WS-E — the manifest, the validator and the dispatch tail (decision 3, mechanical half)

`triage.flavor: scoped_plus` is an allowed manifest key. Under `--require-triage`, a manifest with it
must carry a `type: review` job with `tier: deep` and `backend: claude` (else a violation names the
rule). A new `--require-cross-model-receipt <path>` (passed by `/v:dispatch` step 8 for `scoped_plus`
only) verifies the receipt file: valid against `schemas/plan-review.schema.json` plus `run_id`,
`pre_eval_id` and `diff_digest` (`sha256:` over the wave's sealed patch bytes) equal to the run's.
`/v:dispatch` step 8: for `scoped_plus`, run `compound-v-codex-review.sh --plan-file <sealed patch>
--context-file <spec>` and write `receipts/cross-model.json` with the three binding fields before the
review gate; step 9 no longer writes `phase: MERGED` by hand (the finalizer does since stage 1 — the
step appends the terminal `actual` and hands off). `/v:orchestrate` copies `flavor` from the record.
`phase-preeval.md`, `cross-model-review.md` (SCOPED+ row: **yes, mandatory**) and `SKILL.md` Stage −1
say all of it.

Every script keeps a green `--selftest`; `tests/test-native-points.sh`, `tests/test-triage-landing.sh`,
`tests/v2.9-e2e` green; CI green. The feature is verified through its own path: after the merge, the
hook is driven with the probe's eight requests and the stage-2 request (a small `scorecard.py` edit)
must come back SCOPED; a small `scope-check.py` edit SCOPED+; a `.env` edit FULL; a README typo DIRECT.
