# Compound V 3.0 — proportionate triage, scoped tests, native-Workflow orchestration

**Status:** design r2, revised after the three Phase-1 pre-flights. Supersedes r1 wholesale.

**Inputs:** [recon](../recon/2026-09-01-v3.0-triage-tests-orchestration.md) · [1A archaeology](../preflight/2026-09-01-v3.0-1a-archaeology.md) · [1B domain](../preflight/2026-09-01-v3.0-1b-domain.md) · [1C runtime contracts](../preflight/2026-09-01-v3.0-1c-docs.md)

## Problem

Three defects, confirmed against this repository, none of them the one we assumed.

**The sizing engine has no caller.** 7,883 lines of deterministic, model-free scoring across six scripts, and `grep -rln "compound-v-preeval" commands/ agents/ hooks/` returns nothing. `docs/superpowers/pre-eval/` has never existed in git history. No `state.json` carries `pre_eval_id`. The logic is sound; it is never consulted.

**Small work is not over-processed — it escapes entirely.** All 10 recorded runs served releases of ≥788 changed lines. All 10 releases under 200 lines ran with no manifest and no run directory. The measured failure is an unrecorded bypass, not excess ceremony.

**Nothing scopes tests, and 100% of real jobs ran without a mechanical scope gate.** The manifest has no test field; `agents/spec-reviewer.md:138` demands the whole suite unconditionally. 73 of 73 recorded jobs ran `backend: claude` — the one backend where the scope gate is prose the dispatcher must remember to type.

**Evidence limit, stated plainly.** The maintainer's "~20,000 tests for a one-word change" was not reproduced by any lane: no downstream repository, CI config or recorded measurement in this repo exhibits it. **Feature B's defaults are therefore chosen on principle, not on measurement.** They must be re-derived against a real instance before anyone claims a measured improvement.

## Goals

1. A three-tier triage decision that is impossible to skip on the dispatch path and recorded everywhere else.
2. Tests proportionate to the change, bought with a floor and with evaluation, not with an argument.
3. Dispatch moved onto Claude Code's native Workflow runtime, which makes the scope gate mechanical on the claude path for the first time.

## Anti-goals

- No coverage instrumentation and no inferred file→test mapping. Mappings are declared, or the tier runs everything.
- No new scoring logic. Only invocation is missing.
- Engine A is not removed.
- No auto-arming of any scheduler. The permission-bypass flag is never emitted.
- The unattributed "$47,000" native-workflow cost figure is never cited.

## Scope change: v2.18 is absorbed

Feature C as specified in r1 **already exists** on the unmerged `v2.18-autonomy` branch: `_enforcement_rule` in `hooks/epic-goal-stop.sh` already implements source-change detection, run-record exemption, an `enforcement.*` config key defaulting OFF, a once-per-session marker, `|| true` registration and an unconditional exit-0 EXIT trap.

Two `Stop` registrations compose at the harness level (all run; any block wins) but **not semantically** — v2.18 deliberately put both of its rules in one script because two blocking rules on one event give undefined ordering, and its test asserts exactly one response and one state update.

Therefore `v2.18-autonomy` merges into this branch and ships as part of 3.0. Feature C becomes a rule added to the existing script, not a second hook. v2.18's own unfinished work (job p5: command wiring for `/v:epic`, `/v:status`, `/v:init`, `epic-mode.md`) is in scope here.

## Feature A — Triage that cannot be skipped

### A1. A third tier

`compound-v-preeval.py` gains `DECISION_SCOPED`. The band matrix stops collapsing 8 of 9 cells:

| | impact low | impact medium | impact high |
|---|---|---|---|
| **difficulty low** | DIRECT | SCOPED | FULL |
| **difficulty medium** | SCOPED | SCOPED | FULL |
| **difficulty high** | FULL | FULL | FULL |

Unknown bands stay fail-closed to FULL. `DIRECT` additionally keeps the existing Layer-B predicates.

**The matrix is computed inside the engine, never post-hoc from the verdict dict.** Override #4 (`compound-v-preeval.py:424`) returns genuine `low`/`low` bands alongside `override_fired=4`; a post-hoc reader would grant DIRECT — and with it auto-route — to a record whose own audit trail says a hard override fired. **Any fired override forces FULL.**

Tier meanings end to end:

- **DIRECT** — implement in place, run the floor, commit on the current branch. No manifest, no run directory, no worktree, no PR, no reviewer dispatch. A triage record is still written and committed.
- **SCOPED** — manifest, run directory, scope gate, floor, and a single combined SPEC+QUALITY review pass. Recon and the three pre-flights are skipped.
- **FULL** — the current pipeline, unchanged.

### A2. The mechanical consumer

`compound-v-validate-manifest.py` gains a required top-level block:

```yaml
triage:
  tier: SCOPED
  pre_eval_id: <id>
  taxonomy_digest: <sha256 of the taxonomy bytes>
  decided_at: <ISO-8601>
```

A manifest without a well-formed `triage` block fails validation, and `/v:dispatch` already refuses to run on a validator FAIL. A `taxonomy_digest` that does not match the taxonomy on disk also fails, so a record cannot outlive the rules that produced it.

**Rollout.** Requiring it turns CI red on 11 committed files (10 run manifests plus `examples/manifest.example.yaml`), and `compound-v-fastpath-materialize.py:build_manifest` emits no `triage` and self-validates in-code, so it breaks at runtime and in its own selftest. Two changes, in this order:

1. `build_manifest` emits a `triage` block. Its selftest is updated in the same commit.
2. The historical 11 are handled by the **allowlist precedent this repo already set** in `.github/workflows/validate.yml:139-151` — listed by id, never back-filled, because "a reconstructed audit trail is the fabricated-evidence pattern, not a repair". The validator gains `--require-triage` (default on for `--mode pre-dispatch`, off for the CI historical sweep).

### A3. The entry point

New `/v:triage <request>`: resolve localization, classify, score, write and **commit** the record to `docs/superpowers/pre-eval/<id>.json`, print the tier with the predicates that decided it. This is the caller the engine has never had. `/v:orchestrate` invokes it when no record exists.

### A4. The narrow auto-route class

Iron Invariant #4 is amended, not deleted:

> **The score OFFERS by default. It auto-routes only inside the DIRECT auto-route class, whose membership is decided by mechanically checkable predicates and never by model judgement. Every other tier still requires a human offer and acceptance.**

Membership requires **all** of the following. The pre-flights killed the shape-only version of this list: every shipped unattended-landing system (Renovate auto-merge, SRE canarying, ITIL standard change) gates on **checks having passed** and on **demonstrated history**, not on how a change looks.

1. Tier is `DIRECT` and no override fired.
2. Exactly one resolved path, and it is a literal.
3. Taxonomy present and digest-matched — never on a fail-closed `unknown` band.
4. Path matches the taxonomy's `auto_route_allow` set.
5. Path matches **no** entry in the taxonomy's `sensitive` set. The set is **repo-local and taxonomy-driven**, not hardcoded: what is dangerous differs per project. This repository's taxonomy seeds it with auth, security, payments, PII, accessibility, CI workflows, `hooks/`, **and `skills/**/*.md`, `agents/*.md`, `commands/*.md`** — because here those files *are* the enforcement layer, so "docs-only" is a self-modification hole rather than a safe class. A downstream project whose markdown is ordinary documentation simply does not list it, and `/v:onboard draft-taxonomy` proposes the set from what the repo actually contains.
6. No test file touched.
7. **The floor has been run and passed.** A DIRECT change may not commit having run nothing. This ordering is the predicate r1 was missing — A4 and B2 were separate features with nothing sequencing them.
8. **Full post-diff re-validation.** After the edit, predicates 2, 5, 6 and the line budget (`auto_route_max_lines`, default 20) are **all** re-checked against `git diff --numstat` and `--name-only`. r1 re-checked only the line count, which left three of the four TOCTOU windows open. Any failure demotes to SCOPED before commit, and the demotion is recorded.
9. **Miscalibration circuit breaker.** Auto-route is armed from the first decision — a warm-up gate was considered and **rejected by the maintainer**, on the grounds that it would make the feature's whole point unavailable for weeks. The safety property is therefore reactive rather than preventive: `compound-v-triage-outcomes.py` tracks the rolling demotion rate over the last `auto_route_window` (default 20) DIRECT decisions, and when it exceeds `auto_route_max_demotion_rate` (default 0.25) auto-route **disarms itself** and reverts to offering until a human re-arms it. This blocks nothing on day one and reacts once the classifier has demonstrably mis-sized work.

   **The residual risk, stated plainly:** with no warm-up, the first miscalibrated DIRECT change commits before any evidence exists that the classifier is calibrated in this repository. Predicates 7 (floor passed) and 8 (full post-diff re-validation) are the only things standing between a mis-sized change and a commit, and the breaker can only fire *after* the first bad commit lands. The commit is on a branch and revertable; nothing is pushed automatically.

### A5. Recording the bypass

`docs/superpowers/memory/triage-outcomes.jsonl` starts receiving `predicted` on every decision and `actual` on every completed run — the stream `compound-v-triage-outcomes.py` was written for and has never had a data point.

`compound-v-triage-outcomes.py:733` currently collapses anything that is not fast-path into the `fullpipeline` cohort. SCOPED must become its own cohort, or the fast-path precision figure `/v:status` renders is silently corrupted by the new tier.

### A6. The taxonomy

`.claude/compound-v-impact-taxonomy.yaml` does not exist here, and absent taxonomy is an unconditional fail-closed FULL — so the engine cannot emit a non-`unknown` band in its own repository. `/v:init` does **not** seed it; `/v:onboard draft-taxonomy` does (`compound-v-onboard.py:535,744`), self-validating and behind a human gate. 3.0 runs that command rather than hand-authoring YAML.

## Feature B — Scoped tests, bought with a floor and an evaluation

### B1. Reuse, do not rebuild

`run_test_floor` (`compound-v-fastpath-run.py:308-343`) **already is** the floor: merge-blocking, records the command and its exit code, fail-closed on an empty command. It has never had a producer for `--test-cmd` (`"$CFG_TESTS"` is an unbound placeholder), and it returns at `:343` before `changed_paths` is computed, so it is not diff-proportionate. Feature B supplies the producer and moves the return below the diff computation. It does not introduce a second floor.

### B2. The contract

```yaml
test_contract:
  floor_command: "…"        # always runs, every tier
  full_command: "…"
  impacted_map:
    - when: "scripts/compound-v-*.py"
      run:  "python3 {path} --selftest"
```

```yaml
jobs:
  - id: task-1
    test_scope: impacted     # full | impacted | floor_only
```

`impacted_map` is declarative. A changed path matching no `when` glob resolves to `full_command` — an unmapped file is unknown blast radius, never "nothing to run". `floor_only` means *only the floor*, never nothing.

**The floor is three sets, not one.** Regression-test-selection practice (Azure TIA and the RTS literature) always runs impacted ∪ **previously failing** ∪ **newly added**. r1 had only the first. Previously-failing comes from the last recorded run's results; newly-added from `git diff --name-only --diff-filter=A`.

**Known miss rate, stated with the claim.** Call-graph-derived selection is measured at 0.2% (class-level) to 10.6% (method-level) unsafe per revision, from reflection and library exclusion. A hand-written glob map carries strictly less information than a call graph, so **0.2% is an optimistic floor, not an expectation.** This is why the floor and the CI backstop are not optional.

### B3. Transport and reporting — the gap r1 missed

`schemas/job_result.schema.json:7` is `additionalProperties: false` and has no field for a test command or its exit code (`exit_code` is the worker process's). And there is **no transport**: every worker takes `--prompt-file`, and the `job_spec` contract has no test field — so `test_scope` would reach an external worker only as prose in a prompt, which is exactly the failure A2 exists to prevent.

Both are in scope:
- `job_result.schema.json` gains `tests: {command, exit_code, scope, selected_count}`.
- `job_spec` gains a `test_contract` slice, and each worker script passes it through as a real argument, not as prompt text.

### B4. The review gate

`agents/spec-reviewer.md:138` becomes tier-aware: the floor must pass unconditionally; `full_command` is required at FULL and for any job carrying an unmapped path; the declared impacted set suffices at SCOPED and DIRECT. **A job reporting no test command at all is a FAIL**, not a pass — the reviewer reads `tests.command` and `tests.exit_code` from the job result, which is why B3 is a prerequisite rather than a nicety.

### B5. The CI backstop, made real

"The full suite still runs in CI before merge" is fragile as stated: GitHub reports a conditionally-skipped job as `Success`, so a path filter can turn a required check green without running it. The backstop must be a job that always runs and is required, dispatching internally.

Separately, and independently of this feature: **none of the three files under `tests/` is executed by CI on this branch** — the only sweep is `for s in scripts/*.py`. Any test written for Feature C would land dead on arrival. That is the v2.14.1 false-green shape recurring and is fixed here.

### B6. The ADR

`docs/superpowers/adr/0003-scoped-tests-with-a-floor.md` supersedes the v2.17 rejection at `2026-07-25-v2.17-cochange-and-evidence-packing-design.md:308-310`. It must state the original rationale (v2.14.1: 25 of 29 selftests silently never running), name the three-set floor, the CI backstop and the measured RTS miss rate as the mitigations, and record what would falsify it.

## Feature C — The bypass rule, inside the existing hook

A rule added to `hooks/epic-goal-stop.sh` (absorbed from v2.18), not a second registration.

- Fires when the turn is ending and tracked, non-exempt files changed with no triage record for the session.
- **`session_id` is on the `Stop` stdin payload** — that is the mechanism r1 said it lacked.
- Exempt: an existing triage record for the session, membership in the DIRECT auto-route class, or a session opt-out.
- OFF by default under `enforcement.triage_gate`.

Mechanics corrected by the pre-flights:

- **`stop_hook_active` is a consecutive-block counter, not a session flag**, and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` (default 8) makes Claude Code override the hook and end the turn anyway. The rule blocks at most once per session on its own marker; it must not rely on the harness counter.
- **Exit 2 blocks.** Other non-zero exits are non-blocking errors. The `|| true` registration is nonetheless load-bearing, and now for a precise reason: **bash exits 2 on a parse error** — probed locally (`stray fi` → 2, unterminated quote → 2, unclosed function → 2) — which is exactly the blocking code, and no in-script trap can run when the script fails to parse. The `$comment_stop` describing this contract lives on the v2.18 branch, not on main; absorbing v2.18 brings it.
- **All `Stop` hooks share a 1.5s budget.** A `git status` that times out is a *silent* no-op — the dead-guard shape again. The rule must use a bounded, cheap check and must record when it could not complete, rather than passing silently.

## Feature D — Dispatch on the native Workflow runtime

**Naming:** this is **Engine C**, the name used in nine shipped locations. "Engine B" is already taken by the rejected `claude -p` shell-out.

**This reverses a load-bearing guarantee and is treated as one.** `skills/compound-v/workflows-accelerator.md:60-71` states that Engine C "only changes how jobs fan out, never the enforcement or recovery layer" and that "`state.json` resume stays in Engine A". Feature D moves the scope gate and the state write *into* the workflow. `docs/superpowers/adr/0004-workflow-as-the-dispatch-engine.md` records the reversal, its rationale (the gate is currently prose on the only path anyone uses) and its falsification condition.

### D1. The gate becomes a stage

The script has no filesystem or shell access, but **agents it spawns do have full tools including Bash** — verified four independent ways by 1C, and this is what the design rests on.

```js
await pipeline(jobs,
  j        => agent(implementPrompt(j), {phase: 'Implement', schema: JOB_RESULT}),
  (r, j)   => agent(gatePrompt(j, r),   {phase: 'Gate',      schema: GATE_VERDICT}),
  (v, j)   => agent(recordPrompt(j, v), {phase: 'Record',    schema: RECORD_ACK}))
```

The variadic form and the `(prevResult, originalItem, index)` stage signature are confirmed against the tool contract. Three properties are mandatory, each closing a defect the pre-flights found:

- **The Gate stage must be total.** A stage that *throws* drops its item to `null` and **skips every remaining stage** — so a Gate exception would mean no `state.json` written, no record committed, and a job silently becoming `null`, precisely on the jobs that went wrong. That is the v2.6.4 audit-trail loss reappearing structurally. The Gate catches everything and returns a verdict; it never throws.
- **`null` is FAIL, never pass.** `agent()` returns `null` when the user skips it or it dies on a terminal API error. A gate that treats `null` as absence of violations is unreachable exactly when the worker died.
- **The Record stage must be idempotent.** On relaunch, every agent that started after a failed one re-runs, including completed ones.

### D2. The generator

`scripts/compound-v-emit-workflow.py` turns `manifest.yaml` into the script: `depends_on` → topological staging, `max_parallel` → chunking, backend/tier/effort → `agent()` options. Constraints:

- The runtime makes `Date.now()`, `Math.random()` and no-arg `new Date()` **throw**, and `import()` fails before the run starts. The generator emits none of them; timestamps are passed in via `args`.
- The tool's own guidance is "pass the script inline — do not Write it to a file first", which is the opposite of committing the artifact. `scriptPath` takes documented precedence, so the dispatch prose must force the `scriptPath` form — otherwise the committed artifact is not what ran.
- `CLAUDE_CODE_WORKFLOWS` restricts a session to named workflows and refuses `script`/`scriptPath` outright. The dispatcher probes for it and falls back to Engine A.

### D3. Engine selection

**The r1 justification was wrong and is withdrawn.** Workflows *are* available in `claude -p` and the Agent SDK; only the `ultracode` keyword is route-restricted. The selection rests instead on three operational facts:

- A subagent cannot launch one — probed live under both the public name `Workflow` and the internal `RunWorkflow`. Observed, not contracted, so the probe is re-run at dispatch rather than assumed.
- Resume is same-session-only, and a mid-fan-out failure re-runs completed agents. Cross-session recovery therefore stays with `state.json` and `/v:resume` in Engine A.
- Headless launch requires an allow rule, auto mode or a `PreToolUse` hook. Under `bypassPermissions` a headless run could launch a workflow with **no prompt and no spend cap**, which this project will not ship as a default.

| Context | Engine |
|---|---|
| Top-level interactive session, probe succeeds, user opted in | **C** — native Workflow |
| Subagent, `/v:epic`, launchd shim, or any headless route | **A** |

Engine C is the inner loop for one dispatch; it is never the system of record. The cross-vendor arbiter is unaffected — Codex and Gemini workers are spawned processes, and a workflow `agent()` reaches them through Bash.

### D4. Version floor

Local install is 2.1.238. Floor: **Claude Code ≥ 2.1.219**. The `/workflow-authoring` skill requires 2.1.248 and is unavailable on the development machine, so nothing may depend on it.

## Acceptance criteria

1. `compound-v-preeval.py` emits three decision values; a selftest covers all 9 matrix cells, the unknown/fail-closed case, and that **any fired override forces FULL** even when the bands read `low`/`low`.
2. `compound-v-validate-manifest.py` FAILS on a missing or malformed `triage` block and on a `taxonomy_digest` mismatch; `--require-triage` defaults on for `--mode pre-dispatch`. A planted violation is shown to fail.
3. `compound-v-fastpath-materialize.py` emits a `triage` block and its own selftest passes; the 11 historical files are allowlisted by id, never back-filled.
4. `/v:triage` exists, writes and commits a record, and `/v:orchestrate` obtains one when absent.
5. The auto-route class implements all nine predicates of A4, including floor-passed and full post-diff re-validation of predicates 2/5/6/line-budget. A test proves a change that outgrows the class is demoted and the demotion recorded. The `sensitive` set is read from the taxonomy, never hardcoded, and this repo's taxonomy lists `skills|agents|commands` markdown. A selftest proves the circuit breaker disarms auto-route once the rolling demotion rate exceeds the threshold, and that it never delays the first decision.
6. `phase-preeval.md`, `SKILL.md`, `rationalization-table.md` and `routing-policy.md` all carry the amended Iron Invariant #4; no file still asserts the unamended form.
7. `triage-outcomes.jsonl` receives `predicted` and `actual` events, and SCOPED is its own cohort in `compound-v-triage-outcomes.py`.
8. `.claude/compound-v-impact-taxonomy.yaml` exists here, produced by `/v:onboard draft-taxonomy`, and a live `--score-only` probe returns a non-`unknown` band.
9. `run_test_floor` gains a producer, returns below the `changed_paths` computation, and runs impacted ∪ previously-failing ∪ newly-added. No second floor is introduced.
10. The manifest accepts `test_contract` and per-job `test_scope`; an unmapped path resolves to `full_command`; `floor_only` never resolves to an empty command.
11. `job_result.schema.json` carries `tests: {command, exit_code, scope, selected_count}`, and every worker receives the test contract as a real argument, not as prompt prose.
12. `spec-reviewer.md` requires the floor unconditionally, requires `full_command` at FULL and for unmapped paths, and FAILS a job reporting no test command.
13. ADR 0003 (scoped tests) and ADR 0004 (Workflow as dispatch engine) exist, each naming the decision it supersedes and its own falsification condition.
14. The triage rule lives inside `epic-goal-stop.sh` as a second rule, is OFF by default, blocks at most once per session on its own marker, uses a bounded check that records incompletion rather than passing silently, and has a test proving the raw script exits 2 when it fails to parse while the `|| true` registration still fails open.
15. `compound-v-emit-workflow.py` emits implement → gate → record; the Gate stage never throws and treats `null` as FAIL; the Record stage is idempotent; the emitted script contains no `Date.now`, `Math.random`, bare `new Date()` or `import()`.
16. `/v:dispatch` selects Engine A in subagent, `/v:epic`, shim and headless contexts and Engine C only in a top-level session where the live probe succeeds and `CLAUDE_CODE_WORKFLOWS` is unset; the naming "Engine C" is used throughout.
17. CI executes the files under `tests/`, and the full-suite backstop is a job that always runs rather than a conditionally-skipped one that reports Success.
18. v2.18's job p5 (command wiring for `/v:epic`, `/v:status`, `/v:init`, `epic-mode.md`) is complete, since v2.18 ships inside 3.0.
19. Every new script carries `--selftest` and is discovered by the existing CI sweep; every new guard is demonstrated to fail on a planted violation before it is trusted.
20. README, CHANGELOG and `AGENTS.md` state the Claude Code ≥ 2.1.219 floor and that Feature B's defaults are principle-derived, the "20,000 tests" observation being unreproduced.

## Decisions taken (brainstorm, 2026-09-01)

1. **No warm-up for auto-route.** Armed from the first decision; safety is the reactive circuit breaker in A4.9, not a history precondition. The residual risk is recorded there in the maintainer's hearing rather than mitigated away.
2. **The `sensitive` set is repo-local and taxonomy-driven.** The markdown exclusion is this repository's entry, not a global rule.
3. **`v2.18-autonomy` is absorbed whole**, including its unfinished command wiring (job p5). One Stop script, one release.
4. **Build with the caveat rather than measuring first.** The "~20,000 tests" observation is unreproduced and every cost-governance source found was vendor marketing, so Feature B's defaults are principle-derived and no speed or cost claim ships with this release. AC-20 enforces the wording; the pipeline records selected-test counts and durations (AC-11) so the next release can speak from our own data.
