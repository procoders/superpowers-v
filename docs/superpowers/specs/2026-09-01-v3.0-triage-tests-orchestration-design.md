# Compound V 3.0 — proportionate triage, scoped tests, native-Workflow orchestration

**Status:** design, approved in brainstorm 2026-09-01. Recon: [`docs/superpowers/recon/2026-09-01-v3.0-triage-tests-orchestration.md`](../recon/2026-09-01-v3.0-triage-tests-orchestration.md).

## Problem

Three defects, all confirmed against this repository at HEAD `d9286c7`, and none of them the one we assumed.

**The sizing engine has no caller.** `scripts/compound-v-preeval.py` and its five siblings are 7,883 lines of deterministic, model-free scoring — and `grep -rln "compound-v-preeval" commands/ agents/ hooks/` returns nothing. `docs/superpowers/pre-eval/` has never existed in git history. No `state.json` carries `pre_eval_id`. The scoring logic is sound; it is simply never consulted.

**Small work is not over-processed — it escapes entirely.** Every one of the 10 recorded runs served a release of ≥788 changed lines. Every one of the 10 releases under 200 lines ran with **no** manifest and **no** run directory. The measured failure is an unrecorded, ungoverned bypass, not excess ceremony. Any design justified by "the pipeline is too heavy for small changes" would optimize a path with zero historical uses.

**Nothing scopes tests to a change, and 100% of real jobs ran without a mechanical scope gate.** The manifest schema has no test field at any level; `agents/spec-reviewer.md:138` requires the whole suite unconditionally. Meanwhile 73 of 73 recorded jobs ran `backend: claude` — the one backend where the scope gate is prose the dispatcher must remember to type, rather than a line inside a worker script.

The maintainer locates the day-to-day pain in **downstream working projects and in plain Claude Code sessions** — the second being a context where Compound V's dispatch never runs. A manifest field alone cannot reach it.

## Goals

1. A three-tier triage decision that is **impossible to skip on the dispatch path** and **recorded** everywhere else.
2. Tests proportionate to the change, bought with a floor rather than with an argument.
3. Orchestration moved onto Claude Code's native `Workflow` runtime, which makes the scope gate mechanical on the claude path for the first time.

## Anti-goals

- No coverage analysis, no inferred file→test mapping. Mappings are **declared**, or the tier runs everything.
- No new scoring logic. The existing engine is correct; only its invocation is missing.
- Engine A (the current loop) is **not** removed. Headless, scheduled, subagent and `/v:epic` contexts cannot launch a Workflow and must keep working.
- No auto-arming of any scheduler. No emission of the permission-bypass flag, ever.
- The unattributed "$47,000" cost figure circulating about native workflows must never be cited in any artifact.

## Feature A — Triage that cannot be skipped

### A1. A third tier

`scripts/compound-v-preeval.py` gains `DECISION_SCOPED` alongside the existing `DECISION_FASTPATH` and `DECISION_FULL`. The 3×3 difficulty×impact band matrix stops collapsing 8 of 9 cells into FULL:

| | impact low | impact medium | impact high |
|---|---|---|---|
| **difficulty low** | DIRECT | SCOPED | FULL |
| **difficulty medium** | SCOPED | SCOPED | FULL |
| **difficulty high** | FULL | FULL | FULL |

`DIRECT` additionally keeps every existing Layer-B predicate (`fan_out <= threshold`, single literal path). Unknown bands stay fail-closed to FULL — absent taxonomy must never produce a cheap tier.

The three tiers mean, end to end:

- **DIRECT** — implement in place, run the floor plus the declared impacted tests, commit on the current branch. No manifest, no run directory, no worktree, no PR, no reviewer dispatch. A triage record is still written.
- **SCOPED** — a manifest and a run directory, the scope gate and the floor, and a **single combined** SPEC+QUALITY review pass. Recon and the three pre-flights are skipped. This is the tier that does not exist today.
- **FULL** — the current pipeline, unchanged.

### A2. The mechanical consumer

This is the load-bearing part. A tier that an agent may consult is worth nothing; the v2.19 lesson is that prose is not mechanism.

`scripts/compound-v-validate-manifest.py` gains a required top-level `triage` block:

```yaml
triage:
  tier: SCOPED              # DIRECT | SCOPED | FULL
  pre_eval_id: <id>         # the record under docs/superpowers/pre-eval/
  taxonomy_digest: <sha256> # content-addresses the taxonomy that produced the bands
  decided_at: <ISO-8601>
```

A manifest without a well-formed `triage` block **fails validation**, and `/v:dispatch` already refuses to run on a validator FAIL. Dispatch therefore becomes unreachable without a triage decision. The validator additionally rejects a `taxonomy_digest` that does not match the bytes of the taxonomy on disk, so a record cannot outlive the classification rules that produced it.

### A3. The entry point

New `/v:triage <request>` command: resolve localization, classify (T3 enum), score, write the record to `docs/superpowers/pre-eval/<id>.json`, **commit it**, and print the tier with the predicates that decided it. This is the caller the engine has never had.

`/v:orchestrate` calls it when no record exists rather than failing, so the normal path acquires a triage record without a separate step.

### A4. The narrow auto-route class

Iron Invariant #4 is **amended, not deleted**. Current text (`skills/compound-v/phase-preeval.md:20`): *"The score only OFFERS, never auto-routes."* New text:

> **The score OFFERS by default. It auto-routes only inside the DIRECT auto-route class, whose membership is decided by mechanically checkable predicates and never by model judgement. Every other tier still requires a human offer and acceptance.**

Membership requires **all** of the following, each computable from git plus the taxonomy:

1. Tier is `DIRECT`.
2. Exactly one resolved path, and that path is a literal (no glob).
3. The taxonomy is present and its digest matches — never on a fail-closed `unknown` band.
4. The path matches the taxonomy's `auto_route_allow` glob set.
5. The path matches **no** entry in the taxonomy's `sensitive` set. Seeded with auth, security, payments, PII, accessibility, CI workflows, and `hooks/` — the same exclusions the Sonnet carve-out already uses.
6. No test file is touched.
7. The realised diff is ≤ `auto_route_max_lines` (default 20). This is re-checked **after** the edit, from `git diff --numstat`; a change that outgrows the class is demoted to SCOPED before commit, and the demotion is recorded.

Predicate 7 is what keeps the class honest: eligibility is granted on an estimate and **confirmed against the real diff**, so a "one-word fix" that turns into 200 lines cannot ride the cheap tier.

### A5. Recording the bypass

`docs/superpowers/memory/triage-outcomes.jsonl` starts receiving events — the stream `compound-v-triage-outcomes.py` was written for and has never had a single data point. Every triage decision appends `predicted`; every completed run appends `actual`. This is what turns the currently invisible bypass into a measurable one.

## Feature B — Scoped tests, bought with a floor

### B1. The manifest contract

New top-level block, plus a per-job override:

```yaml
test_contract:
  floor_command: "python3 scripts/lint-frontmatter.py . && bash tests/run-guards.sh"
  full_command: "bash tests/run-all.sh"
  impacted_map:
    - when: "scripts/compound-v-*.py"
      run:  "python3 {path} --selftest"
    - when: "hooks/*.sh"
      run:  "bash tests/test-hooks.sh"
```

```yaml
jobs:
  - id: task-1
    test_scope: impacted      # full | impacted | floor_only
```

`impacted_map` is **declarative**. When a changed path matches no `when` glob, the job runs `full_command` — an unmapped file is treated as unknown blast radius, never as "nothing to run". There is no inference and no coverage instrumentation.

### B2. The floor

`floor_command` runs on **every** job at **every** tier, including DIRECT. It carries the integrity gates and linters — the checks whose absence caused the incident this reversal has to answer for. `test_scope: floor_only` means *only the floor*, never *nothing*.

The full suite still runs in CI before merge. Scoping changes what a worker runs **during** a job, never what guards the merge.

### B3. The review gate

`agents/spec-reviewer.md:138` currently reads "the composite must build/compile and the test suite must pass". It becomes tier-aware: the floor must pass unconditionally; `full_command` is required at FULL and at any tier whose job carries an unmapped path; the declared impacted set is sufficient at SCOPED and DIRECT. A job that silently ran *nothing* is a FAIL, not a pass — the reviewer must see a command and its exit code.

### B4. The ADR

`docs/superpowers/adr/0003-scoped-tests-with-a-floor.md` explicitly supersedes the v2.17 rejection at `2026-07-25-v2.17-cochange-and-evidence-packing-design.md:308-310`. It must state the original rationale (v2.14.1: 25 of 29 selftests silently never running in CI), name the floor and the CI backstop as the mitigations, and record what would falsify the decision. Without the ADR the old rationale stays discoverable and correct, and someone will rightly re-apply it.

## Feature C — The bypass gate, for sessions with no pipeline

Half the reported pain is in plain Claude Code sessions where Compound V's dispatch never runs. Nothing in Features A or B reaches them.

New `hooks/triage-stop.sh`, registered on `Stop`:

- Fires when the turn is ending and `git status --porcelain` shows modifications to **tracked, non-documentation** files.
- Passes silently when a triage record exists for the session, when the change is inside the DIRECT auto-route class, or when the user opted out for the session.
- Otherwise blocks the turn **once** with `{"decision":"block","reason":…}` naming `/v:triage` and the opt-out.

Constraints, all non-negotiable:

- **OFF by default**, enabled by `enforcement.triage_gate` in `.claude/compound-v.json`. A false positive here bricks a session, which is why the same caution was applied to the v2.18 enforcement hook.
- Blocks at most once per session. `stop_hook_active` is never cleared once set, so a hook that blocks unconditionally is a trap.
- Registered as `"…/triage-stop.sh" || true` with an unconditional `trap 'exit 0' EXIT` inside — the same two-part fail-open contract already documented in `hooks/hooks.json`, because a non-zero exit from a `Stop` hook *is* a block and a syntax error is fatal before any in-script trap runs.
- It composes with, and does not replace, the `Stop` hook on the unmerged `v2.18-autonomy` branch. Two registrations, each independently fail-open.

## Feature D — Orchestration on the native Workflow runtime

The maintainer chose Workflow **instead of** our loop, not merely under it. The recon's objection — that the scope gate cannot be interposed — is too pessimistic and is corrected here.

### D1. Why the gate survives

The workflow script has no filesystem or shell access, but **the agents it spawns have full tools**. The gate therefore moves from script logic into a pipeline stage:

```js
await pipeline(jobs,
  j => agent(implementPrompt(j), {phase: 'Implement', schema: JOB_RESULT}),
  (r, j) => agent(scopeGatePrompt(j), {phase: 'Gate', schema: GATE_VERDICT}),
  (v, j) => agent(recordPrompt(j), {phase: 'Record', schema: RECORD_ACK}))
```

The gate stage runs `scripts/compound-v-scope-check.py` and returns a git-derived verdict. A script cannot be persuaded to skip stage 2. This is **stronger** than today: on the claude path — 73 of 73 real jobs — the gate is currently a bash block in a markdown file that an agent under efficiency pressure can simply not run.

`state.json` is written and committed by the `Record` stage, which closes the defect the v2.19 CI gate now catches after the fact.

### D2. The generator

`scripts/compound-v-emit-workflow.py` turns `manifest.yaml` into a workflow script: `depends_on` becomes topological staging, `max_parallel` becomes chunking, and each job's backend, tier and effort become `agent()` options. The script is emitted into the run directory and committed, so the exact orchestration that ran is part of the audit trail.

### D3. Engine selection, and why Engine A stays

Three verified constraints decide this, none of them preferences:

- A **subagent cannot launch a Workflow**. `compound-v:parallel-dispatcher` is a subagent, so the seam moves up into the top-level session.
- Launch requires **explicit human opt-in** and is deliberately not honored from `-p`, SDK, scheduled or webhook routes.
- Resume is **same-session only**, and on relaunch every agent that started after a failed one re-runs, including completed ones.

So `/v:dispatch` probes and selects:

| Context | Engine |
|---|---|
| Top-level interactive session, Workflow available, user opted in | **B** — native Workflow |
| Subagent, headless `-p`, scheduled, `/v:epic`, launchd shim | **A** — the current loop |

Cross-session crash recovery stays in Engine A regardless: `state.json` plus `/v:resume` re-dispatches incomplete jobs. Engine B is the inner loop for one dispatch; it is never the system of record.

The cross-vendor arbiter is unaffected — Codex and Gemini workers are spawned processes, and a workflow `agent()` can invoke the same worker scripts through Bash.

## Acceptance criteria

Each is mechanically checkable, and each corresponds to a numbered section above.

1. `compound-v-preeval.py` emits three decision values, and the band matrix in A1 is reproduced by a selftest covering all 9 cells plus the unknown/fail-closed case.
2. `compound-v-validate-manifest.py` FAILS on a manifest with no `triage` block, on a malformed one, and on a `taxonomy_digest` that does not match the taxonomy bytes. A planted violation is shown to fail, not merely asserted to.
3. `/v:triage` exists, writes and commits a record under `docs/superpowers/pre-eval/`, and `/v:orchestrate` obtains a record when none exists.
4. The DIRECT auto-route class is implemented as the seven predicates in A4, with the post-edit line-count re-check demoting an outgrown change to SCOPED and recording the demotion.
5. `phase-preeval.md`, `SKILL.md`, `rationalization-table.md` and `routing-policy.md` all carry the amended Iron Invariant #4. No file still asserts the unamended "never auto-routes".
6. `triage-outcomes.jsonl` receives a `predicted` event per decision and an `actual` event per completed run.
7. The manifest schema accepts `test_contract` and per-job `test_scope`; a path matching no `when` glob resolves to `full_command`; `floor_only` never resolves to an empty command.
8. `spec-reviewer.md` requires the floor unconditionally, requires `full_command` at FULL and for unmapped paths, and FAILS a job that reports no test command at all.
9. ADR 0003 exists, names the v2.17 rejection and the v2.14.1 incident, and states its own falsification condition.
10. `hooks/triage-stop.sh` is OFF by default, blocks at most once per session, is registered with `|| true`, carries an unconditional exit-0 EXIT trap, and has a test proving the raw script exits non-zero when broken while the registration still fails open.
11. `compound-v-emit-workflow.py` emits a script whose stages are implement → gate → record, and whose staging reproduces `depends_on` order and `max_parallel` chunking for a fixture manifest.
12. `/v:dispatch` selects Engine A in a subagent, headless, scheduled and `/v:epic` context, and Engine B only in a top-level session with the capability present.
13. `.claude/compound-v-impact-taxonomy.yaml` exists in this repository, so the engine can emit a non-`unknown` band here and 3.0 is dogfooded rather than only shipped.
14. Every new script carries `--selftest` and is picked up by the existing CI discovery loop; every new guard is demonstrated to fail on a planted violation before it is trusted.

## Open questions carried into the pre-flights

- The "~20,000 tests" figure is the maintainer's account, not an observation. Phase 1A should look for the concrete downstream shape it refers to; if it cannot be reproduced, B1's defaults are chosen on principle rather than on measurement, and the spec must say so.
- Whether `/v:init` already seeds `.claude/compound-v-impact-taxonomy.yaml` — if it does, AC-13 is a bug report, not a feature.
- Whether the 9→2 collapse was deliberate. If a spec line exists saying so, A1 is a reversal and needs the same ADR treatment as B4.
