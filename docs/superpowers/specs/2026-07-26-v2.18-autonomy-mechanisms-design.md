# v2.18.0 — Arm the autonomy: turn prose into mechanism

**Revision r7 — a CLEAN REWRITE, not another patch.** r1-r6 accumulated **35 revision markers in 421
lines**, and by r6 every remaining review finding was the same kind: a fossil from an earlier revision
sitting next to the text that superseded it. One paragraph told the implementer to take a lock; the next
said no lock exists. A document that argues with itself cannot be built from, and layering an r7 marker
on top would have produced the same defect a seventh time.

So the design below is stated **once**, in its current form. The decision history — which is genuinely
valuable, because several of these were expensive — moves to the appendix, where it can be read as
history rather than mistaken for instruction.

## Why this release exists

The [autonomy diagnosis](2026-07-25-autonomy-ceiling-diagnosis.md) established by live probe that **no
epic has ever run in this repository**. The marathon loop (v2.10), the two-tier watcher (v2.11) and the
headless shim (v2.14) are ~1,900 lines of green, self-tested code that has never executed against a real
build. The maintainer had already routed around all of it — a hand-written overnight watchdog for a
*different* repo, on the native scheduler, running codex under `nohup`.

The sentence that names the trap: *"not survives while you sleep"* appears **four times** across our
docs. Documenting the limitation with great care substituted for removing it.

## Scope

**Ships:** A (Stop hook, goal-condition), B (the same hook used for enforcement, off by default),
F (wire the headless shim into `/v:epic --watch`, offered not armed), G (`timeout_sec` becomes real),
H (move the Iron Five out of the compaction truncation zone).

**Deferred to v2.19 — "the epic state machine learns time and waiting":** C (working-time budget) and
D (sleep until the usage window resets). Both need state-transition tables, and both land in the *same*
resume/reconcile machinery; specifying them apart is worse than specifying them together.

**Deferred to its own release:** detaching the codex worker. It is a completion protocol, not a flag.

**Dropped:** E (adaptive staleness). Its premise was false — see the appendix.

**Honest ranking check.** Against the diagnosis's own list, this ships cause **#1** (no blocking
primitive) and cause **#5** (the codex cap). Causes #3 and #6 are deferred with their design problem
named. **The resurrection duty cycle is not improved by this release**, and nothing here claims it is.

## Feature A — Restore the `Stop` hook (goal-condition only)

We removed `Stop`/`SubagentStop` in v0.1.1 on the premise that the event was undocumented. **That
premise was false.** A `Stop` hook returning `{"decision":"block"}` prevents the turn from ending, and
Anthropic's own `ralph-loop` plugin — sitting in this machine's plugin cache — is built on exactly that.
We deleted our only blocking primitive and then spent three versions building a scheduler substitute
with a 45-minute blindness window.

**Maintainer's choice: goal-condition only**, not the broader "block while unfinished work exists"
budget. **Cost, stated:** safer and more predictable, but it covers fewer marathon shapes, because a
feature-DAG marathon cannot always state its completion condition up front. Expect meaningfully longer
unattended runs **with a ceiling**, not eight hours.

### The hook contract

New `hooks/epic-goal-stop.sh`, registered on `Stop` with **no matcher** (Stop is not a tool event), and
registered as **`"<script>" || true`**.

**Event gate — first, before any state access.** Proceed only when `hook_event_name == "Stop"`. Exit 0
for `SubagentStop`, `StopFailure`, an unknown event, or a missing field. The harness converts a `Stop`
registration to `SubagentStop` for subagents, and Compound V dispatches subagents constantly — without
this gate a subagent shares the session id, passes isolation, is continued repeatedly, and burns the
main session's counter.

**Fail-open is mechanical, not intentional.** Two independent mechanisms, both required: the `|| true`
in the registration, and the script itself as an **unconditional-`exit 0` wrapper** around all fallible
logic. A block is expressed **only** by emitting valid JSON — never by an exit code. This matters
because a non-zero exit from a `Stop` hook *is itself a block*, so any ordinary bash failure (a bad
assignment, a redirect, a missing `jq`, a syntax error) would otherwise wedge the user's session.

**Inertness.** The hook is inert — exit 0, no output — when no goal is armed **and** enforcement is off.
The goal rule alone is inert whenever no goal is armed.

**Session isolation.** The armed record carries a `session_id`; the hook compares it to the one on
stdin and exits 0 on mismatch. **Arming refuses an empty session id** (`ralph-loop`'s guard falls
through on an empty stored id, which silently holds *every* session in the project open).

**Reads `stop_hook_active`, logs it, and does not return on it.** The flag is set on the first block and
never cleared for the rest of the turn, so returning on it would cap the feature at exactly one block —
while a synthetic-stdin selftest still passed.

### State: what is read, what is written

**The hook never writes `epic-state.json`.** That file has 35 `_atomic_write_json` call sites, most
documented as *"not flock-guarded — only the single live driver calls this"*. Adding the hook as a
second writer breaks that invariant, and a lock inside `_atomic_write_json` would self-deadlock
`claim_resume`, which already calls it while holding the lock.

| Datum | Home | Written by |
|---|---|---|
| armed goal condition, `session_id`, `arm_id`, `max_continues` | `epic-state.json` (lazily created) | `/v:epic` only — the single live driver, as today |
| `continue_count`, the enforcement once-marker | hook store in the OS temp dir | the hook only |

The hook therefore **reads** `epic-state.json` and **writes only its own store**. No lock, no wait
inside the user's turn, no deadlock.

**Hook store key: `digest(canonical project root) + session_id + arm_id`.** All three are required.
Root, because keying on the session alone lets project A suppress project B in the same session.
`arm_id` — a unique immutable id minted at **every** arm — because disarm/rearm inside one live session
would otherwise reuse the slot and a **sequential second epic would inherit the first epic's count**.

**Counter contract.** `max_continues` is immutable, finite, positive; **`0` is invalid, not
"unlimited"**. `continue_count` is mutable and starts at 0 for a new `arm_id`. The increment is
persisted **before** a block is emitted; if that write fails the hook **opens**.

**Store loss is a real hole, and the honest response is to fail open.** A temp sweep or a reboot can
remove the store mid-arm. Recreating the counter at zero would silently grant another full tranche of
continuations beyond `max_continues`. So: **a missing store during an active arm fails OPEN** — the hook
stops blocking for that arm and says so on stderr. Autonomy stopping is an acceptable failure; an
unbounded loop is not.

**Bounds, honestly ranked.** Our own `continue_count` is *the* bound. The harness cap
(`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, default 8) is a backstop we do not rely on — it is gated `if (n > 0
&& …)`, so `0` disables blocking limits entirely, and it honors 8 while overriding the 9th. The epic
circuit breakers remain unchanged and authoritative above both.

### The goal condition

Evaluated **deterministically from on-disk state**, never by model judgment — otherwise we would have
replaced prose with prose. Exactly **two** conditions ship:

- `all_features_done` — resolved by a **new canonical completion-category helper**, shared by routing
  and the hook. **Not `is_terminal`**: that classifier is also true for a tripped breaker, a `halt_epic`
  verdict, exhausted work, and an unsatisfiable DAG, so using it would declare the goal met *at the
  moment the epic failed* — a fabricated completion claim. Every terminal reason prefix is tested.
- `final_review_passed` — which already refuses `passed` while any audit is due.

**`no_incomplete_jobs` is refused at arm time**, with a message saying why: it is *run*-scoped, lives in
a file the epic state machine never opens, and a naive read would be **wrong** rather than merely
missing, because a job marked `done` whose files are not in git is not done.

**Discovery.** At most **one armed epic per project**. Arming refuses or explicitly replaces an existing
arm. Discovery starts from the hook's `cwd`, canonicalized, walks a fixed ordered path, and **fails open
on zero or multiple matches** rather than guessing which epic to hold open.

**`StopFailure`.** An armed goal **survives** a failed turn; a transient failure is not a completion
signal. The wedged-failing-turn case is covered by the continue counter, not by disarming.

## Feature B — The same hook, used for enforcement (OFF by default)

The observed bypass — *"the design was fully settled with you, so I implemented directly"* — is
**literally compliant with the letter of the strongest gate in the stack**: the upstream brainstorming
HARD-GATE releases at design approval, and the Compound V pipeline begins exactly there.

**Rule.** If tracked source files changed this session and **no run record exists** (no
`docs/superpowers/execution/<run-id>/state.json` created or advanced, no accepted fast-path record),
block once with a correction naming the sanctioned shortcut.

- **`enforcement: off` is the default**, config-gated. A false positive wedges a session.
- **Blocks at most once per marker lifetime** — see the honest guarantee below.
- Detection is **git-derived**: `git diff --name-only HEAD` unioned with untracked, filtered to tracked
  source paths, **excluding `docs/superpowers/**` and the hook's own store** (or arming a goal would
  itself count as "source changed").
- **The honest guarantee is "at most once while the marker survives"**, not "once per session": a temp
  sweep can occur mid-session and would permit one more correction. The failure direction is benign —
  an extra correction, never a missed one — and stating the weaker true promise beats stating a
  stronger false one.
- **It is best-effort and no criterion says otherwise.** The runtime **silently discards** a `Stop`
  block when a turn ends via a tool result, an MCP end-turn, or a loop tick. This raises the cost of
  skipping the pipeline; it cannot make skipping impossible.

### Precedence when both rules fire on one `Stop`

A single `Stop` event must produce **exactly one state update and exactly one JSON response**. Order:

1. Event gate. Not `Stop` → exit 0.
2. **Goal rule first.** If a goal is armed, unmet, and `continue_count < max_continues`: increment,
   persist, emit the continuation block. **Done — the enforcement rule does not run.** A goal-driven
   continuation is the system working as intended; a pipeline correction on the same turn would be
   noise, and two blocks on one event is undefined behaviour.
3. **Enforcement second**, only if the goal rule did not block: if enforcement is on, source changed,
   no run record, and the once-marker is unset — set the marker, emit the correction block.
4. Otherwise exit 0.

## Feature F — Wire the headless shim into `/v:epic --watch` (offered, NOT armed)

The shim is referenced only by README, CONVENTIONS, CHANGELOG, CI and the onboard doctor. **`/v:epic`
never calls it. `/v:init` never calls it.** It is an orphan.

**Maintainer's choice: wire it, do not arm it.** `--watch` offers the artifact and prints it; the human
still installs it. **Cost, stated:** this leaves the diagnosis's top-ranked cause — *nothing is ever
armed* — only partly addressed. A user who ignores the offer gets exactly today's behaviour.

**The wiring lives in `/v:epic` prose, not inside the shim.** The shim ships an AST-based selftest
asserting exactly **one** `subprocess.*` call in the whole file and that it names neither `launchctl`
nor `crontab`; any new call there fails it. The offer **never** pre-fills `--allow-build`.

## Feature G — Make `timeout_sec` real

`DEFAULT_TIMEOUT_SEC=900`, and **all nine real runs used it** — no manifest ever overrode it. Worse, a
`timeout_sec` key in a manifest is **silently accepted and silently ignored today**: the validator has
no unknown-key rejection, so the field parses, validates, and reaches nothing.

**Contract.** Integer seconds, minimum **60**, maximum **21600**, default **900 unchanged** so every
existing manifest behaves identically. Documented in the manifest schema's per-job table (currently
absent there), validated and bounded, and **actually passed** to the worker's existing `--timeout-sec`.
**No unknown-key rejection is added** — that would retroactively invalidate ten committed manifests.

**The outer-bound rule, with its owner and its residual.** The dispatcher spawns the worker through the
harness Bash tool, whose **foreground ceiling is 600 seconds** — so today's documented 900-second cap is
*already* unreachable; the launcher dies first. The background path (`run_in_background: true`) has no
such ceiling and is already permitted. Therefore:

> A job whose `timeout_sec` exceeds **600** MUST be dispatched on the background path, and the outer
> bound must exceed `timeout_sec` **plus the supervisor's `--grace`** so the worker can still write its
> result before it is killed.

**Residual, stated:** that rule lives in the dispatcher's prose — and this release exists because prose
is not enforcement. Shipping the field, the bounds and the rule is honest; claiming the rule is
guaranteed would not be. A mechanical version belongs with detachment, where a launcher that can wait
hours is the point.

## Feature H — Move the Iron Five out of the compaction truncation zone

Skill bodies are re-injected after compaction **truncated, keeping the start of the file**. The Iron
Five sit at lines **183-191** of a 271-line `skills/compound-v/SKILL.md` — inside the truncation zone.

**Move the Iron Five only.** ("The phase-trigger table" was ambiguous: three tables qualify and two are
already inside the first 150 lines.) The block must **end at or before line 150**, so a 9-line block
inserts at ~142.

**The citation arithmetic is computed at implementation time, not assumed.** Inserting at ~142 shifts
the original range **142-182**; lines before 142 and after 191 are untouched. There are **16**
line-anchored citations into `SKILL.md` across four files; **which of them fall in the shift zone must
be recomputed against the actual insertion point** and every affected one re-anchored, with the onboard
staleness check re-run. Earlier revisions asserted "exactly one" from a different insertion point; that
number is not carried forward.

## Global constraints

Python **3.9-safe, stdlib only**. Shell hooks: `bash`, shellcheck-clean, executable bit set (CI enforces
both), `command -v jq >/dev/null 2>&1 || exit 0`, and **every** pipeline guarded — under `set -euo
pipefail` a no-match `grep` aborts the script, and an aborted `Stop` hook exits non-zero, which is a
block. tz-aware `datetime.now(timezone.utc)`, never `utcnow()`. Deterministic JSON. `--selftest` present
as a literal string for CI auto-discovery, ASCII-safe under `LANG=C`, offline. **No fabricated
metrics** — in particular, no claimed hours of autonomy that were not measured.

## Anti-goals — the safety posture, unchanged

**NEVER emit the permission-bypass flag.** This repo's own history includes a live worker that deleted
an entire repository; the shim bans the flag and its selftest asserts the absence. Do not reverse it, do
not add an escape hatch. Keep `--allow-build` opt-in. Keep the scope gate, the cross-vendor arbiter, the
confirmed-blocker bar and the PASS-integrity sample audits — they are the moat, and they are not what
costs us the hours. No auto-arming of any scheduler. No enforcement on by default. **No claim that
anything survives the machine sleeping** — nothing local runs while a closed lid sleeps, and a genuine
machine-off overnight needs remote infrastructure.

## Acceptance criteria

**Scope: A, B, F, G, H only.** C and D are deferred and carry no criteria here; E is dropped.

**A/B — the hook (highest blast radius in this release: it runs in every session of every user)**
- Proceeds only on `hook_event_name == "Stop"`; exits 0 for `SubagentStop`, `StopFailure`, unknown and
  missing — with a test proving **a subagent turn is never held open**.
- Inert when no goal is armed **and** enforcement is off.
- Registered as `"<script>" || true`; the script is an unconditional-`exit 0` wrapper; a block is only
  ever valid JSON. Fault-injection tests: unreadable state, malformed stdin, absent `jq`, failed store
  write, deliberately broken script.
- **A selftest asserts the hook performs no write to `epic-state.json`.**
- Store keyed by `digest(root) + session_id + arm_id`; a **sequential re-arm starts at 0** (tested);
  two projects in one session do not share a slot (tested).
- `max_continues` immutable, finite, positive, **`0` invalid**; increment persisted **before** the
  block; failed persist opens; **a missing store during an active arm fails OPEN** and does not
  recreate the counter at zero (tested).
- Reads `stop_hook_active`, does not return on it.
- Refuses to arm with an empty session id; at most one armed epic per project; discovery fails open on
  zero or multiple matches.
- Completion uses the **new canonical helper, not `is_terminal`**; every terminal reason prefix tested;
  exactly two conditions ship; `no_incomplete_jobs` refused at arm time with a reason.
- The armed record is **lazily created** in `epic-state.json` — the three golden key-set selftests still
  pass.
- **Precedence tested:** goal-continuation and enforcement both eligible on one `Stop` ⇒ exactly one
  state update and exactly one JSON response, goal first.
- Enforcement is **off unless configured**; detection excludes `docs/superpowers/**` and the hook store;
  the guarantee documented is **"at most once while the marker survives"**. **No criterion claims it is
  unbypassable.**

**F — shim**
- `/v:epic --watch` offers the artifact; **nothing is installed**; the shim's AST selftest still passes
  (so no new `subprocess.*` call was added to it); the offer never pre-fills `--allow-build`.

**G — timeout**
- `timeout_sec` documented in the per-job table, validated (int, 60-21600, default 900 unchanged), and
  actually passed. The dispatcher doc states the 600s foreground ceiling, the mandatory background path
  above it, and `outer > timeout_sec + grace`. A test proves a value **above 900** reaches the worker on
  the background path. No unknown-key rejection added. Detachment out of scope.

**H — position**
- Iron Five only; block **ends at or before line 150**; content unchanged; the shift zone and the set of
  affected citations are **computed against the actual insertion point**, every affected citation
  re-anchored, onboard staleness re-run.

**Release**
- 2.18.0 lockstep across `plugin.json` + `marketplace.json` + `CHANGELOG.md`; all selftests green under
  `LANG=C` on 3.9; scope gate clean on every job. No claim of improved duty cycle, working-time
  budgeting, usage-limit waiting, or detached workers.

## Appendix — decision history

Kept because several of these were expensive, and separated from the design above so it can be read as
history rather than mistaken for instruction.

**Feature E (adaptive staleness) was dropped, not weakened.** Its floor could not go below today's 45
minutes — a full pipeline wave legitimately exceeds that with no state mutation, and the crashloop a
hair-trigger causes is documented. And the "75 minutes of dead air" is `45 + 30`, where the ~30-minute
poll is a separate constant it never touched. A mechanism that can only move the wrong way is theatre.

**Two pre-flights disagreed about `stop_hook_active`.** The contract audit traced the runtime and said
honoring it caps the hook at one block; the archaeology quoted the harness telling us to honor it. The
contract audit won, for two reasons an implementer can check: the guidance appears only inside the
*cap-exceeded warning* (advice for hooks with no bound of their own), and `ralph-loop` — the one shipped
implementation that actually loops — never reads the flag at all.

**Corrected claims that were wrong when first written:** `setsid` does not exist on macOS (nor
`timeout`/`gtimeout`), and our own worker already avoids the external binary for that reason; the
documented 900s worker cap is already unreachable behind a 600s foreground launcher ceiling;
`is_terminal` is not a completion classifier.

**Why the rewrite.** r1-r6 accumulated 35 revision markers in 421 lines. By r6, every remaining review
finding was a fossil — superseded text sitting beside its replacement, telling an implementer to do two
incompatible things. Five such contradictions were caught by review across two releases, and at least
one was introduced within an hour of catching the previous one. Careful patching demonstrably does not
prevent this; stating the design once does. **The v2.19 candidate that follows from this: a mechanical
check that a spec's acceptance criteria do not contradict its body — the same "prose is not enforcement"
lesson this release is about, turned on our own documents.**
