# v2.18.0 — Arm the autonomy: turn prose into mechanism

**Revision r4** — r1 was corrected by the Phase-1C contract audit (2 CRITICAL) and then by the Phase-1A
archaeology, which **falsified a load-bearing assumption in Feature C, removed Feature E entirely, and
found my two pre-flights in direct disagreement**. Every finding was re-verified on this machine before
acceptance. Codex then reviewed r3 and returned **DO NOT BUILD** — 4 CRITICAL, 7 HIGH, 1 MEDIUM, all
real. **Three were my own self-contradictions between the design body and the acceptance criteria** —
the same failure mode that cost v2.17 four rounds, and one of them I introduced an hour earlier in
r3.1. Corrections are marked `[r2]` / `[r3]` / `[r4]`.

**[r4] SCOPE CUT — the detached worker (Feature G) is split out.** Codex's review made it plain that
"detach the worker" is not a feature, it is a **completion protocol**: it needs an explicit
`launching → running → result_ready → done` state machine, a collect-side scope gate re-run against a
baseline the collector never observed, proof that files are actually in git before anything is marked
done, PID publication *after* spawn by the supervisor itself, and reconciliation for abandoned
`launching` records. That is a subsystem with its own failure modes, and bolting it onto a release that
already carries a hook running in every user session is how defects get made. **v2.18 ships the half
that delivers most of the value with none of that risk** — `timeout_sec` becomes a real, validated,
actually-passed manifest field, lifting the 15-minute cap that every one of our nine real runs hit.
Detachment gets its own release and its own evidence.

**[r3] The two pre-flights disagreed, and the disagreement is recorded rather than quietly resolved.**
The contract audit said honoring `stop_hook_active` makes the hook block exactly once (it traced the
runtime: the flag is set on the first block and never cleared). The archaeology said to honor it,
quoting the harness's own guidance string. **Both quoted real evidence; the contract audit wins**, for
two reasons an implementer can check: that guidance string appears only *inside the cap-exceeded
warning* — it is advice for hooks with no bound of their own — and `ralph-loop`, the one shipped
implementation that actually loops, never reads the flag at all. We read it, log it, and **do not
return on it**; our own persisted counter is the bound.

**Why this release exists.** The [autonomy diagnosis](2026-07-25-autonomy-ceiling-diagnosis.md)
established, by live probe, that **no epic has ever run in this repository**. The marathon loop (v2.10),
the two-tier watcher (v2.11) and the headless shim (v2.14) are ~1,900 lines of green, self-tested code
that has never executed against a real build. The maintainer routed around all of it — a hand-written
overnight watchdog for a *different* repo, on the native scheduler, running codex under `nohup`.

The single sentence that names the trap: *"not survives while you sleep"* appears **four times** across
our docs. **Documenting the limitation with great care substituted for removing it.**

**Scope was chosen by the maintainer** (2026-07-26). Where a safer, narrower option was picked over my
recommendation, that is recorded below with its honest cost — not silently upgraded.

## Feature A — Restore the `Stop` hook (goal-condition only)

**The premise we removed it on was factually wrong.** `hooks/hooks.json` claimed `SubagentStop` "is not
documented in official Claude Code hooks reference". It is documented; a `Stop` hook returning
`decision: "block"` **prevents Claude from ending the turn and continues the conversation**. Decisive
local proof: Anthropic's own **`ralph-loop`** plugin, present in this machine's plugin cache, is built
on exactly this, as is `/goal`. We deleted our only blocking primitive and then spent three versions
building a scheduler substitute with a 45-minute blindness window.

**Maintainer's choice: goal-condition only** — *not* the broader "block while unfinished work exists"
budget I recommended. **Honest cost, stated:** it is safer and more predictable, but covers fewer
marathon shapes, because a feature-DAG marathon cannot always state its completion condition up front.
Expect meaningfully longer unattended runs **with a ceiling**, not eight hours.

**Design.**
- New `hooks/epic-goal-stop.sh`, registered on `Stop`.
- **[r4] CRITICAL — the hook MUST gate on `hook_event_name == "Stop"` before any state read or write.**
  The harness converts a `Stop` registration to `SubagentStop` for subagents, and Compound V dispatches
  subagents constantly (pre-flights, implementers, reviewers). Without this gate a subagent shares the
  session id, passes isolation, gets continued repeatedly, **and burns the main session's counter**.
  Exit 0 for `SubagentStop`, `StopFailure`, an unknown event, or a missing field. Tested explicitly.
- **[r4] Inertness, stated correctly.** r3's Feature A said the hook exits immediately without an armed
  goal while Feature B said the same hook may block *without* one when enforcement is on — following A
  literally made B unreachable. The accurate rule: **the goal rule is inert without an arm; the hook as
  a whole is inert only when no goal is armed AND enforcement is off.**
- **The goal condition is evaluated DETERMINISTICALLY from on-disk state, never by model judgment** —
  otherwise we would have replaced prose with prose. The condition is a small closed enum resolved
  against `epic-state.json`. **[r3] Exactly TWO conditions ship**, both answerable by the existing
  single-source-of-truth classifiers. **[r4] `is_terminal` is the WRONG classifier for completion** and
  r3 named it by mistake: its own docstring says it is true when the epic will never progress again
  without a human — **including a tripped breaker, a `halt_epic` verdict, exhausted work, or an
  unsatisfiable DAG**. Using it would declare "all features done" satisfied *at the moment the epic
  failed*, which is a fabricated completion claim. v1 therefore ships **one canonical
  completion-category helper**, reused by both routing and the hook, distinguishing *completed* from
  *terminal-for-other-reasons*; every terminal reason prefix is tested. The two conditions are
  `all_features_done` (the new helper) and `final_review_passed` (which itself already refuses `passed` while
  any audit is due). **`no_incomplete_jobs` is REFUSED at arm time** — r1 listed it, the archaeology
  showed it is *run*-scoped, lives in a file the epic state machine never opens, and a naive read of it
  would be **wrong**, not merely missing, because a job marked `done` whose files are not in git is not
  actually done (the git-wins reconcile). Shipping the reader is out of scope; refusing the condition is
  the spec keeping its own promise.
- **Session isolation** (the `ralph-loop` pattern): the armed state records `session_id`; the hook
  compares it against the `session_id` on stdin and exits 0 on mismatch. **[r3] Arming REFUSES an empty
  session id** — ralph's guard falls through when the stored id is empty, which silently turns isolation
  off and holds *every* session in the project open. We inherit the pattern, not the hole.
- **[r3] The armed record lives INSIDE `epic-state.json`** (lazily created), not in a new file under
  `.claude/`. Verified: **`.claude/` is not gitignored in this repo**, so a state file there would be
  committed by accident *and* would trip the scope gate for any job that does not list it. Putting it in
  `epic-state.json` also fixes visibility for free — **`/v:status` is epic-blind today** (zero
  references to `epic-state.json`), and the dashboard finds epics by walking the execution tree, so a
  goal file anywhere else is invisible to both surfaces.
- **[r4] Discovery must be deterministic, and exactly ONE arm may exist.** The hook receives no state
  path, and there can be many `epic-state.json` files under the execution tree — r3 never said which one
  it reads. v1: **at most one armed epic per project**; arming **refuses** (or explicitly replaces) an
  existing arm; discovery walks a fixed, ordered path and **fails OPEN when zero or more than one
  record matches**, rather than guessing and mutating the wrong epic's counter.
- **[r2/r4] Bounded by OUR OWN counter first — with the contract spelled out.** r3 conflated the limit
  and the running count. v1 persists **two** fields: an immutable `max_continues` (a finite positive
  integer, validated at arm time — **`0` is invalid, not "unlimited"**) and a mutable `continue_count`.
  The increment is **persisted atomically BEFORE the block is emitted**; if that write fails, the hook
  **opens** (exit 0) rather than emitting a block it did not record. Otherwise a failed write plus an
  emitted block loops forever. The harness cap (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`,
  default 8) is a **backstop we do not rely on** — it is gated `if (n > 0 && …)`, so a `0` disables
  blocking limits entirely, and it honors 8 blocks while overriding the 9th. The existing epic circuit
  breakers remain unchanged and authoritative on top. r1 called these "three bounds" as if equal; two of
  the three are not ours to guarantee.
- **[r2] CRITICAL — `stop_hook_active` must NOT be treated as "return success immediately".** r1 said
  it should be. Traced in the shipped runtime: once a `Stop` hook blocks, `stopHookActive` is set and
  **never cleared for the rest of the user turn** — every continue-branch propagates it unchanged. So a
  hook that returns success whenever it is true can block **exactly once**: `max_continues` could never
  exceed 1, the harness cap of 8 would be unreachable dead code, and the circuit breakers would never
  engage. Worst of all, **a synthetic-stdin selftest would still pass while the feature was inert in
  production** — a green test over a dead feature.
  **Verified locally:** the reference implementation we cite, `ralph-loop`, **never reads
  `stop_hook_active` at all** (`grep -c` → 0); it bounds itself with its own persisted `max_iterations`.
  That is precisely why it loops. The runtime's "check `stop_hook_active` and return success" advice
  appears only inside the *cap-exceeded warning*, i.e. it is guidance for hooks that have no bound of
  their own.
  **v1 therefore bounds itself with its OWN persisted counter** and reads `stop_hook_active` only as a
  logged signal. This is also why our own counter — not the harness cap — is the real bound: the cap is
  `if (n > 0 && ...)`, so setting it to `0` disables blocking limits entirely, and the honored count is
  8 with the 9th overridden.
- **[r4] CRITICAL — fail-open must be MECHANICAL, not intent.** r3 said "corrupt state fails open" and
  "guard every pipeline with `|| true`". That is not sufficient: a failed assignment, a redirection, a
  state write, a missing interpreter or a syntax error all return non-zero under `set -euo pipefail`,
  and **a non-zero exit from a `Stop` hook is itself a block**. So a bug in our hook wedges the user's
  session. Two mechanisms, both required:
  1. **Register the command as `"<script>" || true`** in `hooks/hooks.json`, so even a missing or
     unparseable script cannot return non-zero.
  2. **The script is an unconditional-`exit 0` wrapper** around all fallible logic; a block is expressed
     **only** by emitting valid JSON, never by an exit code.
  Fault-injection tests are mandatory: unreadable state, malformed stdin, absent `jq`, a failed atomic
  write, and a deliberately broken script.
- Armed and disarmed explicitly by `/v:epic`; `/v:status` shows whether a goal is armed.
- **[r2] `StopFailure` is a shipped event r1 never mentioned.** An armed goal **survives** a failed turn
  — a transient failure is not a completion signal and must not silently disarm autonomy. The run is
  protected from a wedged failing turn by our own continue counter, not by disarming on failure.

## Feature B — The same primitive, used for enforcement (OFF by default)

The [prose-vs-mechanism research](2026-07-25-autonomy-ceiling-diagnosis.md) found the reported bypass —
*"the design was fully settled with you, so I implemented directly"* — is **literally compliant with the
letter of the strongest gate in the stack**: the upstream brainstorming HARD-GATE releases at design
approval, and the Compound V pipeline begins exactly there. Our own equivalent is prose.

**Design.** A second rule inside the same `Stop` hook: if tracked source files changed this session and
**no run record exists** (no `docs/superpowers/execution/<run-id>/state.json` created or advanced, and
no accepted fast-path record), block once with a correction naming the sanctioned shortcut.

- **`enforcement: off` is the default**, config-gated in `.claude/compound-v.json`. A false positive
  here wedges a session, and this project has been bitten by exactly that class before.
- **Blocks at most once per session** (a counter in the state file), so a user who disagrees is never
  trapped in a loop.
- Source-file detection is **git-derived**, never model-reported: `git diff --name-only HEAD` unioned
  with untracked files, filtered to tracked source paths (docs and the execution audit trail excluded).
- **[r2] It is best-effort, and the spec says so rather than claiming a guarantee.** The runtime
  **silently DISCARDS a `Stop` block** when a turn ends through certain paths (a tool result, an MCP
  end-turn, a loop tick) — observed in the shipped binary as *"Stop hook block discarded … no model
  re-invoke"*, and undocumented publicly. So this rule is **bypassable by construction**. It raises the
  cost of skipping the pipeline; it does not make skipping impossible, and **no acceptance criterion may
  claim it does.** Writing an unbreakable-gate claim we cannot honor would be exactly the overclaim this
  project exists to prevent.

## Feature C — Working-time budget, not calendar time

`compound-v-epic-state.py:1643` computes `elapsed_hours = now - started_at`, where `started_at` is
stamped once at `--init`. Default `max_wall_clock_hours = 10`. **An epic initialized at 2pm is already
over budget by midnight** — the breaker trips on the first overnight check, before any useful work.

**Design.**

**[r4] CRITICAL — r3's fix was still not enough.** Naming three non-watch-gated mutation sites only
moves the hole: after the *first* advance, a watch-off run can spend hours working with no further
listed mutation and carry a stale `active_seconds` forever, and the calendar fallback (which r3 applied
only *before* any advance) never re-engages. The site list was also demonstrably incomplete —
`record_final_review` mutates state directly and its only time bump is watch-gated.
**v1 uses explicit ACTIVE INTERVALS instead of point advances:** a durable `active_since` opened at a
work-lifecycle boundary and closed at the next one, plus accumulated seconds; **the breaker adds any
currently-open interval to the accumulator when it evaluates**, so an in-flight stretch is counted even
if no mutation has landed. Advancement is centralized in one helper so every successful marathon
mutation is covered by construction rather than by an enumerated list that the next contributor will
forget to extend.

**[r3] Background: r1's "advance it at the existing heartbeat points" would have un-bounded every
watch-off marathon — the exact failure this feature's own AC forbids.** Verified: the wall-clock breaker runs for
**any** marathon, but **every** heartbeat site is watch-gated (`_bump_last_progress` is a deliberate
no-op when `watch` is off, to preserve byte-identical state). So on a watch-off marathon the accumulator
would sit at `0` forever and the 10-hour breaker would never trip. v1 therefore:
- advances the accumulator at the **non-watch-gated mutation sites** (`apply_update`,
  `record_progress_cycle`, `record_disposition`), not at the watch-gated bump; and
- falls back to the calendar delta — **loudly** — when the accumulator is absent **or** watch is off and
  no non-gated advance has occurred. "No accumulator" must never mean "no bound".

**[r3] The field must be LAZILY created.** Three golden selftests pin the exact key sets of `autonomy`
and of the top-level state. An unconditionally-written `active_seconds` fails all three. Follow the
existing lazy-creation discipline used by the lease/resume-count surface.

**[r3] Both existing fail-safes are preserved:** a missing or unparseable `started_at` currently
**TRIPS** the breaker. An accumulator path that turns either into a *skip* would invert a deliberate
fail-safe. And `--reset-wall-clock` must reset the accumulator too, or it becomes a no-op.

## Feature D — Sleep until the usage window resets

`compound-v-failure-policy.py:49` caps `rate_limited` at **3 retries** with a **60s** backoff ceiling
(`:63`), and `out_of_credits`/`auth` are not retryable at all. Hit a rolling window at 1am and the run
halts until a human wakes up. **There is no sleep-until-reset path anywhere in the codebase.**

**Design.** A new terminal-ish disposition `wait_until` carrying a resume timestamp:
- The policy returns `{"action": "wait_until", "resume_after": "<ISO>", "reason": ...}` for
  `rate_limited` once the retry budget is spent, and for `out_of_credits`.
- **Nothing sleeps in-process.** A blocking sleep inside a script would hold a process, a worktree and
  possibly a tool timeout hostage. The wait is **recorded in state** and honored by the existing resume
  path — the same machinery `/v:resume` already uses. **[r3]** A recorded wait must **not** look like a
  `pending` job to `/v:resume`, or the resume path re-dispatches straight back into the rate limit.
- **[r3] The provider signal already exists — do NOT write a second parser.**
  `compound-v-classify-failure.py` already extracts `Retry-After` **and** codex's prose form
  ("try again in 5 days" → 432000s), and it is already plumbed through to `job_result.retry_after_seconds`.
  That measured value is the signal; anything else is the labelled estimate.
- **[r3] Every consumer of the policy contract is PROSE, and a new action fails SILENTLY by omission.**
  There is no code consumer at all — four markdown surfaces read `action` (the dispatcher's step, the
  failure-policy doc's action table and its "acting on each action" section, the parallel-dispatch phase
  doc, and the backend-launcher contract). All four **must** be updated in the same change, plus the
  state-machine field table for the new persisted field. A model that hits a table row which does not
  exist simply stalls.
- **[r3] Decide the output shape explicitly:** `decide()` returns a fixed 6-key dict today, so adding
  `resume_after` changes every action's shape. v1 emits it **always, `null` when not applicable** — and
  a selftest asserts the key is present for every action, because the existing selftest inspects only
  `action` plus one field and would not catch a conditional key.
- **[r3]** `out_of_credits` currently **reroutes** to a viable fallback. `wait_until` **follows** the
  reroute (it applies only when no viable fallback remains), so the codex→claude fallback does not
  silently regress.
- **[r4] The waiting state must be DESIGNED, not asserted.** r3 said a recorded wait "must not look like
  a pending job" without saying how. v1 persists an explicit **`status: "waiting"`** alongside
  `resume_after`, plus an eligibility predicate: a wait whose deadline is in the future is **excluded
  from dispatch**; a due wait transitions **atomically** to dispatchable; a malformed timestamp leaves
  the job **stopped with a warning**, never silently dispatchable and never silently stuck. Tested at
  before / exactly-at / after the deadline.
- **[r4] A timed circuit break, or the wait matures into a still-closed backend.** Today an
  unavailable-fallback credit failure sets `circuit_break=True`. Turning `halt` into `wait_until`
  without an expiry rule means the deadline arrives and the backend is *still* circuit-open, so the job
  cannot run — while clearing the break immediately would let sibling jobs hammer an exhausted backend.
  v1 persists **`circuit_break_until`** and reopens **only that backend** when the deadline matures.
- **[r2] For codex, the estimate is the PRIMARY path, not the fallback.** r1 implied a real reset
  signal is usually available. A live `codex exec --json` probe (this session's own event log) emits
  only `thread.started` / `turn.started` / `item.started` / `item.completed` / `turn.completed` /
  `agent_message` / `command_execution` / `error` — **no rate-limit event and no reset time anywhere**;
  codex's reset structs live in its app-server protocol, not in `exec`. Claude does expose a reset via
  a stream-json rate-limit event, but that is **code-verified, not observed on a live 429**. So: use a
  provider signal **only where one demonstrably exists**, and otherwise emit a conservative interval
  **explicitly labelled an estimate**. Never print a precise reset time we did not measure — and note
  that codex is the backend the failure policy circuit-breaks most often, so the estimate path is the
  common one, not the exotic one.

## Feature E — Shrink the blindness window — **[r3] DROPPED**

r1 proposed making the 45-minute staleness threshold adaptive. **The archaeology dismantled the
premise and I am cutting the feature rather than shipping a placebo.** Three findings, each fatal:

1. **The floor cannot go below today's constant.** A full pipeline wave *legitimately* exceeds 45
   minutes while emitting no state mutation — that is documented in our own domain audit, and the
   crashloop a hair-trigger produces is documented too. So an adaptive threshold may only ever raise
   the bar, never lower it. An "adaptive" mechanism that can only move the wrong way is theatre.
2. **Staleness is not the bigger half.** The "up to 75 minutes of dead air" figure is `45 + 30` — the
   ~30-minute poll cadence is a **separate constant**, mirrored byte-for-byte in two files. Shrinking
   staleness alone leaves the poll gap untouched, so the honest ceiling on the win was ~45 of 75
   minutes even in the best case that (1) already forbids.
3. It contends for `compound-v-epic-state.py` with Features A and C, on a file three golden key-set
   selftests pin exactly — real partitioning cost for a benefit that (1) and (2) reduce to roughly zero.

**Honest consequence, stated rather than buried:** the resurrection duty cycle is **not improved by
this release**. The blindness window stays as it is. If we want it, the thing to attack is the poll
cadence, not the staleness constant — and that is its own release with its own evidence.

`grep -rn "headless-shim"` shows it is referenced only by README, CONVENTIONS, CHANGELOG, CI and the

## Feature G — Codex worker: make `timeout_sec` real **([r4] detachment SPLIT OUT)**

`scripts/compound-v-run-codex-worker.sh:45` sets `DEFAULT_TIMEOUT_SEC=900`, and **all nine real runs
used that default** — no manifest ever overrode it. Worse, `timeout_sec` in a manifest is **silently
accepted and silently ignored today**: the validator has no unknown-key rejection, so the field parses,
validates, and reaches nothing.

**v2.18 ships exactly this half:** `timeout_sec` becomes a real per-job field — documented in the
manifest schema's per-job table (where it is currently absent), validated and bounded by the validator,
and **actually passed** by the dispatcher to the worker's existing `--timeout-sec`. The gap being closed
is between a contract that already names the field and a manifest that ignores it.

**No unknown-key rejection is added** — that would retroactively invalidate ten committed manifests.

**[r4] Detachment is deferred to its own release, with reasons.** Codex's review established that
detaching is a **completion protocol**, not a flag:
- worker **stdout is the entire result contract** today; detaching destroys it,
- a durable result file is not a protocol — it needs `launching → running → result_ready → done`, an
  atomic write only *after* the worker-side gate, and a collect-side re-run of the scope gate against a
  baseline the collector never observed,
- **`pid` cannot be written "before launch"** because it does not exist until after spawn; the
  supervisor itself must publish PID/PGID atomically, and abandoned `launching` records need
  reconciliation,
- a worker killed between record and result must classify as **failed/retryable, never done**, and
  nothing may be marked done while its files exist only in a worktree.

Shipping that alongside a hook that runs in every user session would be reckless. The 15-minute cap —
the part that actually bit all nine runs — lifts today.

## Global constraints

Python **3.9-safe, stdlib only**; `--selftest` present as a literal string (CI auto-discovery),
ASCII-safe under `LANG=C`, offline. Shell hooks must be POSIX-ish `bash`, must not require `jq` to be
present without a guard, and must **exit 0 on any internal error**. tz-aware `datetime.now(timezone.utc)`,
never `utcnow()`. Deterministic JSON. **No fabricated metrics** — in particular, no claimed hours of
autonomy that were not measured.

## Anti-goals — the safety posture, unchanged

**NEVER emit the permission-bypass flag.** This repo's own history includes a live worker that deleted
an entire repository; `scripts/compound-v-headless-shim.py:176-180` bans it and its selftest asserts the
absence. **Do not reverse it, do not add an escape hatch for it.** Keep `--allow-build` opt-in. Keep the
scope gate, the cross-vendor arbiter, the confirmed-blocker bar and the PASS-integrity sample audits —
they are the moat and they are not what costs us the hours. No auto-arming of any scheduler. No
enforcement rule on by default. No claim that Compound V survives the machine sleeping — **nothing local
runs while a closed lid sleeps**, and a genuine machine-off overnight still needs remote infrastructure.

## Acceptance criteria

**[r4] These are rewritten wholesale, not patched.** Codex found three places where the design body and
these criteria stated different contracts — the failure mode that cost v2.17 four review rounds, and one
of the three I introduced myself an hour before the review.

**Feature A/B — the hook (highest blast radius in the release: it runs in EVERY session of every user)**
- Gates on **`hook_event_name == "Stop"`** before any state read or write; exits 0 for `SubagentStop`,
  `StopFailure`, unknown, or missing — with a test proving a **subagent turn is never held open**.
- **Inert when no goal is armed AND enforcement is off** (not "inert without an arm", which made the
  enforcement rule unreachable).
- **Fail-open is mechanical:** registered as `"<script>" || true`, and the script is an
  unconditional-`exit 0` wrapper; a block is expressed **only** via valid JSON. Fault-injection tests
  cover unreadable state, malformed stdin, absent `jq`, a failed atomic write, and a broken script.
- **Two distinct fields:** immutable `max_continues` (finite positive; **`0` is invalid, not
  unlimited**) and mutable `continue_count`. The increment is **persisted atomically before** a block is
  emitted; a failed persist **opens** the hook.
- Reads `stop_hook_active` and logs it but **does not return on it** (it is never cleared once set, so
  returning would cap the feature at one block while a synthetic selftest still passed).
- **Refuses to arm with an empty session id**; at most **one armed epic per project**; discovery is
  deterministic and **fails open on zero or multiple matches**.
- The completion condition uses the **new canonical completion-category helper — NOT `is_terminal`**,
  which is also true for a tripped breaker, `halt_epic`, exhausted work and an unsatisfiable DAG. Every
  terminal reason prefix is tested. Exactly **two** conditions ship; `no_incomplete_jobs` is refused at
  arm time with a message saying why.
- The armed record lives inside `epic-state.json`, **lazily created**, so the three golden key-set
  selftests still pass.
- **No criterion claims enforcement is unbypassable** — the runtime discards a `Stop` block on several
  turn-end paths. It raises the cost of skipping the pipeline and nothing more.

**Feature C — working time**
- Uses **explicit active intervals** (`active_since` + accumulated seconds) with advancement centralized
  in one helper; **the breaker adds any currently-open interval when it evaluates**, so a watch-off run
  working for hours with no landed mutation is still bounded.
- Explicit tests for: **missing** `started_at` (must still TRIP), **malformed** `started_at` (must still
  TRIP), sustained **watch-off activity** (must become bounded, not frozen), and `--reset-wall-clock`
  resetting **both** the timestamp and the accumulator.
- The field is **lazily created** — the three golden key-set selftests still pass.

**Feature D — waiting**
- Persists **`status: "waiting"`** plus `resume_after`. A future wait is **excluded from dispatch**; a
  due wait transitions **atomically** to dispatchable; a **malformed** timestamp leaves the job stopped
  with a warning. Tested before / exactly-at / after the deadline.
- Persists **`circuit_break_until`** and reopens **only that backend** at maturity.
- `resume_after` is present on **every** action (`null` when N/A), asserted for each, since the existing
  selftest inspects only `action` plus one field.
- The reset time comes from the **existing** `Retry-After` extractor when present; otherwise a
  conservative interval **labelled an estimate**. For codex the estimate is the **primary** path — a
  live `codex exec --json` probe carries no reset signal at all.
- All four **prose** consumers of the policy contract are updated in the same change; a new action value
  otherwise fails silently by omission.

**Feature F — shim**
- `/v:epic --watch` offers the artifact; **nothing is installed**. The wiring lives in `/v:epic` prose —
  the shim's AST selftest asserts exactly one `subprocess.*` call in that file, so any new call there
  fails it. The offer **never** pre-fills `--allow-build`.
