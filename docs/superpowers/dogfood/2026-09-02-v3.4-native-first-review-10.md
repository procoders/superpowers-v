#### 1 — **HIGH · PASS 1** · item 1 is narrowed, not closed: an EMPTY sealed patch proves anything

`sealed_post_image` returns an empty image for empty bytes, by design
(`compound-v-integration-gate.py:538-539`):

```python
    if not patch_bytes:
        return {}, None
```

and `head_matches_post_image` iterates that image (`:576-591`), so an empty dict returns
`(True, None)` — vacuously. The authority's call site does not guard against it
(`:951-955`):

```python
                    _image, _ierr = sealed_post_image(repo_root, _baseline, _patch_bytes)
                    if _ierr:
                        _why = _ierr
                    else:
                        _proved, _why = head_matches_post_image(repo_root, _image)
```

**The emitter's own copy of the same proof does guard against it.** `compound-v-emit-workflow.py:3921`
is `if image:` before it will call `head_matches_post_image` at all — an empty post-image is not
allowed to prove a merge there. The authority is the twin that dropped the guard.

The three inputs the branch trusts — `receipts/<id>.gate.json`, `jobs/<id>.patch` and `state.json` —
are **all three exempt by name** from the scope gate (item 2's own table) and writable by a
`direct`-mode worker; that is the documented reason the authority exists. So the forgery is three
writes. Reproduced against the merged tree, same fixture as case A:

```text
HEAD:src/work.txt is ->  base          # the job's work is NOT in HEAD
forged: empty jobs/w1.patch, receipt digest sha256:e3b0c44298fc… , state.json merged -> a19075353712

  w1   PASS   receipt=merged   gate root is gone because this job was merged as a19075353712,
       which EXISTS, is an ancestor of HEAD, and HEAD carries exactly the blobs the sealed patch
       sha256:e3b0c44298fc produces — proven from git and the artifact, not from state.json or a pathname
INTEGRATION PERMITTED — 1 job(s), every one resolved to a verdict this gate derived or verified itself.
authority rc=0
```

`e3b0c442…b855` is the SHA-256 of the empty string, so the forgery needs no computation: truncate the
artifact, write that constant into the receipt, name any ancestor commit. The verdict line then
asserts *"HEAD carries exactly the blobs the sealed patch produces"* about a patch that produces no
blobs.

This is the same class of defect as H4 — a proof that is satisfiable without the thing it claims to
prove — one level in. → An image with no paths is not a proof; refuse it the way the emitter does,
and consider requiring the image's paths to be a non-empty subset of the job's `write_allowed`.

#### 2 — **CRITICAL · PASS 2** · Codex **C2** is regressed by this commit: three stdlib modules are now shadowable

The commit added four imports at the top of the authority, above the hardening call
(`compound-v-integration-gate.py:100-105`):

```python
import os
import json        # <- added
import subprocess  # <- added
import tempfile    # <- added
import shutil      # <- added
import sys
```

`_harden_sys_path()` — the function that removes the script's own directory and the cwd from
`sys.path` so a job with a lane over `scripts/**` cannot shadow a stdlib module — is called at
`:152`, **forty-seven lines later**. The post-hardening block at `:155-161` still imports all four,
but they are already in `sys.modules` by then, so those lines are now no-ops. The other two
enforcement CLIs keep the discipline and say so: `compound-v-scope-check.py:201` carries the comment
*"deliberately after `_harden_sys_path()`"*, and `compound-v-emit-workflow.py:54-55` imports only
`os` and `sys` before it. Only the file this commit edited most broke the rule.

Proven live, and attributed to this commit by a control against its parent. Same probe both times: a
copy of the authority in a scratch directory with a plant beside it for each of `json`, `subprocess`,
`tempfile`, `shutil`, `hashlib`, `argparse`, `re`, `yaml`; each plant appends a line to a marker file
and then delegates to the real module, so the run continues:

| Version | Plants imported | Selftest |
|---|---|---|
| `ab3cbbe` (parent) | **none** | 75/75 passed |
| `72e34c4` (this commit) | **`json.py`, `subprocess.py`, `tempfile.py`** | **78/78 passed** |

`shutil` did not announce only because the real one is already in `sys.modules` by the time line 104
runs; the exposure is the same.

What this buys an attacker is the whole authority. `subprocess` is how every `git` call in this file
is made — `rev-parse`, `merge-base`, `read-tree`, `apply`, `ls-files`, `diff` — so a planted
`scripts/subprocess.py` returns whatever the attacker wants git to have said, including the blob
comparison finding 1 is about. `json` is how every receipt, result and `state.json` is read. The
threat model is not hypothetical for this repo: a job with a lane over `scripts/**` is ordinary, and
the CHANGELOG's own C2 entry is that a planted module beside these entry points must never be
imported.

And the run reports green while it happens. → Move the four imports back below `_harden_sys_path()`
and keep only `os` and `sys` above it.

#### 3 — **MEDIUM · PASS 2** · nothing asserts the invariant finding 2 broke

The authority's shadow-module selftest (`:2219-2261`) plants exactly one module — `scripts/yaml.py` —
which is imported *lazily, inside `load_manifest`*, long after hardening. It therefore tests that
`_harden_sys_path()` works, and never that the import block above it stayed empty. That is why a
four-line diff walked past a suite that grew to 78 checks in the same commit.

The invariant is cheap to assert from the file's own source (no import may precede the
`_harden_sys_path()` call except `os` and `sys`), and it is the kind of assertion this repo has
already learned to want: v2.14.1's lesson was that a green CI can be false-green, and this is a green
selftest that is false-green about the exact property it was written to protect. → Guard the ordering
itself, in all three enforcement CLIs, not just the behaviour of the function.
