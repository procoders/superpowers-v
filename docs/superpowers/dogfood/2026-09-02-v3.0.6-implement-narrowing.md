# Dogfood — a narrowed implementer still does the work

**Run:** `docs/superpowers/execution/2026-09-02-v3.0.6-implement-narrowing/`
**Date:** 2026-09-02 · **Engine C**, one wave, two jobs

## What was being tested

3.0.6 removes capability from the Implement stage: `Task`, `Agent`, `SlashCommand`,
`WebFetch`, `WebSearch`. A removal is easy to ship and easy to be wrong about — the
failure mode is an implementer that can no longer do its job, and the earliest place
that shows up is a real run.

Same two-lane shape as the 3.0.5 routing run, so the only variable is the narrowing.

## What happened

Both lanes wrote their file, both gated clean, and the wave finalizer merged them as
`5c89a37`. Seven agents, zero errors. The narrowing changed nothing about the outcome,
which is exactly the claim being tested — a list that broke implementers would have
shown up here as an empty `files_changed`, and 3.0.4 taught this pipeline to refuse
that instead of blessing it.

## What this run does not show

* **The denials were not exercised.** No job in this run tried to spawn a nested agent
  or reach the network, so this proves the narrowing is *harmless*, not that it *bites*.
  That it bites is the runtime's contract for `disallowedTools`, not something this run
  observed.
* **`bashCommandClamp` on Implement is still conditional.** `_clamp_rules` returns
  `None` for a non-`claude` job whose worker script is missing, and an implementer with
  no clamp is unnarrowed on Bash. Unchanged by this release, and recorded here so the
  row in the audit table is not read as more than it is.
