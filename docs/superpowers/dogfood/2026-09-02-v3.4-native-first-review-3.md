### ISSUE 1 — QUALITY: the carve-out drops *any* file under *any* `__pycache__/`, not bytecode — reproduced

[`scripts/compound-v-scope-check.py:203-208`](../../../scripts/compound-v-scope-check.py):

```python
def is_bytecode_noise(path):
    """True for Python bytecode the interpreter writes beside the sources."""
    parts = str(path or "").split("/")
    if "__pycache__" in parts[:-1]:
        return True
    return parts[-1].endswith((".pyc", ".pyo"))
```

The first branch matches on a **directory name**, with no condition on the file. Anything written
under any `__pycache__/` at any depth — a `.py`, a key, a blob — leaves the changed set before
`write_allowed` is ever consulted.

**Reproduced on a throwaway repo, driving the real module.** A job whose lane is `docs/**` writes
three files outside it, then edits its one allowed file:

```
changed set : ['docs/x.md']
violations  : []
noise? scripts/__pycache__/payload.py -> True
noise? scripts/__pycache__/id_rsa     -> True
```

`scripts/__pycache__/payload.py` and `scripts/__pycache__/id_rsa` are out-of-lane writes of arbitrary
content. The gate returns `violations: []` and does not even **list** them as changed. Because
`__pycache__/` is gitignored, `git status` does not show them either: after this change, a write to
that path family is invisible to both the gate and the working tree.

**Failure scenario.** A worker — a compromised one, a prompt-injected one, or an honest one following
bad instructions — is dispatched with `write_allowed: ["docs/**"]`. It writes
`scripts/__pycache__/<module>.cpython-39.pyc` as a hash-based *unchecked* pyc, which CPython imports
without validating against any source, and the gate reports `pass`. The scripts do import each other
(`compound-v-onboard.py:5-9` imports the secret-pattern families from `compound-v-memory.py`;
`compound-v-integration-gate.py:641` loads `compound-v-scope-check.py` by
`spec_from_file_location`), and the second of those is **the gate loading its own matcher**. Nothing
in the pipeline has to commit the file for it to run.

**The widening is not needed by the fix and not pinned by its tests.** All four of the carve-out's
own assertions (`:732-752`) pass with the directory branch deleted — every planted path there ends
in `.pyc` or `.pyo`, and `is_bytecode_noise("a/__pycache__/b.pyc")` is true on the extension alone.
The assertion labelled **`"is_bytecode_noise names exactly bytecode"`** is the one that would have
caught this, and it does not test the claim its own label makes: it asserts two positives that both
carry a bytecode extension and two negatives (`"__pycache__"`, `"src/pycache.py"`) that the extension
check already rejects. It reads as coverage and is not.

→ Restrict the predicate to the extension — `return parts[-1].endswith((".pyc", ".pyo"))` — or AND
the directory branch with it. Then make the fourth assertion earn its label by planting a
non-bytecode file under `__pycache__` and asserting it still **BLOCKS**, the way the third assertion
already does for `evil.py`.
