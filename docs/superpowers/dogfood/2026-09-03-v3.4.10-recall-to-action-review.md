## 5. Issues

**1. SPEC_GAP — the emitted reading budget is not the one the spec and plan fixed.**
`scripts/compound-v-emit-workflow.py:2288-2293` emits: *"READING BUDGET: these records
and nothing further — do not go hunting through the run directories they name…"* — a
budget on reading the **recall evidence**. The spec (design §Decision, item 1) and the
plan (Task A, "the fixed reading-budget instruction from the spec") require a budget on
reading the **lane**: *"budget your reading (`grep -n` then `sed -n` ranges, ≤ 20 reading
calls), never read a large file top to bottom, commit what is complete if the turn budget
nears."* None of those four clauses appears. This is the substantive half of finding 130 —
six implementers died reading a 6,000-line file, and the section that exists to prevent
that recurrence does not say the thing that prevents it. (This run's own manifest had to
carry the budget by hand, in `emitter-recall`'s `body:`.)
→ Emit the spec's instruction. Add a selftest check for its presence.

**2. CONSTRAINT_VIOLATION — `auto_tighten` is read from a manifest key nothing writes.**
`:1781` reads `manifest["memory"]["auto_tighten"]`. The plan's Task A says verbatim:
*"Read `memory.auto_tighten` from `.claude/compound-v.json`"*, and both `commands/v-init.md:496`
(`"memory": { … "auto_tighten": false }`) and `skills/compound-v/SKILL.md:189`
(*"the `/v:init` choice read from `.claude/compound-v.json`"*) place the switch there.
Nothing writes a top-level `memory:` block into a manifest: `/v:orchestrate` does not,
`examples/manifest.example.yaml` has none, `execution-manifest.md` does not document one.
`build_plan` already computes `config_path = <repo>/.claude/compound-v.json` at `:1732`
and passes it to `resolve_job_model` — the file was in hand. So the feature's mechanical
half is unreachable from the supported path, and the defect the spec opens by naming
(*"`memory.auto_tighten` / `memory.auto_recall` are read by no script"*) is relocated, not
closed: `/v:init`'s Auto-tighten stance still drives nothing.
→ Read it from `.claude/compound-v.json`, with the manifest key as an optional per-run
override if that is wanted; assert the config path in a selftest.

**3. QUALITY (docs) — memory.md documents behaviour the code does not have.**
`skills/compound-v/memory.md:93-95` promises the prompt carries "`grep -n` then `sed -n`
targeted ranges, ≤ 20 reading calls, never read a large file top to bottom, commit what is
complete" — the emitter emits none of it (ISSUE 1). `:90` gates action 1 on
*"when `memory.auto_recall` is on (default true)"*; no script reads `auto_recall`, and the
code's real gate is `--no-recall`. `:83` says "for every `type: implement` job"; the code
runs it for every job (ISSUE 5). Prose and code disagree, and per the review contract the
code wins — so this is a documentation defect in the same diff, against AC 4's
"describe **exactly** these actions".
→ Fix ISSUE 1 and re-align these three sentences to what ships.

**4. (advisory) The design's "and in the gate receipt" is unimplemented.**
Design §Decision: *"The verdict is recorded on the job in `state.json` … **and in the gate
receipt**, so the reviewer's Step 0 reads a fact instead of re-deriving one."*
`receipts/emitter-recall.gate.json` and `receipts/docs.gate.json` carry no `recall_check`.
The feature-level AC requires only the job entry and state.json, so this does not fail an
AC — but this reviewer did have to re-derive the verdict by re-emitting.
→ Either carry it into the receipt or strike the clause from the spec.

**5. (advisory) Recall runs for every job, not every implement job.**
`:1784` loops over all jobs. The spec and memory.md both say implement jobs. Measured cost
of the deviation on this run: 76 ms on `spec-review`, whose verdict is `none` by

so). Harmless today; it is a spec deviation and a 15 % share of this emit's recall time.
