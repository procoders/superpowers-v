# Dogfood — running 3.0's triage against a real change in this repository

**Date:** 2026-09-01, on `main` at `v3.0.0`.
**Task chosen:** *"`compound-v-collect-results.py`'s result checker must validate the nested `tests` object, not just top-level fields."* Deliberately small, single-file, and real — it is the gap that let SEAM-2 (every Engine C `job_result` failing its own schema) slip past both the runtime check and CI during the 3.0 build.

**What was exercised:** the shipped `compound-v-localize.py` and `compound-v-preeval.py`, on this repository, with the taxonomy committed in 3.0. No fixtures.

## Result: the machinery works, and its calibration here makes it a two-outcome system

| Input | Decision | Bands |
|---|---|---|
| The request as a sentence | `FULL_PIPELINE` | `unknown`/`unknown`, **override #1 fired** |
| The precise path `scripts/compound-v-collect-results.py` | `FULL_PIPELINE` | `high`/`high` |
| `README.md`, `CHANGELOG.md`, `TROUBLESHOOTING.md`, `docs/superpowers/**.md` | `FASTPATH_ELIGIBLE` | `low`/`low` |
| `tests/test-lane-guard.sh`, `examples/manifest.example.yaml` | *no decision* | `needs_t3: true` — falls through to a model call |

## Four findings

**1. Natural language does not localize in this repository.** The request resolved to **296 paths** at `confidence: ambiguous`, which fires hard override #1 and fail-closes to FULL with both bands `unknown`. `compound-v-localize.py` unions a grep over every token of the request, and this repo is documentation-dense, so an ordinary sentence matches most of the tree. The implementer of `/v:triage` predicted exactly this; it reproduces on the first real attempt. **Triage via a plain request is therefore inert here** — a caller must supply the path.

**2. No code change in this repository can be anything but FULL.** The taxonomy bands `scripts/**` and `hooks/**` as `high`/`high`. That was a deliberate hardening during the build (an unbanded path is *not* fail-closed — it falls through to a model call), and it is strictly safer. It also means the three-tier ladder has no cheap rung for any executable file here.

**3. SCOPED appears unreachable from path rules alone.** The committed taxonomy declares only two band pairs — `low`/`low` for markdown and `high`/`high` for `.github/**`, `scripts/**`, `hooks/**`. The matrix reaches SCOPED only through a `medium` band, and **no path rule produces one.** Content rules do carry `medium` impact (`feature_flag`, `config_literal`), so SCOPED is reachable in principle through content; probing `TROUBLESHOOTING.md`, which contains a `timeout` literal, still returned `low`/`low` under `--score-only`, so **it was not observed to fire** in this probe. Stated as observed, not as proven impossible.

**4. `tests/**` and `examples/**` are unbanded and cost a model call.** Both return `needs_t3: true` — the engine asks a model to classify a path class that is obviously plumbing. `scripts/**` and `hooks/**` were banded during the build for exactly this reason; these two were missed.

## What this means

The feature is correct and the calibration is conservative to the point of being inert **for this repository**. In practice 3.0's triage here is what 2.x was: docs get the cheap path, everything else gets the full pipeline. That is a safe failure, not a dangerous one — but it means the tier ladder cannot be evaluated on this repo, and any precision figure measured here would describe the taxonomy, not the classifier.

**Not fixed in this pass, deliberately.** Widening bands is a safety decision, and this document exists to put the evidence in front of that decision rather than to make it quietly. The cheapest honest follow-ups, in order:

1. Band `tests/**` and `examples/**` — removes a model call on an obviously mechanical class. Low risk.
2. Decide whether any `medium` path band should exist here at all. If not, say so in the taxonomy, so a future reader does not assume SCOPED is reachable and is merely unused.
3. Localization needs a narrower default than "grep every token" before request-level triage is usable in a documentation-dense repository.
