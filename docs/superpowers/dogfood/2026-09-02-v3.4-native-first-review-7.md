### ISSUE 2 — QUALITY: "one probe" is the healthy machine's bill; the degraded machine pays three, and no record says so

[`hooks/lane-guard.sh:304`](../../../hooks/lane-guard.sh) publishes the ladder's cost as:

> *"One probe, ~44 ms, on every Write/Edit/Bash call in every session: 127 ms unresolved before,
> 171 ms after."*

and `:312` hedges it — *"Two things keep the bill to one probe on an ordinary machine: ORDER.
/usr/bin/python3 is tried before the one on PATH because **on macOS** it is the one that ships
PyYAML."* [`README.md:29`](../../../README.md) and [`AGENTS.md:21`](../../../AGENTS.md) carry the
figure with no hedge at all: *"the interpreter **viability probe** below, about **45 ms**"*.

Counted, by wrapping each candidate in a shim that appends to a counter file and driving the
unresolved path:

| Machine shape | interpreter starts | probes |
|---|---|---|
| first candidate **has** PyYAML (this macOS box) | 2 | **1** |
| first lacks PyYAML, second has it (a venv, a Debian box with `python3-yaml` only in a venv) | 4 | **3** |
| **no** candidate has PyYAML — *the fifth pass's incident machine* | 4 | **3** |

Measured in one round, same payload, 50 invocations each (floor 32.1 ms):

| Shape | unresolved path |
|---|---|
| first candidate has PyYAML | **181.7 ms** |
| no candidate has PyYAML | **250.3 ms** |

**+68.6 ms**, a 38 % increase over the figure `README.md` publishes as *the* ambient cost — and it
lands on precisely the population this entire three-pass arc exists for. The machine whose `python3`
has no PyYAML is the machine the fifth pass's guard failed open on; it is now the machine that pays
the most for the fix, and the number it pays appears in no file.

**One of those three probes is avoidable.** `hooks/lane-guard.sh:373-376`:

```bash
for _cv_cand in ${_cv_cands+"${_cv_cands[@]}"}; do
  if _cv_can_yaml "$_cv_cand"; then PY="$_cv_cand"; break; fi
  if [ -z "$_cv_runnable" ] && _cv_can_run "$_cv_cand"; then
    _cv_runnable="$_cv_cand"
  fi
```

The rung-2 fallback is probed **inside** the loop, on candidate 1, before the loop has finished asking
candidate 2 about yaml. `_cv_runnable` is only ever read after the loop completes without a rung-1
hit, so the `_cv_can_run` probe can be deferred to after the loop with no behavioural change. That
alone takes the "first lacks yaml, second has it" shape — the common Linux and virtualenv layout —
from 3 probes to 2, on every `Write`/`Edit`/`Bash` call in every session on those machines.

This is not the fabricated-metric shape: everything published was measured, and measured carefully.
It is the **incomplete-population** shape, in a release whose stated thesis is that a record saying
more than it does is a defect rather than debt. The header already knows the caveat exists — it wrote
*"on an ordinary machine"* — and then `README.md` and `AGENTS.md` dropped the qualifier and published
the happy number as the number.

→ State the worst case where the figure is published (a clause: *"one probe where the first candidate
has PyYAML, three where none does — ~250 ms"*), and defer `_cv_can_run` past the loop so the middle
shape costs two instead of three.
