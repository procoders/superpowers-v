**BLOCKER: completion and verification contracts remain underspecified.**

1. **BLOCKER — “Never block a session” conflicts with “refuse done.”** [Design §§2–4.5](/Users/oleg/Dev/superpowers-v/docs/superpowers/specs/2026-10-22-compound-v-v4-design.md:39) requires fail-open hooks and mandatory receipts, but does not define what happens after exhausted fixes, unavailable browser, or failed stage detection. The existing [Stop hook](/Users/oleg/Dev/superpowers-v/hooks/epic-goal-stop.sh:499) deliberately blocks only once; it is not a completion authority. **Fix:** define persisted run identity, stage transitions, counters, and terminal `verified / incomplete / failed` outcomes. Let sessions end without granting verified status. Make a deterministic finalizer authoritative; hooks consume its result. Stage detection and unavailable-tool policy are product decisions, not implementation details.

2. **HIGH — The reviewed snapshot can differ from the delivered tree.** The retained [sandbox helper](/Users/oleg/Dev/superpowers-v/scripts/compound-v-sandbox-checkout.sh:98) copies `git ls-files`: untracked implementation files disappear, while unstaged deletions cause copying failures. Merely stamping the source tree’s hash onto that review would certify different content. Also, receipts live inside the repository, so “any edit invalidates receipts” makes receipt creation invalidate earlier receipts unless exclusions are defined. **Fix:** specify one canonical content snapshot covering additions, modifications, deletions and file modes; verify checkout equivalence. Exclude only enumerated evidence artifacts from hashing. Trusted runners must produce receipts from actual command results, including provisioning and configuration identity.

3. **HIGH — The $5–7 target has no operational budget.** [A5 already cost $8.1](/Users/oleg/Dev/superpowers-v/docs/v4/salon-report.md:65). V4 adds its own brainstorm, recall agent, detailed planning, actual browser checks and potentially repeated review. Expected drivers are repeated Opus context, pre-flight fan-out, executable-review setup, fixes, and duplicated checks. Four searches and two rounds bound counts, not tokens or expenditure. **Fix:** allocate stage budgets and reserve verification capacity; cap context, output, runtime and concurrency; persist round counts across compaction. Define whether final re-verification is a third review invocation. Aggregate parent, subagent and external-worker costs; the [current band reads account quota](/Users/oleg/Dev/superpowers-v/hooks/run-band.tsx:110), not attributable run cost. Budget exhaustion must produce incomplete status.

4. **HIGH — Acceptance cannot distinguish improvement from judge noise.** [§7](/Users/oleg/Dev/superpowers-v/docs/superpowers/specs/2026-10-22-compound-v-v4-design.md:127) specifies repeated judging but not independent builds, aggregation, or what “beat A5” means across rubric and census. The report records approximately ten-point judge variation; C-light’s advantage lies inside it. A5 also received owner answers directly, whereas v4 must elicit them. **Fix:** freeze prompts, answer protocol, models, rubric, cost boundary and failure caps; independently rebuild each condition and judge blinded pairs. Define numerical pass rules for both metrics and brownfield non-regression. Retain the transition table’s separate brownfield holdout.

5. **HIGH — Light/full escalation has no defined effect.** [§5](/Users/oleg/Dev/superpowers-v/docs/superpowers/specs/2026-10-22-compound-v-v4-design.md:101) promises escalation to “full checks,” but §4.5 already makes every check mandatory. Depth selection also controls checks without a precedence rule. Path-only escalation would weaken v3: its [implementation](/Users/oleg/Dev/superpowers-v/scripts/compound-v-postdiff-reclassify.py:713) examines changed content and structure, catching sensitive behavior introduced in innocently named files. **Fix:** publish a tier-to-obligations matrix, immutable minimum checks, escalation predicates and uncertainty fallback. Recompute against the pinned baseline after fixes; invalidate affected approvals and receipts.

6. **HIGH — Parallel/backend safety is acknowledged but lacks a replacement execution contract.** The transition table requires parsing, pinned lanes and pre-integration checks, yet the design describes routing as instructions. Existing workers [exit zero even for failures](/Users/oleg/Dev/superpowers-v/scripts/compound-v-run-codex-worker.sh:900), and [test failure does not change `status: success`](/Users/oleg/Dev/superpowers-v/scripts/compound-v-run-codex-worker.sh:858). **Fix:** name the deterministic consumer that validates backend/model/effort, worker status, test results, attributed changes and immutable lanes before integration. Worktrees alone do not supply this. Make synthetic failure tests release requirements.

7. **MEDIUM — Two “authoritative” migration policies disagree.** [§7](/Users/oleg/Dev/superpowers-v/docs/superpowers/specs/2026-10-22-compound-v-v4-design.md:125) mandates a clean replacement; the [transition table](/Users/oleg/Dev/superpowers-v/docs/v4/transition.md:129) mandates coexistence before deletion and retains optional V-memory. **Fix:** resolve precedence explicitly and define a pinned, installable v3 channel. Checklist coverage, command survival and migration support are product decisions; only wording/layout belong to the builder.
