# Compound V v4 — переходная таблица (черновик для обсуждения)

Основание: эксперименты с салоном 2026-10-21/22 (`~/Dev/cv-salon-e2e-kit/REPORT.md`) и опись репозитория 3.9.1.

**Выводы, на которых стоят решения**

| # | Вывод | Данные |
|---|---|---|
| В1 | Глубину продукта дают **вопросы до кода**: ответы брейншторма почти удвоили продуманность | A → A3: продуманных функций 37 → 63 за 7 мин / $2 |
| В2 | **Исследование домена и чеклисты** дают продакшен-глубину (GDPR, НДС, WAL, бэкапы, сессии, CSRF, лимиты) | ~19 из 31 недостающих функций родились в пре-флайте эксперта; A5 с чеклистами — 72/79 продуманных против 52/65 у полного пайплайна |
| В3 | **Ревью с исполнением проверок + раунд исправлений** ловит то, что не видно чтением | пароль по умолчанию, `Origin: null` + `no-referrer`, неявка держит слот; Gemini без запуска пропустил то, что Codex воспроизвёл |
| В4 | **Свой движок оркестрации ничего не добавил** на этом масштабе: и на новом, и на существующем коде | полный Compound V: 62/72 против 94/99 (A5), 69/69 против 75/78 (C-light) при 2–10× цене |
| В5 | **Хук триажа сам включил процесс** на обычной фразе | прогон B: FULL → брейншторм без команд |
| В6 | **Не хватает проверки в настоящем браузере** — внутрипроцессные тесты не ловят браузерные баги | баг `Origin: null` у A4 и A5 |
| В7 | Инструкции модель может пропустить → критичные шаги подпирать хуками | урок 3.x «prose vs mechanism» |
| В8 | Параллельность и scope gate на большом существующем коде **не проверены** → оставляем как опцию, не выкидываем | решение Олега |

## Поправки после независимой критики Codex и Gemini (2026-10-22)

1. **Движок, resume, эпики — сначала DEPRECATE/опция, потом удаление.** Эксперименты не проверяли прерывание, зависимости
   между фичами, конфликтующих исполнителей и частичную интеграцию; незавершённым v3-прогонам нужен путь завершения.
2. **Скрытые зависимости развязать первыми:** `taxonomy.py` берёт `_mini_yaml`/`glob_match` из валидатора манифеста;
   `onboard.py` импортирует `churn.py`, `validate-manifest.py`, `memory.py`; хук триажа зовёт `dashboard.py`.
3. **Не хватало в таблице:** исполнитель маршрутизации (переопределения модели, проверка effort и доступности бэкенда),
   разбор `status` результата воркеров (они возвращают 0 и при блокировке), `emit-preflight.py`, `project-config.py`,
   метаданные плагина, миграция при переименовании (ссылки команд, настройки, папки памяти агентов), индексация архива
   (`docs/archive/` вне корпуса V-memory по умолчанию).
4. **Доказательства для удалений:** разница на существующем коде внутри шума; повторная оценка тех же сборок меряет
   шум судьи, а не повторяемость сборки.

**Обязательные дешёвые проверки перед удалением защиты:**
- синтетический параллельный прогон: запретная запись, поддельная/устаревшая квитанция, таймаут, прерывание и возобновление;
- фича на две связанные части этого репозитория: 1 агент + археология против 2 параллельных субагентов по таблице плана
  без манифеста — коллизии записи, регрессии, время (детерминированно, без судьи);
- засеянные провалы гейта завершения: сломанная браузерная форма, пропущенное ревью, правка после ревью — все три должны
  быть отказаны;
- одна контрольная фича на другом существующем приложении.

**Порядок миграции:** развязать импорты и извлечь уцелевшие контракты безопасности с их негативными тестами → построить
лёгкий путь рядом с v3 (исполняемое ревью, браузер, маршрутизация, квитанции) → проверить обновление настроенного
проекта и завершение прерванного v3-прогона → переключить умолчания → удалять код только вместе с его тестами одним
коммитом → переименование в самом конце.

**Спор:** Gemini — заменить триаж (~6 тыс. строк) классификатором на ~150 строк; Codex — сохранить переоценку тира по
итоговому diff. Решить в брейншторме.
