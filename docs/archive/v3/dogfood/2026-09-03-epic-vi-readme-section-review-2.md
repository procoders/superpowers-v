### This review file is not counted in the 34

Stated plainly, because it is the one thing a reader could mistake for a defect. `34` counts the review
corpus as of `00a3ed5`, which includes review-1 (`…-readme-section-review.md`) but cannot include **this**
file — it did not exist when the index was regenerated, and it lands after it. The true corpus becomes 35
review files, 4 APPROVED, the moment this file commits, and `README.md:138` will read `34 / 3` until the
next `bash scripts/compound-v-dogfood-index.sh` run.

That is not a violation of AC-2, which is scoped to the footer "on the merged tree" — where the equality
holds exactly. It is the fixed point this feature cannot reach on its own: the reviewer's output is an input
to the number it reviews, so any regeneration that counted this file would need a further review, which
would make it stale again. The section's "as of this writing" hedge is the correct and intended handling,
and no run can close the gap — only shrink it. Recorded as note N2.
