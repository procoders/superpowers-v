## Verdict

**ISSUES — 3.** Ranked. Nothing here is a scope violation, a fabricated metric, or a reward hack.
Nine of review-1's ten findings are closed with tests that would catch their return, and the tenth was
never a defect. What blocks is that the criterion those fixes served still reports a violation.

1. **`out-of-lane` fires on `>=` — a comparison operator read as a shell redirect** —
   `scripts/compound-v-transcript-watch.py`, `_REDIRECT` at `:139` / `bash_write_targets:284-320`.
   The token `>=` matches `^(\d*)(>>?)(.*)$` with target `=`, which joins to the agent's cwd, has a
   repo-relative form, and is therefore reported. Worse, the text scanned is the *whole command
   string* including heredoc bodies, so any Python or shell snippet piped through a heredoc trips it.
   Reproduced directly on the merged tree:

   ```
   >>> bash_write_targets("cat > /tmp/x.py <<PYEOF\nassert s.count(old) >= 1\nPYEOF")
   ['/tmp/x.py', '=']
   >>> bash_write_targets("true >= 1")
   ['=']
   ```

   The live source is `watch-script`'s own transcript, line 39: a `cat > …/patch1.py <<'PYEOF'`
   heredoc whose body contains `assert s.count(old) >= 1`. The heredoc's real target was correctly
   skipped (outside the repo — issue 1's fix working); the phantom `=` was not.
   **This is what fails feature AC 2**, and it fires on the one signal `v-dispatch.md:183` tells the
   orchestrator to `TaskStop` a workflow for.
   → Do not treat `>=` as a redirect (require a non-empty, non-`=` target, or exclude the operator
   explicitly), and do not scan heredoc bodies as command text. Add both as fixtures to section 8 —
   the suite has no `>=` and no heredoc anywhere.

2. **`error` still fires on a verbatim traceback inside a quoted document** — `error_evidence:727-738`.
   Start-of-line anchoring kills a *sentence* that mentions a traceback but not a *code block* that
   contains one, and this repository's review documents are full of pasted tracebacks. Three of the
   five signals in the required run are this, one per agent, all from `sed -n … review-1.md`:

   ```
   06:36:27 watch-script  a204c447 error Traceback (most recent call last):   ← sed of review-1.md
   06:44:17 spec-review-2 a57a6b1d error Traceback (most recent call last):   ← sed of review-1.md
   06:36:24 docs-wiring   a7abb565 error Traceback (most recent call last):   ← sed of review-1.md
   ```

   Review-1's own closing paragraph predicted exactly this shape. Not an AC 2 failure (`error` is not
   one of the two gated signals) and materially better than round 1, but the noise floor for `error`
   is still one false signal per agent that reads a review.
   → Consider gating `error` on `is_error` or a non-zero-exit marker rather than on text at all; a
   `Bash` result the harness did not mark as an error is weak ground for calling it one. If the text
   heuristic stays, exclude results whose tool_use is a read-only command (`sed`, `cat`, `grep`,
   `head`) — the same "which tool could have produced this" anchor `denial_evidence` already uses.

3. **`agents/spec-reviewer.md:175` contradicts the derived-default rule** — outside every lane of
   this run, recorded here as instructed. The row `| **FULL** | full_command — ran, exit 0 |` demands
   the full suite of every FULL job unconditionally; `skills/compound-v/execution-manifest.md:153`
   resolves a FULL job with a declared `impacted_map` and no `test_scope` to `impacted`, and only
   widens to `full_command` when a changed path matches **no** rule (`:459-461`). That sentence is
   what produced review-1's issue 9 as a finding against a job that was behaving correctly.
   → Amend line 175 to name the unmapped-path condition, the way line 180 already does for
   SCOPED/DIRECT.

### What is right, and should survive the next round

The three structural fixes are the good kind: `rel is None` is now *"not a lane question"* rather
than *"outside the lane"*, and it is stated in the module docstring so the next reader cannot
re-derive the old behaviour by accident; the pending-exchange table moved from a per-call local into
persisted state, with the reasoning written where the parameters are declared; and `denied` is
anchored twice over — by tool and by position — which took it from twelve false positives to zero on
the same corpus. The suite grew by fifteen cases drawn from real traffic rather than from the happy
path, including the two paths no test in this repository had ever executed (default discovery, and a
tick boundary). The roster answers AC 2's "every agent" clause literally: eight transcripts, eight
lines, silent agents included.

Two parse classes remain, both in the same place — the text heuristics that decide what a shell
command wrote and what a tool result means. Fix the tokenizer, decide whether `error` should be a
text heuristic at all, and this closes.
