## Verdict

**ISSUES** — the run is **not DONE**. No code change is required for issues 1–3; they are corrections
to `skills/compound-v/execution-manifest.md`, `skills/compound-v/failure-policy.md`,
`agents/parallel-dispatcher.md` and `CHANGELOG.md`, plus one decision on where `retries[]` lives.

1. **INTEGRATION_MISMATCH (high) — the docs describe a class-filtering retry that does not exist.**
   `skills/compound-v/execution-manifest.md` (§ `retry`, "The trigger is a `null` resolution"):
   "retries on **either** a thrown error matching the transient classes (`529`, `Overloaded`,
   `rate limit`, `429`, `ECONNRESET`/`ETIMEDOUT`/`network`, `overloaded_error`) **or** a `null`
   return. Every other thrown error, and the last transient failure once attempts are exhausted,
   propagate exactly as before this feature." The emitted `withRetry`
   (`scripts/compound-v-emit-workflow.py:2214-2219`) has **no classifier**: it catches *every* throw
   and retries it, and on exhaustion returns `{value: null}` — **nothing propagates**, by design (the
   spec's "each stage falls into exactly the null path it has today"). The same file's next paragraph,
   "A thrown error the classifier CAN read still gets its real class", describes a classifier that was
   never written — `apply_retry_meta` (`:1206-1229`) writes `other` unconditionally. Repeated in
   `skills/compound-v/failure-policy.md` ("retries on the **same** classes this doc defines") and
   `CHANGELOG.md` ("retries on the policy's transient classes"). Also wrong: the doc's signature
   `withRetry(label, fn)`; the code is `withRetry(stage, jobId, fn)`.
   → Rewrite the three passages to what was built: **any** null or throw is retried, unclassified,
   because the runtime hands the script no error text; on exhaustion the stage takes its existing null
   path and Record writes `other` with the reason that says why the class is unnameable.

2. **ACCEPTANCE_GAP (high) — `retries[]` and `escalated_from` are not on the job_result, and the docs
   say they are.** AC 2 requires "Record writes `retries[]`" and AC 3 "the receipt/**result** carry
   `escalated_from`". Task A put both in `state.json` and Record's ack instead
   (`scripts/compound-v-emit-workflow.py:4273-4292`), because `schemas/job_result.schema.json` is
   `additionalProperties: false` (line 7) and that file was outside its `write_allowed` — a
   **correct and well-documented** cut, verified by a selftest that asserts the result stays free of
   both keys. But `execution-manifest.md` ("Each retry is appended to that stage's result as
   `retries: [{stage, attempt, wait_ms}]`"; "the receipt and the job result carry `escalated_from`"),
   `agents/parallel-dispatcher.md` ("The receipt/result carry `escalated_from`") and `CHANGELOG.md`
   ("each retry is logged in that stage's result as `retries: [...]`") all assert the result carries
   them. Two of the run's five acceptance criteria are literally unmet, and the shipped docs claim
   otherwise.
   → Either extend `schemas/job_result.schema.json` with `retries` + `escalated_from` in a follow-up
   job that owns that file (the implementer's own suggestion) **or** amend AC 2/3 and correct all four
   doc passages to say `state.json`. Do not ship the current combination.

3. **INTEGRATION_MISMATCH (medium) — `escalated_from` is a model name, documented as a tier.**
   `agents/parallel-dispatcher.md`: "The receipt/result carry `escalated_from: deep`". The value is
   `opts.model` lowercased (`scripts/compound-v-emit-workflow.py:2296`, `:2303`), i.e. `opus` — a
   rung of `CLAUDE_ESCALATION`, never a tier. `execution-manifest.md` gets this right
   ("`--escalated-from <model>`"), so the two docs disagree with each other as well as with the code.
   → `escalated_from: opus`.

4. **CONSTRAINT_VIOLATION (medium) — archaeology §7 constraint 5 half-satisfied; the file now
   contradicts itself.** The constraint required the reviewer-invariant contradiction to be resolved
   "in the same edit … or the doc will contradict itself in two adjacent paragraphs". The prose at
   `skills/compound-v/execution-manifest.md:79-86` was corrected and now reads "**Invariant 4** demands
   `tier: deep` **or stronger** (`frontier`/Fable)" — but **invariant 4 itself**, at
   `skills/compound-v/execution-manifest.md:194`, was left untouched: "Any review/reviewer job MUST
   resolve to the strongest tier — `tier: deep` OR an explicit `model: opus`", with no mention of
   `frontier`/`fable`. The validator it claims to mirror accepts both
   (`scripts/compound-v-validate-manifest.py:2721`: `in ("opus", "fable")`, and `tier: deep|frontier`).
   The corrected paragraph now cites a rule that says the opposite of it.
   → Update invariant 4's own text to `tier: deep|frontier` OR `model: opus|fable`, matching
   `compound-v-validate-manifest.py:2714-2726`.

5. **QUALITY / honesty (low) — "measured" is the wrong word.**
   `skills/compound-v/execution-manifest.md`, § `retry`: "Each retry is appended … as
   `retries: [{stage, attempt, wait_ms}]` … — **measured**, never estimated". `wait_ms` is the
   configured wait read out of `CFG`; **nothing measures it**, as the same paragraph says two lines
   earlier (the script cannot read a clock). The number is not fabricated — it is real configuration —
   but calling it measured is precisely the wording the anti-ruflo charter exists to police.
   → "the wait that was requested", or drop the clause.

6. **QUALITY (low, observation) — permanent throws are retried too.** `withRetry` retries every thrown
   error, including an `auth` or `out_of_credits` shape that archaeology §7 constraint 7 warned about.
   Deliberate for the null path (no text to classify), but a *thrown* error does carry text. The cost
   is bounded — 2 wasted spawns and 6 s before the dispatcher's own breaker sees it — so this is not a
   blocker. It is, however, the second reason issue 1's class-filtering claim must not stand: the docs
   currently promise the protection the code does not have.

written; re-running the suites is enough to confirm nothing regressed.
