# Recon — Compound V 3.0: proportionate triage, test scoping, native Workflow orchestration (2026-09-01)

*This recon is evidence to widen the brainstorm's questions, not a conclusion to converge on. VERIFIED FACTS / CONSTRAINTS are provisionally binding (1B/1C revalidate); UNVERIFIED LEADS are questions until validated; SUGGESTED DIRECTIONS are read last (directions-late) and are some of several possibilities — generate alternatives that ignore them.*

Engine: native Claude Code `Workflow` (7 agents, 6 read-only recon lanes + 1 synthesis, 826,880 subagent tokens, 219 tool uses, 632s). Run: `wf_c9935684-cd4`. Scope: the maintainer's two stated 3.0 requirements — (1) fast triage into ~3 tiers with proportionate tests and no ceremony for tiny changes; (2) evaluate adopting Claude Code's native Workflow orchestration.

## QUESTIONS TO ASK

Framed as mistakes-to-avoid:

- **Don't build a third tier onto an engine nothing calls.** The sizing scripts are ~7,883 lines of working deterministic code with **zero callers**. Adding scoring fixes the half that already works. Ask instead: what *mechanically* forces the score to be consulted?
- **Don't accept the premise that the pipeline is over-applied to small work — the data says the opposite.** Every recorded run served a release of ≥788 changed lines; every release under 200 lines ran with no manifest and no run directory at all. The measured failure is an *unrecorded bypass*, not excess ceremony. A feature justified by the wrong premise optimizes a path with 0 historical uses.
- **Don't reverse the `impacted-tests` rejection without confronting why it was made.** v2.17 rejected it citing v2.14.1, where 25 of 29 selftests were found silently never running in CI. Running fewer tests is the failure mode that incident created. What is the floor that makes the reversal safe?
- **Don't assume the pain is in the dispatch pipeline.** The maintainer located it in downstream working projects *and in plain Claude Code sessions* — the second is a context where Compound V's dispatch never runs at all. A manifest field cannot reach it.
- **Don't trade the moat for throughput.** 73 of 73 recorded jobs ran on the one backend whose scope gate is prose. Any orchestration change either fixes that or inherits it.
- **Don't design an engine the autonomous paths cannot use.** Workflow cannot be launched from a subagent or from headless/`-p`/scheduled routes, which is exactly where `/v:epic` and the launchd shim live.

- The manifest schema has **zero** test-related fields at any level (`compound-v-validate-manifest.py:525-549`).
- `agents/spec-reviewer.md:138` hard-requires "the composite must build/compile and the test suite must pass", with no size carve-out.
- `impacted-tests` was explicitly **REJECTED** in v2.17: `docs/superpowers/specs/2026-07-25-v2.17-cochange-and-evidence-packing-design.md:308-310` — "REJECTED: directly contradicts the v2.14.1 lesson — we found 25 of 29 selftests silently never running in CI. Running *fewer* tests is the bug we just fixed."
- The one mechanism named "proportionate" is not proportionate to the diff: `compound-v-fastpath-run.py:308-343` runs `--test-cmd` verbatim and returns at `:343` **before** `changed_paths` is computed. `--test-cmd` has no default and no producer anywhere in the repo. No manifest carries `fast_path:`.
- Our own CI has no `paths:` filter (`.github/workflows/validate.yml:3-7`): a one-word markdown edit runs all 34 script selftests (93s measured) plus a dead-link scan over 191 files.

**Proportionality**

- All 10 recorded runs served releases of ≥788 changed lines (smallest `0478857` v2.8.0: 12 files, 778+/10−; largest `9bd724c` v2.9.0: 72 files, 15,231+).
- All 10 releases under 200 lines (v0.1.2 31 … v2.5.4 162) have **no** directory under `docs/superpowers/execution/`. Small work already bypasses the pipeline entirely, leaving no triage record.
- 73 of 73 recorded jobs ran `backend: claude` — the only backend with no mechanical scope gate. External workers invoke the gate inside their own scripts (`compound-v-run-codex-worker.sh:426`, cursor `:320`, antigravity `:371`); for claude it is prose the dispatcher must type (`agents/parallel-dispatcher.md:136,145`).

**Native Workflow**

- A subagent cannot launch a Workflow — verified live in-lane (`ToolSearch "select:Workflow"` → no match), and already recorded at `docs/superpowers/plans/2026-06-26-compound-v-orchestrator-v1-plan.md:52`. `compound-v:parallel-dispatcher` is a subagent, so the orchestration seam must move up into the top-level session.
- The workflow script itself has no filesystem or shell access, and there is no post-agent hook in the runtime.
- Resume is same-session-only, and on relaunch every agent that started after a failed one re-runs — including completed ones.
- Caps are agent-count only: 16 concurrent, 1,000 total, 4,096 items per call. **No token spending cap**; the "Large workflow" advisory warning is suppressed when ultracode is on.
- Launch requires explicit human opt-in plus a permission prompt, and the keyword is deliberately not honored from `-p` / SDK / scheduled / webhook routes.
- Engine C — "Workflow under our enforcement" — is an **already-shipped decision with zero implementation**: `skills/compound-v/workflows-accelerator.md:5` "kept in 1.0, opt-in, default OFF"; `:60` "Engine C only changes **how jobs fan out**, never the enforcement or recovery layer"; `:67` "`state.json` resume stays in Engine A". No script references it; `.claude/compound-v.json` does not exist here.

## UNVERIFIED LEADS

- The origin of the "~20,000 tests for a one-word change" figure was not reproduced by any lane. The maintainer subsequently located it in downstream working projects and in plain Claude Code sessions — **not** in this repo's CI. That answer is from the maintainer, not from a measurement, and the downstream instance has not been observed directly.
- Whether `compound-v-preeval.py` has ever executed in a downstream repo carrying a real taxonomy. Absence of records here cannot distinguish "never invoked" from "records written elsewhere".
- Whether the 9-cell → 2-outcome collapse was a deliberate scope decision or an unfinished ladder. No lane found a spec line either way.
- Why Engine C was never built despite being decided in the 1.0 PRD and fully specified. Capability-blocked, deprioritized, or superseded — unknown.
- Whether `/v:init` would in fact create `.claude/compound-v-impact-taxonomy.yaml` and `.claude/compound-v.json` here. `pre-eval-config.md` says Step 4a seeds them; no lane executed it.
- Community evidence is thin rather than absent: 9 searches / 13 fetches found **no** benchmark or first-hand report that native workflows produce worse code. Complaints are cost and steerability (HN 48311705: a 5-hour cap exhausted in 18 minutes by 62 Opus agents). **FABRICATION FLAG:** the widely-repeated aicosts.ai "$47,000 / 887K tokens per minute" figure has no attribution and must never be cited.
- Cognition's position has partly converged rather than opposing ours: "multi-agent systems work best today when writes stay single-threaded and the additional agents contribute intelligence rather than actions" — close to partition + scope gate.

## SUGGESTED DIRECTIONS

Read last, non-exhaustive, deliberately divergent — generate alternatives that ignore these.

1. **Make the score a precondition, not a suggestion.** Leave the 7,883 lines alone and give them a mechanical consumer: the manifest validator — already the one gate that reliably fails — refuses a manifest with no triage block. Nothing new gets scored; scoring simply becomes unavoidable on the dispatch path.
2. **Govern the bypass instead of speeding up the pipeline.** The data says small work escapes rather than being over-processed. A turn-level gate that notices "tracked code changed with no triage record" reaches plain sessions, which is where the maintainer says half the pain lives — and needs no tier ladder at all.
3. **Buy the reversal with a floor rather than an argument.** Scope tests by tier, but make integrity gates and linters unconditional and keep the full suite in CI before merge, so the v2.14.1 failure mode stays impossible even when the tier is wrong.
4. **Treat the scope gate as a pipeline stage, not as script logic.** The workflow script cannot touch the filesystem, but the agents it spawns can. `pipeline(jobs, implement, scopeGate)` makes the gate structurally unskippable — which would make it mechanical for the first time on the claude path that carries 100% of real traffic.
5. **Reject the framing entirely:** the problem may be that Compound V has one pipeline and needs none — a well-specified verification contract plus the scope gate might deliver the same guarantees with no orchestration layer at all.
