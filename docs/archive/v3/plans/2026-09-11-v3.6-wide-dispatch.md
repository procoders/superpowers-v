# v3.6.0 Wide Dispatch Implementation Plan

> **For agentic workers:** executed by Compound V on Engine C — ten jobs, one manifest
> (`docs/superpowers/execution/2026-09-11-v3.6-wide-dispatch/manifest.yaml`). Spec:
> `docs/superpowers/specs/2026-09-11-v3.6-wide-dispatch-design.md`. Pre-flight audits are named in
> the manifest's `audits` block; their §7 MUSTs bind. `scripts/compound-v-emit-workflow.py` is
> 8,000+ lines and has exhausted implementers' turn budgets before: grep for the named symbols, read
> only those ranges, never the whole file. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close issue #19 (six machinery defects), wire the native advisor and `/skill-doctor` into
the plugin, and do it as the first wide Engine C dispatch of this repository.

**Architecture:** Six independent lanes in wave 1 (the scope gate with the four worker scripts; the
validator, which owns the shipped example and the memory test with it; the lane guard; `/v:init`; the
second-opinion ladder; usage extraction), two lanes in wave 2 (the whole emitter, and the agent
definitions behind the validator), the documentation lane in wave 3, the Review Gate in wave 4. Every
code lane carries planted-failure selftests. The partition reviewer rejected the first shape of this
plan: the memory test is a fixture over the validator and the shipped example, so all three had to
become one lane or the wave would have blocked itself.

**Tech Stack:** Python 3.9 stdlib (`/usr/bin/python3 -B`), bash + shellcheck, Claude Code 2.1.263
native Workflow runtime, git.

## Global Constraints

- Python 3.9 syntax, stdlib only; every script run as `/usr/bin/python3 -B`; bash passes `shellcheck`.
- Never Haiku; no agent frontmatter names Fable; Fable enters only through `advisorModel`.
- Never relax the scope gate; no new entry in `RUN_DIR_EXEMPT_BY_NAME`; provisioning is subtracted
  only through the existing `--preexisting` snapshot path.
- No fabricated metrics; every behavioural change ships a selftest row that fails when the change is
  reverted (state the planted failure in the row's name or comment).
- Docs: plain words, one idea per paragraph, no line over 200 characters outside code/tables, every
  claim true of the code in HEAD; historical or defensive material is linked (CHANGELOG,
  TROUBLESHOOTING), never repeated.
- Lane discipline: touch only your `write_allowed`; `register-lane` first, with a literal `--cwd`.
- Field and flag names are fixed by the Interfaces below; do not rename them.
- Not in any job: CHANGELOG entry, version bump, release, generated architecture docs.
