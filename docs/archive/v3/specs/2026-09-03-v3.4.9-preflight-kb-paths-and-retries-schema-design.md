# v3.4.9 — two small honesty fixes: the pre-flight reports every file it wrote; the conformance checker validates `retries[]` (findings 100, 126) — design

**Date:** 2026-09-03 · **Scope:** two mechanical fixes with no policy content, run as one small cycle.

## Part 1 — the pre-flight result names the knowledge-base files it appended (finding 100)

**Probe.** 1C appends to `docs/superpowers/library-audit/_knowledge-base/<topic>.md` (its Step 7) and 1A may create
`docs/superpowers/archaeology/_knowledge-base/<topic>.md`; the emitted pre-flight workflow's result reports only `wrote: <audit path>`.
An orchestrator that commits what the result names leaves the KB append uncommitted; with a direct-mode job registered at the checkout
root, the scope gate charges that uncommitted file to the job (it had to be stashed mid-run on 2026-09-03).

**Decision.** `scripts/compound-v-emit-preflight.py`'s emitted workflow asks each auditor to return `kb_files: [...]` (the KB paths it
created or appended) in its structured result, and the post-processing lists them in the top-level result as `kb_files` next to
`wrote`; `commands/v-dispatch.md`'s "commit the audits" step names `docs/superpowers/{archaeology,library-audit}/_knowledge-base/**`
explicitly. No KB file is ever written outside those two directories (the auditors' prompts already say so).

## Part 2 — `retries[]` items are validated like `usage` (finding 126 LOW)

**Probe.** `scripts/compound-v-collect-results.py` deep-validates the `usage` sub-object (unknown keys, wrong types) but checks
`retries` items only as "an object"; a retry entry with an unknown key or a missing `stage`/`attempt` passes conformance.
Unreachable from the shipped producer today, an asymmetry with a documented precedent.

**Decision.** `collect-results` validates each `retries[]` item against the schema's item shape (required `stage`, `attempt`;
`wait_ms` int ≥ 0; `escalated_from`/`model` string-or-null; no other keys) and reports a violation naming the index and key,
exactly as it does for `usage`. Selftest: a good item passes; an unknown key, a missing `stage`, a string `attempt` fail.

## Decisions forced by pre-flight 1A/1C (2026-09-03)

- `kb_files` goes into BOTH the wrapper prompt text (asked for by name — an optional schema field is never populated on its own) and `RESULT_SCHEMA['properties']` (additionalProperties: false), and is defaulted `|| []` in the JS template's three bypass branches (skipped / null / catch); the selftest covers the prompt text, the schema and the three bypass literals.
- The commit step lives in `commands/v-orchestrate.md` (Step 2 extracts the three audit paths; Step 8 already commits them and runs before any job's baseline is pinned) — `commands/v-dispatch.md` has no such step and is not touched. The path list names all THREE KB directories: `docs/superpowers/archaeology/_knowledge-base/**`, `docs/superpowers/expert/_knowledge-base/**` (1B's), `docs/superpowers/library-audit/_knowledge-base/**`.
- 1A has no documented KB-write step today, so its `kb_files` is empty in practice — stated, not implied as parity.
- Root cause recorded: the scope gate's pre-existing snapshot protects only untracked files; a modification to an already-tracked KB file (the common case) is charged to a direct-mode job — which is why naming the files in the result matters.
- The `retries[]` validator reuses `_usage_conformance_errors`' type-map pattern but adds the required-field check that pattern lacks (`stage`, `attempt`), iterates the list with an index in every violation, and hard-blocks exactly as `usage` violations do. `schemas/job_result.schema.json` already carries the item shape and is untouched. `tests/test-engine-c-contract.sh` does not exercise this path; `--selftest` is the coverage.
