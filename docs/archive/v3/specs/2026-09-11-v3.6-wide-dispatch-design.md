# v3.6.0 — the first wide dispatch: #19 closed, native advisor, native skill-doctor

**Date:** 2026-09-11 · **Author:** the orchestrator, from Oleg's five-point brief · **Status:** approved brief, spec for the plan

## Why one release

Oleg's brief on 2026-09-11 named five items and one rule: *only when all five are done may 3.6 ship*.

1. The text that said Engine C "has never run a real multi-job dispatch" is corrected **immediately**
   (done: `51d882d`, `42ad523`), and then the claim is retired by a **real wide dispatch** — this
   release is built as one. The widest recorded run before today held five jobs; this manifest holds
   ten, six of them in the first wave.
2. `/skill-doctor` (native, Claude Code ≥ 2.1.252) is used from `/v:init`.
3. The **advisor tool** (native, server-side) becomes the way a stronger model — Fable 5.1 where the
   account has it, Opus otherwise — judges at decision points inside every job; and a project that
   has no Codex gets a second look at its spec/diff through the advisor instead of getting nothing.
4. Issue #19 (six machinery defects, @khymerao) is fixed.
5. Issue #12 is fixed — done by merging #13 and #14 (`157acaf`, `973afdc`); #12 is closed.

## What was verified before writing this

- **Advisor, live-probed 2026-09-11 on Claude Code 2.1.263.** `claude -p --model sonnet --advisor opus`
  produced a `server_tool_use` block named `advisor` and an `advisor_tool_result`
  (`advisor_redacted_result`) in the main transcript. A **Sonnet subagent** spawned by that session
  through the Agent tool produced the same two blocks in *its* transcript
  (`…/subagents/agent-*.jsonl`) — subagents inherit the advisor, as the docs say. A Fable 5.1 main
  model refuses an Opus advisor ("the advisor must be at least as capable as the main model"): the
  pairing rule is real. Per-message `usage.server_tool_use` carries only web counters; advisor calls
  are counted from the content blocks.
- **Advisor docs** (code.claude.com/docs/en/advisor, settings-reference): `advisorModel` is a setting
  of scope "Any file" (project `.claude/settings.json` is legal); `/advisor <fable|opus|sonnet|off>`;
  `--advisor` flag; Anthropic API only; off in a session with feature-flag fetching disabled
  (`DISABLE_TELEMETRY`); `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` disables it entirely; each call re-reads
  the full transcript uncached; Fable as advisor bills to usage credits on some plans and needs the
  one-time consent given through `/model fable`.
- **`/skill-doctor`**: works headless — `claude -p '/skill-doctor' --output-format text` printed a
  table with columns `skill · source · context · 7d tokens · uses · last used` on this machine; the
  twelve `superpowers-v:*` skills cost `< 20` tokens of context each. Limits: the data is this
  machine's session history, not a property of the repo; a phase that fires through a hook or a
  description trigger is not a skill invocation, so `0×` beside `v-dispatch` does not mean unused;
  not available over Remote Control or with feature-flag fetching disabled.
- **#19 F**: khymerao's directory listing shows `.claude/agent-memory/superpowers-v-<agent>/` for all
  five agents. The official sub-agents page names only `<name-of-agent>`; a plugin agent's full name
  is `superpowers-v:<agent>`, and the directory is that name with `:` → `-`. This is field evidence
  from one downstream project, stated as such in the docs.
- **#19 D**, read from the code: the Gate stage's in-memory verdict is the *structured output of a
  clamped transport agent* that was told to run `gate-receipt` and return its JSON verbatim; the
  receipt file is what `gate-receipt` itself wrote under the run directory. The agent cannot write
  that directory (`disallowedTools` + a Bash clamp to the one command). So when the two disagree,
  the echo — not the file — is the side with no provenance: an agent whose Bash call timed out before
  the script finished, or that summarised instead of returning verbatim, produces exactly this shape
  without anyone rewriting the receipt.

## Global constraints

- Python 3.9 syntax, stdlib only, always run as `/usr/bin/python3 -B`. Bash scripts pass `shellcheck`.
- **Never Haiku.** No agent frontmatter names Fable; Fable enters only as the advisor setting.
- **Never relax the scope gate.** No new entry in `RUN_DIR_EXEMPT_BY_NAME`; an ignored write is still a
  write. Provisioning is subtracted only through the existing `--preexisting` snapshot mechanism.
- **No fabricated metrics.** Every behavioural claim in this release has a selftest row that fails
  when the change is reverted (planted failure). Usage numbers are measured from transcripts or
  events, or they are `null`.
- **Docs are clear and simple**: plain words, one idea per paragraph, no line over 200 characters
  outside code blocks and tables, every claim true of the code in HEAD.
- **Lane discipline**: every job touches only its `write_allowed`; `register-lane` is its first
  command with a literal `--cwd`.
- **Not in any job:** the CHANGELOG entry, the version bump, the release — the orchestrator does those
  after the review gate.

## F1 — Worktree provisioning (#19 A + B)

**Problem.** A fresh worktree has no `node_modules`; the floor cannot run there; installing is an
out-of-lane write; no two jobs may declare the same path; the exemption list is closed by design.

**Decision: provisioning is a manifest-level step that runs before the job's before-image is taken.**
That is khymerao's first option — it adds no exemption class, touches neither the partition nor the
validator's overlap rule, and makes the worktree-mode comment ("a fresh tree has no pre-existing
untracked") true again by construction.

- **Manifest** gains two optional top-level keys:
  - `provision_command: string` — non-empty, no newline; executed through `/bin/bash -c`, the same
    interpreter every test command uses since #13. It is manifest content, trusted exactly as
    `test_contract` is, and never comes from a job prompt.
  - `provision_timeout_s: int` in `1..1800`, default `600`.
- **Engine C, claude job with a real worktree** (`agent_isolation: worktree`): `register-lane
  --isolation worktree` runs `provision_command` in the registered worktree **before** taking the
  snapshot, then takes the same digest-bound snapshot direct mode takes today
  (`_preexisting_snapshot` → `write_preexisting` → `preexisting/<id>.txt`). `gate-receipt` in
  worktree mode reads the verified subset when the file exists, exactly as direct mode does. A
  provisioning failure (non-zero exit or timeout) is recorded in the register ack as
  `provision_error` and the job proceeds to a **stricter** gate (no snapshot), never a looser one.
- **Direct-mode job**: provisioning does not run — the main checkout is the user's, already provisioned.
- **External workers** (`compound-v-run-{codex,cursor,antigravity,opencode}-worker.sh`): new optional
  `--provision-command <string>` and `--provision-timeout-sec <int>`. After `git worktree add`, run
  the command through `/bin/bash -c` under `compound-v-run-with-timeout.py`; on success snapshot
  `git ls-files --others --exclude-standard` ∪ `git ls-files --others --ignored --exclude-standard`
  into `$ART/preexisting.txt` and pass `--preexisting "$ART/preexisting.txt"` to the scope gate; on
  failure emit a `status: error` job_result whose `summary` names the command and exit code, and do
  not launch the worker. The emitter passes both flags into the external launch argv when the
  manifest sets them.
- **Scope gate** (`compound-v-scope-check.py`): `--preexisting` is already mode-agnostic (the archaeology
  audit confirms it); only the docstring and `--help` need to say so. Selftest: a worktree with an ignored
  directory listed in the snapshot → not a violation; the same directory absent from the snapshot → violation.
- **The ceiling the domain audit found.** `register-lane` runs as an ordinary agent `Bash` call, and the
  emitted prompt sets no `timeout:`, so the harness default of 120 s would kill an `npm ci` long before
  `provision_timeout_s` and resurface the very `node_modules` violations this feature removes. The emitted
  `register-lane` prompt therefore carries an explicit Bash timeout derived from `provision_timeout_s`, the
  way the Gate prompt already does, and a selftest asserts the emitted script contains it.
- **Rule for authors, in the docs:** the command must be idempotent and must not modify tracked files
  (`npm ci`, not `npm install`; `pip install -r`, not `pip freeze >`). A tracked file it changes is
  attributed to the job.
- **Validator:** type and range checks only. No heuristic that guesses whether a floor needs
  provisioning.

## F2 — The wave finalizer stages run-directory artefacts with `-f` (#19 C)

Every staging call that can touch a run-directory artefact force-adds it. The archaeology audit corrects
this section's first draft: the production failure is **not** in `_stage_paths` but in a separate,
unguarded `git add -A` inside the wave finalizer, which never calls `_stage_paths` at all — so a fix
confined to `_stage_paths` would pass a naive selftest while leaving the reported bug alive. Both sites
take the rule. Selftest: a repository whose `.gitignore` lists `docs/` finalizes a wave whose review job
wrote `docs/superpowers/execution/<run>/results/<id>.json`, exercised through the finalizer's own path.

## F3 — Record states a verdict disagreement instead of asserting its cause (#19 D)

- **The receipt file is the verdict** when it (i) parses, (ii) carries this `job_id`, and (iii) has
  `verdict ∈ {pass, blocked, error}`. The workflow's `--expect-verdict` is a transport echo; when it
  disagrees, Record proceeds with the receipt's verdict and records the disagreement.
  **A condition the code cannot evaluate must not be written as though it were enforced.** The first
  draft of this section also required the run's `manifest_digest`; the archaeology audit found that
  `GATE_SCHEMA` carries no such property and nothing sets one. The implementer either makes
  `gate-receipt` write it and Record check it, or drops the condition and says in a comment why.
- **The disagreement is data, not prose**: `verdict_disagreement: {"field": "verdict",
  "receipt": <value>, "workflow": <value>, "receipt_path": <path>}` in the Record ack and in the
  job's `state.json` entry; the result's `summary` carries both values. The message is:
  `gate verdict disagreement: receipt <path> says 'pass', the workflow held 'blocked'; this
  comparison establishes no cause` — and nothing about rewriting.
- **The `diff_digest` comparison stays** (the forgery axis is different: the digest binds the sealed
  patch). A digest mismatch is still `error`, with the same neutral wording and the same fields
  (`field: "diff_digest"`), and it is checked **before** the verdict comparison so a receipt that
  mismatches both surfaces the forgery signal rather than the benign one. The domain audit found the
  open half of this: the workflow appends `--expect-diff-digest` only when it holds a digest, so a
  degraded transport sends none — and a missing digest must not read as agreement.
- A receipt failing any of (i)–(iv) is `error` as today.
- Selftest rows: receipt `pass` + expect `blocked` → status `success`, `verdict_disagreement`
  present; receipt `blocked` + expect `pass` → `blocked` + disagreement; receipt with another
  `job_id` → `error`; digest mismatch → `error` with the fields; agreement → no field at all.

## F4 — `lane-guard-unresolved.jsonl` records the acting run and names the bootstrap (#19 E)

- A `Bash` call whose command contains `compound-v-emit-workflow.py register-lane` is the registration
  itself. It is logged `ALLOW (register-lane bootstrap)` and writes **no** unresolved record.
- Any other unresolved isolated-agent call is recorded under **one** run: the run named by a
  `--run-dir` in the command when there is one, else the **newest** live lane map. The record carries
  `candidate_runs: [<every live lane map at that moment>]` so an auditor can see the ambiguity.
- The `why` text says what is known: `isolated agent <cwd> did not resolve to a job in this run's
  lane map at the time of this <tool> call; the write was allowed and not lane-checked`.
- `tests/test-lane-guard.sh` rows: bootstrap call → no record and the `bootstrap` log line; an
  unresolved Write with two live runs → exactly one record, in the newest run, with `candidate_runs`
  of length two; the old three-cause wording is gone.

## F5 — The agent-memory lane is the namespaced path (#19 F)

- Every document that says `.claude/agent-memory/spec-reviewer/**` says
  `.claude/agent-memory/superpowers-v-spec-reviewer/**`, with one sentence: the harness names the
  directory after the agent's full name; installed as a plugin that is `superpowers-v-<agent>`
  (field-observed on a downstream project, issue #19); a copy installed as a project agent would use
  the bare name.
- Validator advisory `MEMORY_LANE_UNNAMESPACED`: a lane glob that resolves to
  `.claude/agent-memory/<bare name of one of the five memory agents>/…` produces an advisory naming
  the namespaced form. `MEMORY_ONLY_LANE` recognises both forms. `partition-reviewer` prints the new
  WARN. `examples/manifest.example.yaml` uses the namespaced lane.
- `tests/test-agent-memory.sh` switches to the namespaced path and adds the advisory row.
- This release's own review job declares the namespaced lane — the dogfood of the fix.

## F6 — `/v:init` runs the native `/skill-doctor` (item 2)

- New Step **1f — Skill hygiene**. Gated on `claude --version` ≥ 2.1.261 (the changelog says 2.1.261, skills.md 2.1.252; the stricter floor is cited). Runs
  `claude -p '/skill-doctor' --output-format text < /dev/null` under
  `scripts/compound-v-run-with-timeout.py --timeout 180` (read-only, no permission flags, stdin closed).
  Parses the rows whose first column begins with `superpowers-v:`, prints them (context cost, 7-day
  tokens, uses, last used) and the sum of the `context` column over every loaded skill.
- **Never disables anything, never writes.** It states the limits in the report: per-machine history,
  not a repo property; hook- and description-fired phases are not skill invocations, so `0×` beside
  `v-dispatch` is not "unused"; unavailable over Remote Control and with feature-flag fetching off.
- Step 5's report gains one line for it. `native-mechanisms.md` gains a row: skill usage accounting is
  native (`/skill-doctor`); Compound V keeps no tracker of its own.

## F7 — The advisor is the model policy's judge inside every job (item 3)

- **Policy** (`routing-policy.md`, AGENTS.md "Model policy", CLAUDE.md): *advisor = Fable 5.1 where the
  account has Fable access, else Opus*, set project-wide as `advisorModel` in `.claude/settings.json`.
  Every subagent inherits it and pairs by its own model, so a Sonnet-executed junior slice and an
  Opus reviewer both get the same senior second look at decision points. Fable-as-advisor is the
  sanctioned way Fable reaches routine work; frontmatter still never names Fable. The junior-task
  carve-out for Sonnet is unchanged in this release — widening it is a later, measured decision.
- **`/v:init` Step 4e** offers `advisorModel` in the project's `.claude/settings.json` in the Step 4d
  style (merge, never overwrite, never without a yes): `fable` recommended when `claude --version`
  ≥ 2.1.257 and the user confirms Fable access, else `opus`; discloses the pairing rule (an advisor
  must be at least as capable as the main model; a Fable main accepts only Fable 5.1), the cost (each
  call re-reads the whole transcript, uncached), that `DISABLE_TELEMETRY` turns it off, and
  `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`.
- **This repository** sets `"advisorModel": "fable"` in its own `.claude/settings.json` — the run
  that builds this release is the first measured one.
- **Agent nudges** (`agents/implementer.md`, `agents/spec-reviewer.md`): when an advisor is attached,
  consult it before committing to an approach where more than one design is plausible, when the same
  error recurs, and before reporting done or a verdict. Advice is evidence: re-verify against the
  tree; advice that contradicts the lane or the scope gate is refused and reported.
- **Second opinion without Codex** (the downstream complaint): the cross-model ladder becomes
  1. Codex CLI present → as today (a different model family).
  2. No Codex, advisor configured → an **advisor-assisted second look**: one read-only Opus subagent
     runs the cross-model prompt over the same bytes and is told to consult the advisor before its
     verdict; it emits the same `plan-review.schema.json` findings; the receipt says
     `reviewer_backend: "claude-advisor"` **and `cross_model: false`** — the honesty is a field a machine
     can read, not only a sentence a human may skip — and every rendering says, in one line, *same model
     family — no decorrelation*. It is an honest downgrade, never presented as cross-model, and the prose
     tells a project that can install Codex to install it.
  3. Neither → skip with the notice, as today.
  `/v:review-plan`, `cross-model-review.md`, `/v:dispatch` step 9 and `phase-3` carry the ladder;
  `schemas/cross-model-receipt.schema.json` accepts `claude-advisor`; the validator accepts it and
  prints a WARN naming the missing decorrelation. For SCOPED+ the mandatory second look is satisfied
  by rung 2 with that WARN; rung 3 still refuses.
- **Measured usage**: `compound-v-usage-extract.py` counts, per job and deduplicated by message id as
  today, the `server_tool_use` blocks named `advisor` → `usage.advisor_calls` (integer, or `null`
  when the job was not measured). `job_result.schema.json` gains the key; the aggregator and
  `/v:status` show `adv=N` when `N > 0`. `tests/test-usage-workflow.sh` plants a transcript with two
  advisor calls and asserts `2`.

## Acceptance criteria (feature level)

- AC-1 Every `tests/*.sh` and every `scripts/*.py --selftest` is green; `lint-frontmatter`, `rules-lint`,
  `shellcheck hooks/*.sh scripts/compound-v-*.sh` and the CI dead-link rule pass.
- AC-2 A manifest with `provision_command: "mkdir -p node_modules/x && touch node_modules/x/a"` and a
  worktree job whose floor is `test -f node_modules/x/a` passes the floor and the gate reports no
  violation; the same job with `provision_command` absent is BLOCKED on `node_modules/**`.
- AC-3 A repository that gitignores `docs/` finalizes a wave whose results land under
  `docs/superpowers/execution/…`.
- AC-4 Record, given a `pass` receipt and `--expect-verdict blocked`, records `success` with
  `verdict_disagreement` and a summary that names both values and no cause.
- AC-5 `hooks/lane-guard.sh` writes no record for the `register-lane` bootstrap call and exactly one
  record, in the newest live run, for an unresolved write under two live runs.
- AC-6 No committed document that tells an author what to declare names the bare
  `.claude/agent-memory/spec-reviewer/**` any more; the validator prints `MEMORY_LANE_UNNAMESPACED` for
  the bare form. Three residuals are out of scope and named so the reviewer does not chase them:
  `agents/partition-reviewer.md` keeps it as a deliberate counter-example, `scripts/lint-frontmatter.py`
  keeps it as a selftest fixture path, and `docs/superpowers/architecture/architecture.md` is a
  generated doc refreshed by `/v:onboard --refresh` after the release.
- AC-7 `commands/v-init.md` has Step 1f (skill-doctor) and Step 4e (advisor) in the offer-never-write
  style; `.claude/settings.json` in this repo carries `advisorModel: fable`.
- AC-8 `usage.advisor_calls` is measured from transcripts and shown by `/v:status`; the run that built
  this release reports it for at least one job, or reports `null` honestly.
- AC-9 The review job declared the namespaced memory lane, passed the gate, and reported which plugin
  version supplied its agent definition. **Native memory is not claimed to have been exercised**: the
  installed plugin cache on this machine lags `HEAD`, so the running `spec-reviewer` definition may
  predate `memory: project`, and a hand-written file in that lane would not be evidence of the native
  mechanism. The same limit applies to the advisor paragraphs this release adds to `agents/*.md`: they
  reach a later run, not this one.
