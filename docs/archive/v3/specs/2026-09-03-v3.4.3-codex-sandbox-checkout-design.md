# v3.4.3 — Multi-model on Engine C: a Codex job builds the sandbox-checkout helper — design

Stage 4 of the verification program: one job runs on the `codex` backend through Engine C — the headless
worker script (`compound-v-run-codex-worker.sh`), its own worktree, the git-derived scope gate, the
authority, the finalizer — and merges exactly its lane. The deliverable is real: reviewers of stage 2 and 3
had to hand-build a byte-identical sandbox (`git ls-files` copy, fresh `git init`, empty pre-eval dir) to
drive the triage hook on a checkout with an active run; finding 64 called it "worth a helper someday".

## Decisions
1. `scripts/compound-v-sandbox-checkout.sh <dest> [--keep-execution] [--empty-pre-eval] [--taxonomy-from <path>]`:
   copies every `git ls-files` path of the current repository into `<dest>` (byte-identical, file modes
   kept), runs `git init` + one commit there, drops `docs/superpowers/execution/**` unless `--keep-execution`,
   empties `docs/superpowers/pre-eval/` when asked, and prints the sandbox path plus a one-line summary
   (files copied, commit). Bash 3.2 + git only; no python. Exit 0 on success; non-zero with a message on any
   fault (not a git repo, dest exists and is non-empty).
2. `tests/test-sandbox-checkout.sh`: builds a tiny repo, runs the helper, asserts byte identity for tracked
   files, absence of untracked ones, the execution dir dropped/kept per flag, the pre-eval dir emptied per
   flag, and the refusal on a non-empty dest.
3. `docs/superpowers/dogfood/README.md` (or the reviewer agent) gains one sentence: "to probe the hook on a
   checkout with a live run, use the helper".
4. Routing: the implement job is `backend: codex`, `tier: standard` (→ `gpt-5.6-terra`, effort medium),
   `type: large_isolated`, `isolation: worktree` (codex ⇒ worktree is an invariant), `timeout_sec: 900`;
   the review job stays Claude/Opus/direct. `.claude/compound-v.json` is NOT required for a manifest that
   names the backend explicitly (the resolver's built-in codex map applies) — to be verified live (finding).
5. Verification points (the multi-model contract, all git-derived): the launch argv file exists in the run dir
   before launch; `job_result.session_id` is a UUID from the `--json` stream; `results/<job>.json.worktree`
   is under `$TMPDIR/compound-v/<run-id>/<job-id>` — OUTSIDE the repository, the worker's own tree (`.cv-worktrees/` is only a selftest fixture path; pre-flight amendment 1); the gate measured that tree;
   `files_changed` == the lane; the finalizer merged exactly those paths; the events log exists.

## Out of scope
A Codex reviewer (cross-model review stays `/v:review-plan`); antigravity/cursor/opencode/devin (same
contract, not exercised here); `/v:init`.

## Pre-flight amendments (2026-09-03, after 1A archaeology and 1C library audit)

1. **The codex worker's worktree is `$TMPDIR/compound-v/<run-id>/<job-id>`**, outside the repository
   (`compound-v-run-codex-worker.sh` WT_PARENT/WT, `job_result.schema.json`, `adapter-codex.md`); the
   `.cv-worktrees/` path in the draft was the emitter's selftest fixture. Decision 5 and the manifest say so.
2. **Only the UserPromptSubmit hook is reachable in a sandbox.** The helper can never produce a sandbox with
   `.claude/compound-v.json` (never committed), so `hooks/epic-goal-stop.sh`'s rules cannot fire there; the
   reviewer note names `hooks/triage-prompt-nudge.sh` specifically.
3. **`--keep-execution` keeps what git tracks and nothing else:** `lane-map.json` and `logs/*.jsonl` are
   gitignored, so the "resolved lane" signal can never be reproduced in a sandbox; the helper's `--help` says so.
4. **Symlinks:** no tracked symlink exists today; the helper copies a symlink as a symlink (never follows it)
   and the test includes one, so a future symlink cannot leak a target from outside the sandbox.
5. **`.claude/compound-v.json` is not required** for an explicitly named backend — confirmed in
   `compound-v-resolve-model.py` (built-in DEFAULT_MODELS; codex/standard → gpt-5.6-terra).
6. **CI shellchecks `hooks/*.sh` only.** This run's `impacted_map` row shellchecks the new script at merge time;
   extending CI to `scripts/*.sh` and `tests/*.sh` is a follow-up, recorded here, not done in this run.
7. **Version drift, stated:** the pinned codex-cli 0.144.1 is behind npm's 0.153.x; the review job quotes
   `codex --version` and the events log's first line so the run's own record says what actually ran.

## Testing and evidence

`tests/test-sandbox-checkout.sh` green; every other suite and selftest green. The multi-model contract is
verified from the run directory by the review job: `jobs/<job>.launch-argv` (or the emitted launch command)
exists before launch; `results/<job>.json` carries a UUID `session_id`, a `worktree` under `.cv-worktrees/`,
`files_changed == write_allowed`; `receipts/<job>.gate.json` measured that worktree; `logs/<job>.events.jsonl`
exists and its first line is `thread.started`; the wave commit carries exactly the lane.
